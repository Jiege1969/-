# 模型路由器设计

创建日期：2026-04-26

## 一、目标

模型路由器负责把任务分配给合适模型。

它的目标不是永远调用最大模型，而是在稳定运行前提下获得足够好的结果。

## 二、输入

模型路由器接收以下信息：

1. 用户消息。
2. 任务类型。
3. 是否需要深度推理。
4. 是否需要代码能力。
5. 是否需要图片理解。
6. 是否为股票、文档、视频等业务任务。
7. 当前 GPU 显存状态。
8. 当前任务队列长度。

## 三、输出

模型路由器输出：

1. 模型名。
2. 推理参数。
3. 是否进入队列。
4. 降级策略。
5. 任务记录。

## 四、第一阶段规则

| 任务 | 模型 |
|---|---|
| 系统状态解释 | `qwen2.5:7b` |
| 普通聊天 | `qwen3:14b` |
| 知识库问答 | `qwen3:14b` |
| 深度分析 | `qwen3:30b` |
| 复杂推理 | `deepseek-r1:32b` |
| 代码维护 | `qwen3-coder:30b` |
| 股票解释 | `qwen3:14b` 或金融模型 |
| 图片理解 | `gemma3:27b` |

## 五、显存保护

1. 30B 级模型同时只允许一个任务运行。
2. 显存空闲不足时，大任务排队。
3. 企业微信即时任务优先返回“已收到，正在处理”。
4. 批量任务默认后台执行。

## 六、后续进化

模型评测模块定期生成建议：

- 哪类任务适合哪个模型。
- 哪个模型速度慢但质量高。
- 哪个模型适合降级兜底。

生产模型策略变更必须人工确认。
