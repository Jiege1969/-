# 工程样本：企业微信机器人机械回复感根治 - 2026-05-10

## 1. 问题定义
*   **问题等级**：P0
*   **涉及子系统**：00总管、01智能系统、02企业微信接入设置、企业微信全部5个机器人
*   **表面症状**：用户对企业微信任何机器人发送模糊消息（如“你好”“哈哈”），统一回复“我还没判断出您具体想处理哪件事”，体验机械生硬；发送“有未处理的报警吗”无法查询系统状态
*   **根因（经过四轮审讯后）**：
    1. 企业微信统一指令入口（19310）使用本地关键词规则路由，没有调用大模型做语义理解
    2. 系统已部署的本地大模型能力（Ollama/qwen2.5:7b）未被消息入口调用
    3. 血脉探针的异常事件数据未被消费，管家没有查询接口

## 2. 解决方案
*   **核心思路**：在19310的消息处理入口处，增加对本地意图归因API（5801）和报警查询API（5802）的前置调用。意图明确时走归因器路由，意图模糊时走温和兜底，异常报警类直接返回探针数据。失败时自动回退到原有规则。
*   **架构变更点**：19310的消息处理链路从“直接走本地规则”变为“先调5801归因 → 成功则走新路由 → 失败则回退旧路由”
*   **新增组件/脚本**：
    - `D:\杰哥智能化系统\00杰哥系统总管\intention_router\intention_api.py`（意图归因API，端口5801）
    - `D:\杰哥智能化系统\00杰哥系统总管\alert_query_api.py`（报警查询API，端口5802）
*   **修改的配置文件**：
    - `D:\杰哥智能化系统\02杰哥扩展系统\00公共组件\企业微信接入设置\02脚本\企业微信统一指令本地服务入口.py`（增加5801/5802调用逻辑）
    - `D:\杰哥智能化系统\00杰哥系统总管\01配置\最高智能总管_入口规则.json`（增加意图归因和报警查询两条规则）

## 3. 关键发现与解决过程
*   **Ollama端口**：容器映射后实际端口是29134，不是默认的11434
*   **模型选择**：qwen3:14b无法正确输出JSON，qwen2.5:7b经验证是最优选择
*   **启动方式**：28100智能体大脑需要先激活虚拟环境（`.venv\Scripts\Activate.ps1`）
*   **持久化**：5801/5802需注册为Windows计划任务，否则重启后消失
*   **代码修改原则**：在`execute_command`函数前置调用5801，改动量<10行；不改动`classify_route`核心路由函数；失败自动回退

## 4. 验收标准
*   对企业微信系统管家发送“帮我看看茅台” → 引导到股票专家，给出提问模板
*   发送“哈哈” → 温和引导，建议找系统管家，不列菜单
*   发送“今天有什么异常报警” → 返回今日异常事件数量和摘要

## 5. 可复制性评估
*   **哪些子系统可能有同类问题** : 视频制作系统、税收业务系统、工作秘书的入口也面临同样的关键词路由局限
*   **核心可复用部件** : `intention_api.py`的Ollama调用框架、`alert_query_api.py`的异常事件扫描逻辑、19310前置调用的代码模式
*   **预期需要差异化的部分** : 各系统的意图分类提示词（决策树中的关键词和路由目标）；报警查询的数据源路径
