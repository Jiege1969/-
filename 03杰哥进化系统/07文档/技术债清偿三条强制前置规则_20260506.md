# 技术债清偿三条强制前置规则

生成时间：2026-05-06 06:31:55 +08:00

## 一、定位

本文件把“目录锁定、日志分级、上线清单”三类技术债转成以后所有新模块的开工前置规则。

这不是追责文件，而是反退化规则：以后系统继续长大，不能再用同样方式欠同样的债。

## 二、规则一：目录编号先定责

任何新增目录、业务线或能力模块，必须先判断它属于哪一个语义域：

- 系统级目录：`01配置`、`02脚本`、`03数据`、`04日志`、`05备份`、`06临时`、`07文档`。
- 顶层系统：`00总管`、`01智能`、`02扩展`、`03进化`。
- 业务线目录：例如股票、知识库、企业微信、税收、内容、视频。
- 能力模块目录：例如反馈提炼、提示词管理、模型评测、系统复盘。

强制要求：

- 不得只凭编号判断职责。
- 同层同语义域内编号必须唯一。
- 发生编号冲突时，先补 README 和角色索引；不轻易搬目录。
- 新模块开工前必须写明“归属系统、语义域、父目录、输出目录、日志目录”。

## 三、规则二：日志先分级再扩散

任何新增脚本、服务或计划任务，必须在开工前声明日志策略。

统一日志级别：

| 级别 | 用途 | 事件ID |
|---|---|---|
| DEBUG | 临时排查，默认不长期保留 | 可选 |
| INFO | 正常运行记录、心跳、摘要 | 可选 |
| WARN | 可恢复异常、降级、重试、边界提醒 | 建议 |
| ERROR | 失败、阻断、外部动作风险、数据不一致 | 必须 |

强制要求：

- ERROR 必须带事件链 ID，格式 `EVT-YYYYMMDD-NNN-简述`。
- 日志默认写入所属系统 `04日志` 或总管指定日志目录。
- 运行状态输出写入 `03数据\运行状态`，不得散落到业务脚本目录。
- 日志必须声明保留期：短期、滚动、长期证据、永久台账四类之一。

## 四、规则三：上线不是只放功能脚本

任何新能力上线前，必须同时具备：

1. 功能脚本或工作流。
2. 只读探针、健康检查或 dry-run。
3. 日志接入和保留期。
4. 验收标准。
5. 回滚方式。
6. 人工闸口。
7. 安全边界。
8. 台账登记。

缺一项即不得进入正式执行，只能停留在草案、影子、只读或禁用态。

| 目录编号债 | README 和角色索引已补齐，但仍需前置化 | 新增目录编号总图和开工前置规则 |
