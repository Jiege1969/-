# 四系统小闭环通用施工模板

## 一、定位

本模板用于所有子系统施工，不限于股票系统。股票系统只是样板场景，用来验证这套闭环能否在真实业务中稳定运行。

四系统小闭环不是“多做资料”，而是让一个业务系统同时具备：

- 能产出真实业务结果；
- 能被总管系统管住边界和进度；
- 能被智能系统旁路提升质量；
- 能被进化系统提炼可复用经验；
- 能在不依赖某一次对话记忆的情况下继续施工。

## 二、四系统分工

1. 00总管系统

职责：定方向、定边界、定验收、管接续。

必须做到：

- 开工先做状态检查；
- 高风险动作必须有闸口和显式确认；
- 施工过程中只写工作日志和必要业务数据；
- 只有收工或用户明确要新开对话时，才更新接续包、接续卡片、新对话包；
- 不把局部体力活误当成系统闭环。

2. 01智能系统

职责：提供模型、服务、消息桥接、文稿质检等智能能力。

必须做到：

- 默认轻量，按需调用；
- 文稿质检第一阶段只做旁路实验；
- 不自动替换正式输出；
- 不接管正式推送；
- 手机端排版、图片链接、报告链接、免责声明等输出体验必须纳入检查。

3. 02扩展系统

职责：承载真实业务。股票、税收、内容处理、本职工作等都属于扩展系统。

必须做到：

- 有真实输入、真实处理、真实输出；
- 有预览、闸口、正式执行和回滚/防重复机制；
- 输出给用户的是结论、策略、风险、下一步，不是堆砌后台指标；
- 用少量代表性样本证明机制成立，不机械追求无限补资料。

4. 03进化系统

职责：沉淀方法、经验和规则。

必须做到：

- 日志可以全记录，经验库必须慎入库；
- 只沉淀用户明确修正、失败修复成功、重复体验问题、高风险边界变化、可迁移机制；
- 不沉淀闲聊、临时偏好、一次性测试噪声、未验证模型建议；
- 经验沉淀前必须符合学习提炼导航规则。

## 三、标准施工链

任何子系统至少按以下链路推进：

1. 状态检查
   - 服务是否在；
   - 关键文件是否存在；
   - 当前验收是否仍通过；
   - 是否存在旧数据、旧状态或并行竞态风险。

2. 样板任务
   - 选择一个真实、低风险、可验证的业务任务；
   - 不选择过大、过重、无法验收的任务；
   - 样板任务要能代表该子系统的主要工作方式。

3. 预览闸口
   - 正式写入前先生成预览；
   - 预览必须说明会写什么、不会写什么；
   - 预览不允许触发真实发送、正式库写入、外部交易或不可逆动作。

4. 显式执行
   - 只有闸口允许时，才可进入执行器；
   - 执行器必须带显式确认参数；
   - 执行后必须能防重复、可追溯。

5. 验收收束
   - 跑本子系统验收；
   - 跑四系统小闭环验收；
   - 记录工作日志；
   - 不在施工中反复刷新接续包。

6. 经验判断
   - 判断本轮是否有可复用经验；
   - 有则写入经验候选或通用方法；
   - 没有则只留在工作日志。

## 四、股票样板已验证的通用经验

1. 证据链不是为了无限补股票，而是为了证明“预览、闸口、显式执行、正式导入、防重复”的机制成立。

2. CSV、台账、模板等跨对象复用时，必须校验对象身份，例如股票代码、客户编号、业务编号，不能只按字段名保留旧值。

3. 多个生成脚本存在依赖关系时，不要并行运行依赖链，否则会读到旧文件，造成目标错位。

4. 接续包不是施工流水账。施工中只写工作日志；收工或新开对话时再统一固化接续包。

5. 文稿质检是智能层旁路能力，不是正式输出主链路。第一阶段不自动替换、不自动发送、不自动固化模板。

## 五、验收标准

一个子系统可以认为进入“四系统小闭环雏形”，至少满足：

- 扩展系统：有一个真实业务样板跑通；
- 总管系统：有状态检查、闸口、验收、日志；
- 智能系统：至少有一个旁路提质能力或明确的接入位置；
- 进化系统：至少沉淀一条经验证的可复用方法或明确标记“本轮无可沉淀经验”；
- 高风险边界：未真实发送、未自动交易、未绕过人工确认、未滥写接续包。

## 六、禁止事项

- 不为闭环而闭环；
- 不把样板施工变成无限资料补全；
- 不为了智能化而常驻重模型；
- 不把模型建议直接学成规则；
- 不把普通施工日志直接写入经验库；
- 不在用户未要求收工或新开对话时频繁更新接续包。
