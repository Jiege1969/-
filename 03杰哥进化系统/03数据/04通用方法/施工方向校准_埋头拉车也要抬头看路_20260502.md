# 施工方向校准：埋头拉车，也要抬头看路

生成日期：2026-05-02

## 经验来源

股票系统搭建过程中多次出现“解决具体问题”的场景：企业微信入口、点击详情、报告口径、D盘归集、接续包、验收护栏等。每个问题都必须解决，但如果只盯着局部，很容易偏离系统总目标。

## 核心经验

具体问题要解决，但每次解决后都要回到系统主线：

```text
问题是否解决 -> 是否保持主线 -> 是否需要护栏 -> 是否沉淀经验 -> 是否同步接续
```

## 适用场景

- 修复企业微信入口。
- 修改股票报告模板。
- 新增脚本和入口。
- 调整目录和基础设施。
- 接入新数据源。
- 修改验收标准。

## 方向检查清单

每次施工前后检查：

1. 这件事服务于哪个系统目标。
2. 是否影响四大系统分工。
3. 是否触碰安全边界。
4. 是否新增重复入口或临时文件。
5. 是否需要加入验收。
6. 是否需要同步接续包。
7. 是否值得形成经验卡片。

## 可复用规则

- 能小步闭环，不大步铺开。
- 能接入现有链路，不另起炉灶。
- 能做验收护栏，不只靠记忆。
- 能沉淀经验，不只修一次。
- 能保持方向，不被局部问题牵着走。

## 反例

- 为修一个按钮，在桌面生成一堆入口文件。
- 为补一个报告字段，绕过证据核验闸口。
- 为图快，真实发送企业微信或启用 n8n 自动触发。
- 为追求智能，提前推广到全系统，跳过股票试验场。

## 结论

这是后续系统施工的通用方法：脚踏实地干实事，同时不断校准方向。真正的闭环不是“做完一个功能”，而是功能可用、方向不偏、经验可复用。
