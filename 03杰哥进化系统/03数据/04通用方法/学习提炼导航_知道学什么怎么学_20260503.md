# 学习提炼导航：知道学什么、怎么学、从哪里学

生成日期：2026-05-03

## 一、定位

进化系统不是“什么都学”。它的任务是把真实业务、施工、验收和用户确认中的高价值经验，提炼成可复用能力；同时防止闲聊、临时测试、未验证模型建议污染经验库。

## 二、学习判断

优先学习：

- 用户明确修正或认可的原则。
- 失败后修复成功的根因。
- 重复出现的体验问题。
- 影响高风险边界的变化。
- 能迁移到其他系统的机制。

不应学习：

- 普通闲聊和临时口误。
- 未验证的大模型建议。
- 一次性测试输出。
- 已有机制覆盖、没有新增价值的重复记录。
- 没有验收、没有用户确认、没有复用价值的临时偏好。

## 三、学习渠道

主要渠道：

- 工作日志：记录事实经过和用户确认。
- 验收日志：证明机制是否真实跑通。
- 接续包：证明经验是否进入后续施工提醒。
- 文稿质检记录：观察审稿建议是否连续稳定有用。
- 股票证据链和验收面板：从真实业务闭环提炼规则。
- 用户明确打标：`#经验`、`#规则`、`#教训` 或明确认可。

## 四、学习流程

```text
记录
→ 归类
→ 评分
→ 验证
→ 提炼
→ 写边界
→ 固化
→ 定期清理
```

关键要求：

- 先写日志或候选，不直接进长期经验库。
- 模型输出不是事实，必须经过验证或用户确认。
- 可迁移方法必须写清适用范围和反例边界。
- 固化必须落到规则、脚本、验收、模板候选或通用方法中。

## 五、文稿质检案例

本次文稿质检层的学习对象不是“模型写得好不好看”，而是：

- 企业微信手机端和电脑端显示不同，手机端窄屏会造成长链接、长段落、表格错位。
- 本地模型可能为了排版删除图片链接。
- 股票报告的图片链接、报告链接、免责声明、代码、价格、风险线必须由脚本硬比对守门。
- 文稿质检第一阶段必须旁路、手动、按需、可关闭。

这些已经转化为：

- `text_reviewer.py` 的规则检查。
- 审稿 Prompt 的手机端排版提醒。
- 禁止字段硬比对。
- 文稿质检旁路实验验证。

## 六、反偏提醒

进化不是把所有东西都记住，而是让系统越来越清楚：

- 哪些问题值得复盘。
- 哪些经验能迁移。
- 哪些建议必须丢掉。
- 哪些边界不能放松。
- 哪些机制已经足够，不要重复建设。
