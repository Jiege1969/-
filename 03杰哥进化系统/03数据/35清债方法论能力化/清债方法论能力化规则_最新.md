# 清债方法论能力化规则

- 生成时间：2026-05-06
- 定位：把“摸清家底找差距”的施工经验转化为系统可学习、可执行、可复用的治理能力。
- 主要承载系统：总管负责当下执行，进化负责长期沉淀。
- 当前状态：已接入清债决策引擎和新模块开工前置闸口。

## 一、核心判断

清债不是把旧债移动到台账、观察、以后处理里，而是把事实判断、依赖核实、源头修正、删除收口、复验同步连成闭环。

系统以后遇到旧文件、旧路径、旧脚本、旧工作流、旧日志时，按以下顺序判断：

1. 这是当前资产，还是历史副本。
2. 它有没有当前运行、审计、回滚或人工确认依赖。
3. 它是否可再生。
4. 它是否承担正式证据、真实发送、正式导入、写入前备份、回滚凭据作用。
5. 它是否已有标准最新锚点。
6. 它的源头是否仍会继续制造时间戳旧债。

## 二、四类处置

### 可收口旧流水

特征：同类 `*_最新.*`、`*-latest.*` 或同代码最新资产已经存在，旧文件只是时间戳副本，且不命中人工、回执、真实发送、正式导入、写入前备份等审计关键词。

动作：确认或补齐最新锚点后，删除旧时间戳副本；同时把源头脚本改成最新覆盖或受控轮转。

### 需补锚点再收口

特征：旧文件是时间戳流水，但目录里缺少标准最新锚点。

动作：从最新一份生成标准最新锚点，修正源头脚本，再删除旧副本。不能因为“没有最新锚点”就长期观察。

### 审计资产单独核实

特征：涉及人工填写、正式回执、真实发送、凭据隔离、写入前备份、历史K线刷新前备份、不可再生数据。

动作：不得混入普通流水批量删除。先判定不可再生、可回滚、正式证据，保留必要证据和当前权威资产，再清重复流水。审计资产核实不是“以后处理”，而是进入专门资产化和压缩收口路径。

### 现役保留

特征：当前规则、母样本、台账、最新报告、最新配置、运行入口依赖。

动作：保留；如存在重复命名，合并为当前权威资产。

## 三、施工节奏

每轮清债按六步执行：

1. 扫描：只读统计旧时间戳、最新锚点、目录热度和命中规则。
2. 分类：按可收口、需补锚点、审计资产、现役保留分组。
3. 止血：先改还在制造时间戳副本的脚本源头。
4. 收口：删除已证实无依赖旧副本。
5. 纠错：施工中发现误补、误判、坏字符，立即修正，不挂待办。
6. 复验：接续包、开工上下文、总管闭环、坏字符扫描全部通过后同步面板。

## 四、复制到新系统

股票系统作为母样本时，只复制以下成功基因：

- 最新锚点策略。
- 人工闸口。
- 禁用态和灰度态分层。
- 只读探针。
- 交付验收。
- 安全边界。
- 母样本工作流。
- 清债决策预检。

不得复制以下旧债：

- 时间戳流水无限堆叠。
- 无台账工作流。
- 无保留期日志。
- 无源头治理的清理脚本。
- 把可判断依赖推回用户确认。

## 五、总管与进化双回路

总管负责把规则变成当前动作：

- 开工前运行清债决策引擎。
- 对候选目录输出分类、数量、体积、样例和下一步动作。
- 能证实无依赖的旧流水进入收口批次。
- 需要补锚点的目录先修源头再收口。
- 审计资产进入专门资产化清单，不混删、不长期悬挂。

进化负责把有效方法沉淀成长期规则：

- 每次施工发现可复用方法，沉淀为规则卡。
- 每次清债发现误判，沉淀为否决条件或纠错规则。
- 每次新系统搭建，先读取股票母样本成功基因和清债防复发规则。
- 每次发现“留档观察式新债”，把它转成可执行的规则、脚本或删除批次。

## 六、系统能力化要求

总管必须具备清债决策报告脚本，至少输出：

- 可收口旧流水目录。
- 需补锚点目录。
- 审计资产目录。
- 现役保留口径。
- 每类文件数量、体积、样例。
- 推荐下一步动作。

当前落地入口：

```powershell
python "D:\杰哥智能化系统\00杰哥系统总管\02脚本\生成清债决策引擎报告.py"
python "D:\杰哥智能化系统\00杰哥系统总管\02脚本\验证清债决策引擎报告.py"
```

安全边界：清债决策引擎只读扫描并写报告，不直接删除；删除由经分类后的施工批次完成。
