## 二、股票系统当前定位

股票系统应作为“成熟样本”和“能力母本”，但不是其他业务线的套壳模板。

当前硬边界清楚：

- 股票系统是研究分析系统，不是交易系统。
- 自动交易、券商接口、下单、撤单、资金账户、交易工作流均为关闭和禁止项。
- 允许范围是研究分析、风险提示、关注条件、复盘、证据核验、企业微信问答和报告输出。

这条边界本身就是可复用能力：任何业务系统都应区分“可分析、可建议、可草案”和“不可自动执行”的边界。

## 五、对税收影子底座的直接启发

股票母本可直接转化为税收影子底座的四条方法：

1. 候选依据，不直接结论。
2. 风险点和待核实事项必须显式列出。
3. 地方口径、基层流程缺失时，降级为待补，而不是停工或强答。
4. 人工复核意见进入样本，不自动变成规则。

对应到税收业务：

```text
政策资料 -> 候选依据
适用条件 -> 条件匹配
地方口径 -> 待核实事项
用户补充 -> 人工修正样本
草案输出 -> 待复核草案
```

## 六、不适配提醒

不能把股票系统的以下模式机械复制给税收、内容、视频等业务线：

- 高频定时刷新。
- 盘中保护。
- 单股短回复风格。
- 行情指标体系。
- 技术分析术语。
- 交易语境下的买卖观察表达。

这些能力背后的“结构思想”可以借鉴，但业务表现必须重写。

## 七、母本结论

股票系统最值得复用的不是“股票功能”，而是以下底层能力：

> 可信输入、只读预检、候选判断、风险边界、人工闸口、待复核输出、复盘沉淀、灰度回滚。

这八项应进入所有后续业务系统的开工检查。
