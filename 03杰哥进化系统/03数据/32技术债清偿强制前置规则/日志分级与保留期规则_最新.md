# 日志分级与保留期规则

生成时间：2026-05-06 06:31:55 +08:00

## 一、目标

控制日志规模债，避免日志散落、无级别、无事件关联、无保留期。

## 二、四级日志

| 级别 | 记录内容 | 默认保留 | 说明 |
|---|---|---|---|
| DEBUG | 临时排查、变量细节、实验信息 | 1-3 天 | 默认不得长期保留 |
| INFO | 正常运行、心跳、探针 ready、任务完成 | 7-30 天 | 可滚动压缩 |
| WARN | 降级、重试、边界提醒、可恢复异常 | 30-90 天 | 建议带事件ID |
| ERROR | 阻断、失败、数据不一致、高风险动作拦截 | 长期证据 | 必须带事件ID |

## 三、事件链 ID

ERROR 必须带事件链 ID：

`EVT-YYYYMMDD-NNN-简述`

一次事件链至少记录：

- 前件：定时、手动、预警或用户指令。
- 检查：探针、状态、依赖、路径。
- 动作：执行了什么。
- 结果：成功、异常、跳过或阻断。
- 验收：自动或人工结论。

## 四、目录口径

- 运行状态：`03数据\运行状态`
- 运行日志：所属系统 `04日志`
- 长期证据：总管台账或 F 盘备份台账登记后保留
- 临时调试：`06临时` 或专用调试目录，必须有清理期限

## 五、新脚本前置要求

新增脚本必须声明：

- 日志级别。
- 日志路径。
- 最大保留天数或保留策略。
- 是否产生事件ID。
- 是否写最新状态文件。
- 是否写滚动 JSONL。

## 六、禁止项

- 禁止 ERROR 无事件ID。
- 禁止日志写到脚本同级目录后长期堆积。
- 禁止把运行状态、调试日志、证据台账混在一个目录。
- 禁止没有保留期的新定时任务。

## 七、清理判定口径

日志清理不得只按“旧不旧”判断，必须先判断未来核查价值。

应保留的日志：

- 记录将来可能需要核查的问题、故障、异常、误判、回滚、验收、审计、安全边界或人工确认。
- 记录尚未完全闭环的问题，即使当前服务恢复，也仍可能用于追溯原因。
- 记录可复盘的关键施工节点，例如删除前后证据、主线能力验收、数据一致性检查。

可删除的日志：

- 仅属于工作流水账、轮询心跳、重复状态检查、临时演练输出。
- 对应问题已经解决、验收通过，且已有收口报告或台账记录关键结论。
- 不含唯一配置、凭据、异常原因、回滚依据、审计价值或未来核查价值。

执行要求：

- 删除前读取内容或结构化抽样，确认其不属于未来核查证据。
- 对小批量候选，优先逐个读取复核；对大批量候选，先按事件链、级别、关键词和抽样建立保护清单。
- 不得把已确认无效的流水账压缩归档成新债。
- 若日志含未来核查价值，应纳入证据链或长期台账，而不是混在普通流水账里。
