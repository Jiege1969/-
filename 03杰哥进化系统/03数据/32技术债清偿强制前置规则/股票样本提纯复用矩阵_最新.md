# 股票样本提纯复用矩阵

时间：2026-05-06

## 一、核心判断

先把股票分析系统搭建好，再以它作为其他系统的底基和样本，这个思路是有效的。它让系统从抽象规划进入真实可运行状态。

但当前债务也与这个思路有关：早期股票系统为了跑通功能，积累了目录、日志、工作流、守护、台账、旧路径等债务；如果其他系统整包照抄，就会把这些债务复制出去。

所以后续不是否定股票样本，而是提纯股票样本。

## 二、复用原则

- 成功基因要吸收。
- 债务教训要纠正。
- 业务专用内容不得误当通用模板。
- 复用前必须写清“复用什么、不复用什么、纠正什么”。

## 三、提纯矩阵

| 类别 | 股票系统内容 | 对其他系统的处理 |
|---|---|---|
| 成功基因 | 分层推进、只读分析、质量面板、验收闭环、人工闸口 | 直接复用为施工方法 |
| 成功基因 | 从样本到灰度再正式 | 复用为所有业务系统上线节奏 |
| 成功基因但需控风险 | 企业微信、n8n、模型、Docker 联动 | 只允许 shadow/dry-run 起步 |
| 债务教训 | 目录和编号早期未锁死 | 新系统开工前先定目录职责和 README |
| 债务教训 | 日志散、保留期不足 | 新脚本必须声明日志级别、事件 ID、保留期 |
| 债务教训 | 工作流重复和台账滞后 | 新工作流必须先登记归属、风险、回滚、禁用状态 |
| 债务教训 | 守护和探针后补 | 上线当天必须同步探针、日志、验收、回滚 |
| 禁止复发 | 旧路径、旧任务、死配置残留 | 证据充分无依赖时同轮收口 |
| 禁止误用 | 股票行情、交易语义、股票池指标 | 只做模式参考，不搬到税收/办公/内容系统 |

## 四、系统落地

### 税收系统

复用：证据链、分层资料池、报告生成、人工确认。

纠正：不得复制股票交易语义；不得自动申报、自动提交；知识库必须有来源、版本、地区、有效期。

### 总管系统

复用：状态面板、探针、验收、事件链。

纠正：总管不得承载业务主逻辑；总管只做协调、闸门、台账和状态感知。

### 进化系统

复用：复盘、经验卡、反退化检查。

纠正：规则必须能阻断施工，不只做文档摆设。

### 智能系统

复用：模型路由、提示词模板、只读问答、质量评估。

纠正：提示词必须版本化；模型和依赖必须有清单；模型不得越过人工闸口触发外部动作。

### 其他扩展系统

复用：先样本、再灰度、再正式。

纠正：每个业务系统必须声明自己的业务边界、数据资产和禁止动作。

## 五、开工硬门

任何新系统如果说“参考股票系统”，必须同时提交：

- 成功基因复用清单。
- 债务规避清单。
- 业务专用内容禁止复制清单。
- 只读/dry-run 路线。
- 台账、日志、验收、回滚入口。

缺任一项，只能停留在草案或影子态。
