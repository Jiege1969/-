# 并发写最新文件竞态经验卡片

生成时间：2026-04-28

## 一、问题现象

在股票企业微信 n8n 适配器禁用态验收中，本地验收和总管汇总并行运行，同时写入 `股票企业微信n8n适配器禁用态_最新.json`，导致最新文件出现 JSON 叠写和半写入内容，读取时报 `JSONDecodeError`。

## 二、原因判断

- 多个进程同时写同一个 `最新.json`。
- 写入方式是直接覆盖文本文件，缺少临时文件和原子替换。
- 验收脚本优先读取 `最新.json`，没有回退读取最近完整时间戳文件。

## 三、修复办法

- 写最新文件时先写入 `.tmp` 临时文件，再用原子替换覆盖目标文件。
- 验收读取最新文件失败时，回退扫描同目录下最近的完整时间戳 JSON 文件。
- 对会写同一最新文件的验收，避免在同一轮并行执行同一链路的本地验收和总管汇总。

## 四、可复用规则

- 凡脚本会写 `*_最新.json`、`*_最新.md`，应优先使用临时文件加原子替换。
- 凡验收依赖 `最新.json`，应考虑读取失败时的完整文件回退。
- 总管汇总脚本内部已经调用本地验收时，不应和本地验收脚本并行运行。

## 五、适用范围

- 00总管验收链路。
- 02扩展系统业务脚本。
- 03进化系统经验样本。
- 所有会同时写入“最新”文件的本地自动化脚本。

## 六、安全边界

本经验卡片只记录经验，不删除文件，不覆盖旧系统，不触发 n8n，不发送企业微信，不写正式库，不调用交易接口。
