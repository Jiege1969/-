# D盘归集后SSH私钥ACL修复经验卡片

生成时间：2026-05-02 10:57

## 问题

D盘目录归集后，股票企业微信公网回调从接续记录中的 ready 变成公网 502；本地 `19300` 股票助手和 `19302` 企业微信桥接仍正常。

## 根因

SSH 私钥 `D:\杰哥智能化系统\01杰哥智能系统\01配置\云服务器密钥\jiege_agent_relay_ed25519` 继承了过宽 ACL，包含 `Authenticated Users`、`Users` 等权限。Windows OpenSSH 报 `UNPROTECTED PRIVATE KEY FILE` 并忽略私钥，导致反向隧道进程看似存在但实际不可用。

## 修复逻辑

不要重建公网回调；先按日志确认原链路：

```text
43.167.210.211 -> 127.0.0.1:18080 -> 127.0.0.1:19302
```

再把私钥 ACL 收紧为当前用户只读，例如：

```text
杰哥\Administrator:(R)
```

然后用既有受控脚本恢复隧道：

```text
D:\杰哥智能化系统\02杰哥扩展系统\01股票研究系统\02脚本\停止股票公网回调隧道.ps1
D:\杰哥智能化系统\02杰哥扩展系统\01股票研究系统\02脚本\启动股票公网回调隧道.ps1
```

## 验证

- `查看股票公网回调状态.ps1` 必须返回 `ready`。
- `local_bridge_ok=true`
- `ssh_tunnel_ok=true`
- `public_callback_ok=true`
- 公网 GET/POST `/wecom-bot/message` 可返回股票助手回复。
- 主动推送先跑 dry-run，确认 `ok=true` 且不真实发送。

## 经验

凡是做磁盘归集、目录迁移、备份还原、复制密钥文件后，不能只看文件是否存在，还必须检查 SSH 私钥 ACL。私钥权限错误会造成“服务在、本地通、公网不通”的假运行状态。

## 边界

该修复只处理隧道与私钥权限，不触发 n8n，不真实发送企业微信，不调用券商接口，不自动交易，不写旧系统。
