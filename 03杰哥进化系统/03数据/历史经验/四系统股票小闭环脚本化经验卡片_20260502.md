# 四系统股票小闭环脚本化经验卡片

生成日期：2026-05-02

## 一、来源问题

用户明确要求：开始搭建“股票分析系统、总管系统、智能系统、进化系统组成的稳定可复用闭环”。

这不是单个股票功能修复，而是要把四个系统之间的协作关系固化为可重复执行的流程。

## 二、核心经验

四系统闭环不能只停留在设计文字里，必须脚本化、可验收、可接续。

有效做法是：

```text
总管定方向和边界
-> 智能系统提供服务与企微底座
-> 股票扩展系统承载真实业务和验收
-> 进化系统沉淀经验与规则
-> 总管更新日志、接续和下一轮计划
```

## 四、可复用规则

以后只要继续股票系统施工，收工前至少判断：

1. 总管是否有最新计划、日志、接续包。
2. 智能系统的 `19300` 股票助手和 `19302` 企微桥接是否正常。
3. 股票扩展系统是否仍通过完全交付、C+++、日常一键和企微前台回归。
4. 进化系统是否沉淀了本轮经验或方法。
5. 是否刷新了下一轮接续材料。

## 五、验收口径

四系统小闭环成立，不看文档多少，而看是否同时满足：

- 四个系统环节都能被脚本检查到。
- 股票系统真实业务仍可用。
- 智能底座服务仍正常。
- 总管能生成状态面板和验收报告。
- 进化系统有经验沉淀。
- 安全边界没有放宽。

## 六、安全边界

- 不真实发送企业微信。
- 不启用 n8n 自动触发。
- 不调用券商接口。
- 不自动交易。
- 不写正式业务库。
- 不删除文件，不重启正式服务，除非用户明确确认。
