# 四系统闭环必须纳入公网回调经验卡片

生成日期：2026-05-02

## 一、来源问题

四系统股票小闭环一键执行时，股票系统本地验收、C+++、日常一键和企微前台回归均通过，但四系统状态面板失败。

实际断点是：

- `19302` 股票企业微信桥接入口一度未监听。
- 本地桥接恢复后，公网回调仍未 ready。
- 原四系统闭环只检查本地服务和本地回归，没有把 SSH 公网回调隧道纳入一键执行器。

这会导致“本地通过，但手机企业微信不可用”的假稳定。

## 二、修复动作

- 用既有受控脚本恢复 `19302` 股票企业微信桥接入口。
- 用既有受控脚本恢复股票公网回调 SSH 反向隧道。
- 修改 `生成四系统股票小闭环状态面板.py`，新增“公网回调 ready”检查。
- 修改 `执行四系统股票小闭环.py`，把 `查看股票公网回调状态.ps1` 纳入一键执行动作。
- 修正企微前台回归验收口径：从固定 `20/20` 改为“至少20项且失败0”，避免回归用例扩展到34项后误报。

## 三、可复用规则

涉及企业微信手机端可用性时，不能只检查本地 `19302`。

必须同时检查：

1. 本地股票助手 `19300` 正常。
2. 本地企微桥接 `19302` 正常。
3. SSH 反向隧道存在。
4. 公网回调探针通过。
5. 探针不得真实发送企业微信，不得调用交易。

## 四、长期护栏

四系统股票小闭环一键执行器必须包含公网回调 ready 检查。

如果未来企微回归用例增加，验收应使用“通过数量 >= 基准数量 且失败数量 = 0”，不要写死旧数量。

## 五、安全边界

- 恢复桥接和隧道只使用既有受控脚本。
- 不真实发送企业微信。
- 不启用 n8n 自动触发。
- 不调用券商接口。
- 不自动交易。
- 不写正式业务库。
