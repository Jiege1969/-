# 03进化系统轻量任务契约规则卡

创建日期：2026-05-05

任务标识：parallel-C-03-light-task-contract-rule-deposit

定位：学习 OpenClaw/Hermes 的任务契约、编排分层、状态账本和可审计回收逻辑，只抽象方法，不引入原件、代码、协议、依赖或外部工作流。

## 总原则

- 不新增第二中枢：00总管仍是跨系统入口、口径和汇总中枢，03只沉淀规则与审计证据。
- 标准任务单JSON先行：所有轻量任务先形成可解析任务单，任务单只表达意图、边界、输入、输出、风险和验收。
- SQLite为影子权威台账：仅在影子层记录任务、状态、验收和阻断原因，不写正式库，不驱动真实动作。
- Redis先做影子增强：仅缓存任务ID、影子状态、幂等键和审计索引，不做真实动作队列或权限放行器。
- n8n只干跑：只允许mock payload、本地解析和审计说明，不调用webhook，不启用工作流。
- 真实动作单线闸门：企业微信、正式库、n8n、券商接口、自动交易等真实动作默认关闭，未来如需放行必须走唯一人工闸门。
- 股票分析only：股票任务只允许分析、复盘、规则沉淀和只读验收，不连接券商、不下单、不自动交易。

## 标准任务单JSON契约

必填字段：`task_id`、`source_system`、`target_system`、`intent`、`scope`、`inputs`、`expected_outputs`、`safety_boundary`、`dry_run`、`real_action_requested`、`acceptance`。

任务单不得被解释为 n8n 触发许可、企业微信发送许可、正式库写入许可、券商接口调用许可或自动交易许可。

## 核心规则

| 规则ID | 规则名称 | 验收口径 |
| --- | --- | --- |
| LTC-001 | 不新增第二中枢 | 不声明总调度、总入口、总权限或总执行器；只作为03规则沉淀依据。 |
| LTC-002 | 标准任务单JSON先行 | 必填字段齐全，`dry_run=true`，`real_action_requested=false`。 |
| LTC-003 | SQLite作为影子权威台账 | 角色为 `shadow_authoritative_ledger`，不写正式库，不驱动真实动作。 |
| LTC-004 | Redis先做影子映射增强 | 角色为 `shadow_mapping_enhancement`，缓存可由JSON和SQLite重建。 |
| LTC-005 | n8n只允许干跑 | `triggered=false`、`webhook_called=false`、`workflow_enabled=false`。 |
| LTC-006 | 真实动作单线闸门 | `real_actions_enabled=false`，不存在多入口或默认放行。 |
| LTC-007 | 股票分析only | `broker_api_called=false`、`auto_trade=false`、`order_placed=false`。 |

## 安全边界

本规则卡不触发 n8n、不发送企业微信、不写正式库、不调用券商接口、不下单、不自动交易、不读取生产凭据、不发起外部网络调用。
