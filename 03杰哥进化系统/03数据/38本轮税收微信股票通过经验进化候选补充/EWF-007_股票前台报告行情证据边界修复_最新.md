# EWF-007 股票前台报告行情证据边界修复

生成时间：2026-05-12 07:27:00

## 施工目标

把“公开行情快照降级”这类底层数据状态传递到前台报告和企业微信短答，避免报告把非实时行情说成实时行情。

## 施工内容

- 修复 `生成重点关注池公开行情快照.py`：公开接口失败时复用最近一次快照，并明确写入 `是否降级`、`数据新鲜度`、`降级原因`、`降级来源快照生成时间`。
- 修复 `股票助手入口.py`：标准报告v2新增行情口径证据；风险提醒新增“降级快照不按实时行情执行”。
- 修复 `股票助手入口.py`：企业微信前台短答新增行情提示，机器人直接回复也能看到数据边界。
- 重启 19300 股票助手服务，使运行中的企业微信入口加载新逻辑。

## 验证结果

- `python -m py_compile 股票助手入口.py`：通过。
- CLI `--json 分析云南锗业`：企业微信回复包含“行情提示：当前行情为最近一次公开快照”。
- HTTP `GET http://127.0.0.1:19300/health`：状态正常，端口19300在线。
- HTTP `POST http://127.0.0.1:19300/analyze`：企业微信回复包含行情降级提示。
- 最新标准报告v2包含：
  - 风险提醒：行情数据为降级快照，不按实时行情执行，只作为研究观察。
  - 证据补充：行情口径已降级为最近快照，原始行情时间为2026-05-11 13:28:35。

## 当前边界

- 这次只修复行情证据边界，没有补齐财报正文、公告、行业价格连续序列。
- 若公开行情接口恢复，快照脚本会回到正常公开行情口径，前台短答不再显示降级提示。
- 未开放真实发送企业微信、未触发n8n、未调用券商接口、未自动交易。

## 后续建议

把“数据新鲜度/证据缺口/方法适配状态”统一做成前台报告证据头，所有报告先交代数据来源，再给结论。
