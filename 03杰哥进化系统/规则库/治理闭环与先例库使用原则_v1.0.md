# 治理闭环与先例库使用原则 v1.0

固化日期：2026-05-10

## 一、定位

本文件属于进化系统规则库，用于约束进化系统如何参与杰哥智能化系统治理内核。

进化系统的职责是复盘、提炼和提出规则优化草案。它不得绕过总管直接修改生产规则，不得擅自打开真实发送、外网写入、交易、规则进化生效开关。

## 二、治理闭环

治理闭环不是业务执行流程，而是治理系统对自身效果的复盘机制：

```text
施工申请 -> 风险定级 -> 门禁检查 -> 执行或阻断 -> 证据归档 -> 结果复盘 -> 规则优化提案
```

进化系统可以定期分析：

- 施工门禁通过率；
- 阻断原因；
- 同类问题是否复发；
- 是否出现误放行；
- 是否出现误阻断；
- 哪些检查项太松；
- 哪些检查项过度冗余；
- 哪些旧规则与当前实践冲突。

进化系统输出的是草案，不是生效规则。草案必须经总管评估，重大变更必须由杰哥确认。

## 三、先例库不是教条库

先例库是经验材料库，不是自动授权库。

先例可以提供：

- 曾经的处理思路；
- 曾经的风险定级；
- 曾经的门禁组合；
- 曾经的证据路径；
- 曾经的失败原因；
- 曾经的复发记录。

先例不能提供：

- 当前自动放行；
- 当前自动授权；
- 当前免检查资格；
- 当前机械照搬命令；
- 当前越过上级规则的理由。

## 四、先例复用四原则

1. 参考原则：先例是判断材料，不是最终裁决。
2. 重审原则：每次复用先例，都必须重新检查当前环境、对象、风险和边界。
3. 抽象原则：优先复用理念、结构和验证方法，不优先复用具体命令。
4. 反证原则：如果当前条件与先例不同，先例必须降权，必要时作废。

## 五、遗产吸收四种命运

老系统遗产进入治理内核前，必须标明处理方式：

| 命运 | 含义 |
|---|---|
| 收编 | 机制正确、仍然适用，纳入新总管 |
| 改造 | 思想有用，但实现旧了，改为统一入口 |
| 归档 | 历史有价值，但不再执行 |
| 封存 | 有风险、冲突、过期，禁止误调用 |

## 六、最低结构化字段

每条先例或遗产记录至少应包含：

- 先例编号；
- 来源文件；
- 所属层级；
- 适用系统；
- 对应规则；
- 施工类型；
- 风险等级；
- 执行结果；
- 证据路径；
- 可复用理念；
- 可复用方法；
- 禁止复用动作；
- 最后复核日期。

## 七、安全边界

进化系统任何治理建议都必须声明：

- 不直接触发 n8n；
- 不直接发送企业微信；
- 不直接调用券商接口；
- 不直接自动交易；
- 不直接修改生产规则生效开关；
- 不把历史先例当作当前授权。
