## 三、不适配场景：母本复制前的反适配检查

| 母本设计 | 在什么业务线中不适用 | 不适配时应替换为 |
|:---|:---|:---|
| 高频刷新最新锚点 | 税收系统，数据低频变更 | 按事件驱动刷新，非定时刷新 |
| 股票式硬 fail-closed | 内容处理，草稿不应因一项指标闭口 | 软降级：标记异常但继续可用 |
| 轻量日志策略 | 视频系统，渲染过程需完整日志 | 按任务批次保留完整过程日志 |
| 实时企业微信推送 | 视频系统，渲染完成才需要通知 | 仅在任务完成或失败时推送 |
| 每个环节人工闸口 | 高频自动化任务 | 仅关键节点设闸口，其余自动化 |
| n8n当主脑 | 所有业务线 | n8n只负责编排和提醒，判断、账本、源数据处理留在业务系统和总管 |
| Redis正式主链默认接管 | 初期业务线或证据链未稳定业务线 | Redis先做影子队列/缓存，正式队列需单独许可 |
| 股票交易意图拦截词原样复制 | 税收、内容、视频、办公等非股票业务 | 提取“高风险意图拦截”方法，重写本业务的高风险词表 |
| 股票L5/L6/L7/L8分层 | 非候选池型业务 | 改为该业务自己的阶段：采集、预审、生成、复核、交付、归档 |
| 企业微信可信IP真实发送流程 | 不需要外部主动通知的业务线 | 使用本地报告或人工打开入口；真实发送另走灰度许可 |
| 单股证据核验字段 | 税收政策、视频素材、知识库文档 | 保留“证据核验链”结构，重写字段和验收标准 |

## 五、母本提取原则

- 只读提取，不修改股票系统。
- 提取的是成功基因，不是机械复制目录。
- 每个结论必须能指向实测依据、脚本路径、文档路径或运行现象。
- 不可把股票专有规则包装成通用规则。
- n8n、Redis、企业微信真实发送、模型路由均不得默认为已放量能力。
- 发现股票系统中的坏模式，进入清债队列；只有触发清债条件时才切换轮次处理。

## 六、轮次002登记的坏模式：只登记，不在本轮清理

| 坏模式 | 影响 | 当前处理 |
|:---|:---|:---|
