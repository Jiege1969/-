# 道术映射工作流

> 版本：v1.0  
> 生效日期：2026-05-07  
> 所属系统：03杰哥进化系统 / 规则库  
> 定位：把用户用业务语言表达的“想要什么”，转化为可施工、可复核、可进化的设计方法

## 1. 使用场景

当用户提出一个新系统、新功能、新业务场景，尤其是税收、视频、本职工作、企业微信非股票业务等扩展系统并准备进入方案设计或正式施工时，执行本工作流。普通总结、只读核查、材料整理不强制进入完整流程。

## 2. 工作流总览

```text
用户场景描述
-> 提炼“道”：目的、价值观、边界、用户主导权
-> 提炼“术”：输入、输出、字段、流程、样例、验收
-> 区分通用与专用：哪些能进入母本，哪些只能留在本业务线
-> 形成第一阶段施工图
-> 落成影子样例或可信底座
-> 人工复核与进化沉淀
```

## 3. 第一步：提炼道

必须回答：

| 问题 | 说明 |
|:---|:---|
| 用户真正想解决什么问题 | 不是功能名，而是业务困惑或使用场景 |
| 系统应扮演什么角色 | 助手、整理者、分析者、提醒者，不是替代者 |
| 哪些价值不可牺牲 | 诚实、证据、边界、人工确认、可追溯 |
| 不知道时怎么办 | 降级、标注不确定项、提示补材料 |

## 4. 第二步：提炼术

必须回答：

| 项目 | 说明 |
|:---|:---|
| 输入 | 数据/资料/素材/问题来自哪里 |
| 元数据 | 需要记录哪些字段 |
| 处理链条 | 从输入到草案经历哪些步骤 |
| 输出 | 给用户看的业务语言产物是什么 |
| 复核 | 用户在哪里修正、补充、否决 |
| 进化 | 修正如何进入案例库或策略锚点 |
| 验收 | 第一阶段做到什么算完成 |

## 5. 第三步：区分通用与专用

| 类型 | 处理 |
|:---|:---|
| 通用理念 | 进入策略锚点库或可信业务智能体通用纲领 |
| 通用流程 | 进入业务系统母本模板 |
| 业务专用字段 | 留在对应业务系统设计纲领 |
| 未成熟想法 | 进入待讨论，不施工 |

## 6. 第四步：第一阶段施工图

第一阶段必须足够小，优先选择“可信底座”或“影子样例”：

- 税收：国家级政策可信底座 + 地方口径待补机制 + 待复核草案样例。
- 内容：原文来源/授权/用途登记 + 改写草案 + 人工复核。
- 视频：素材需求/授权状态 + 脚本草案 + 分镜草案。
- 股票：证据链/候选池/风险提示/复盘修正。
- 本职工作：任务材料/目标/约束 + 行动建议草案。

## 7. 第五步：脚本和命令落地原则

后续写脚本或命令时，应体现：

- R0脚本只读，不写状态。
- W1刷新锚点必须声明。
- W2/W3必须人工确认。
- 输出文件必须标明资产身份。
- 草案文件必须标明“待复核”。
- 不确定项必须显式列出。
- 人工修正不得自动升级为正式规则。

## 8. 施工前检查

正式施工或高风险动作前必须确认：

```text
方向校准：服务主线=是/否；增强能力=是/否；临时清理冲动=是/否；结论=执行/入待清队列/暂停讨论
```

扩展系统进入正式可运行功能前必须完成开工五问；普通讨论、影子样例、资料结构整理不作为正式开工。

## 9. 结论

道决定方向，术决定落法。魂是诚实、可靠、可追溯、可复核、可进化；用是每个业务系统根据自身特点选择字段、流程、模板和闸口。
