# 持续学习与经验入库规则

> 版本：v1.0  
> 生效日期：2026-05-09  
> 所属系统：03杰哥进化系统 / 规则库  
> 上位契约：`杰哥智能系统内生理念与能力契约_v1.0`  
> 关联规则：`系统原则到能力转化规则_v1.0`、`智能有机体成形规则_v1.0`、`主动纠错与防机械执行规则_v1.0`  
> 定位：把讨论、施工、问题修复和系统运行中形成的有效方法，转化为可复用、可验证、可进化的系统规则和能力。

## 一、根本原则

杰哥智能系统必须具备持续学习能力。

持续学习不是简单记录聊天内容，也不是把所有想法都写成规则，而是把真实讨论、真实施工、真实问题、真实复验中反复有效的经验，经过提炼、分类、验证和固化，进入系统自己的规则库、检查器、模板、面板、接续包或业务子系统。

```text
用户提醒/施工经验/系统问题
-> 经验素材
-> 进化候选
-> 验证样本
-> 规则或模板
-> 检查器/面板/接续包/业务能力
-> 后续运行复验
```

只有进入后续运行并能被复用的经验，才算系统真正学会。

## 二、必须提炼的来源

以下内容不得只停留在当次对话：

- 用户反复强调的原则、担心和判断。
- 搭建中实际有效的方法。
- 纠错中暴露出的系统性问题。
- 复验中证明有效的防范机制。
- 并行施工中形成的边界和协同经验。
- 旧系统、旧文档、旧失败中的可迁移方法。
- 系统自己发现的误判、误拦、机械执行、方向偏差。

## 三、入库分层

| 层级 | 内容特征 | 处理方式 |
|:---|:---|:---|
| 经验素材 | 单次想法、单次观察、未验证方法 | 记录为候选，不直接升格 |
| 进化候选 | 已有明确问题和适用场景，但样本不足 | 放入进化候选或问题回收 |
| 规则候选 | 至少一次真实修复或复验有效，边界清楚 | 写入规则草案或模板 |
| 正式规则 | 多次有效、可迁移、可验收、不与上位规则冲突 | 进入规则库并接入检查 |
| 运行能力 | 已进入脚本、面板、接续包、开机自检、业务流程 | 作为系统能力持续复验 |

## 四、经验入库七问

每次讨论、施工、纠错或复验后，系统都要判断：

1. 这里有没有可复用的原则、方法或防错机制？
2. 它解决的是方向、稳定、边界、效率、体验、协同还是进化问题？
3. 它只是一次偶然有效，还是可迁移到其他系统？
4. 它应进入总管、智能、进化、扩展，还是某个业务子系统？
5. 它应该落成规则、模板、检查器、脚本标头、面板、接续包、回执字段还是业务流程？
6. 它有没有触碰真实外发、交易、税务、正式库、服务重启等红线？
7. 它下一次如何被开机自检、只读巡检、回归、自然日样本或用户真实使用验证？

## 五、升级和降级

持续学习必须去伪存真：

- 只说得通、没有实践结果的，留为素材。
- 一次有效但边界不清的，留为候选。
- 多次有效但适用范围窄的，做局部规则。
- 多业务可迁移且验收清楚的，升为通用规则。
- 反复失效、过度复杂或制造新旧债的，降级、归档或废弃。

## 六、防止规则山

系统要学习，但不能把学习变成堆文件。

新增规则前先判断：

- 现有规则能否覆盖？
- 是否只需要补充索引、检查项或样例？
- 是否有真实问题支撑？
- 是否能进入后续运行？

如果没有真实问题、没有复用价值、没有验收方式，不得升格为新规则。

## 七、落点要求

一条经验真正进入系统，至少要落到以下一个位置：

- 规则库。
- 进化候选记录。
- 检查器。
- 开机自检或每日巡检。
- 当前施工面板。
- 一键接续施工包。
- 业务子系统配置、模板或回执。
- 问题回收和复验记录。

若它只停留在对话里，视为未吸收。

## 八、典型样例

本次“不要机械执行规则”的经验，不能只成为一次提醒，而应完成：

```text
用户提醒 -> 主动纠错与防机械执行规则 -> 只读检查器
-> 开机自检接入 -> 面板和接续包记录 -> 后续复验
```

本规则本身也必须被检查：如果以后系统又出现“用户已经明确指出低风险问题，系统却机械等待确认”，应视为持续学习机制未生效，需要问题回收和规则复盘。

## 九、总则

```text
智能不是一次答对，
而是每次答错后能提炼，
每次做对后能复用，
每次复用后能验证，
每次验证后能进化。
```
