# 四大系统与子系统内生能力分层落地规则

> 版本：v1.0  
> 生效日期：2026-05-09  
> 所属系统：03杰哥进化系统 / 规则库  
> 上位契约：`杰哥智能系统内生理念与能力契约_v1.0`  
> 子系统模板：`业务子系统问题分型与复核回执模板_v1.0`  
> 定位：把杰哥智能系统的内生理念和能力，分层落实到四大系统以及各业务子系统，确保能力不是只停留在总管层，而是逐层具备、逐层约束、逐层反馈。

## 一、总原则

杰哥智能系统整体要具备智能有机体能力，四大系统和子系统也必须具备与自身职责相匹配的能力。

不是要求每个子系统都拥有全部总管能力，而是要求每个系统在自己的层级内具备对应的：

```text
目标定位
层级服从
输入输出契约
感知反馈
调度协同
边界免疫
问题修复
问题分型
复核入账
记忆进化
用户可感知闭环
教学相长
上位目标统摄下位条件
```

## 二、四大系统分工

| 系统 | 核心职责 | 必须具备的内生能力 |
|:---|:---|:---|
| 00杰哥系统总管 | 总目标、边界、调度、接续、验收、交付判断 | 总目标判断、依赖调度、红线免疫、交付验收、接续记忆、问题升级、P1分型、同日修复后复核入账判断、用户反馈回收、条件服务目标判定 |
| 01杰哥智能系统 | 理解、生成、知识、模型能力、草案能力 | 输入理解、证据约束、草案边界、知识感知、模型降级、输出可复核、失败解释分型、事实双账表达、解释反哺、条件与目标解释 |
| 02杰哥扩展系统 | 税收、股票、视频等业务能力，以及企业微信公共通讯适配 | 业务边界、用户可感知入口、子系统协同、真实动作免疫、业务问题回收、局部职责缺口识别、入口复验、子系统经验上报、等价证据提交 |
| 03杰哥进化系统 | 复盘、规则、模板、经验沉淀、能力升级 | 去伪存真、规则升降级、样本归档、复用模板、长期记忆、能力检查、问题分型规则进化、复核入账检查器、教学相长规则化、条件类型升降级 |

## 四、分层落地八问

每个系统或子系统都必须能回答：

1. 我服务哪个上位目标？
2. 我的上级系统是谁，我不能反向覆盖谁？
3. 我的输入、输出、依赖和服务对象是什么？
4. 我怎样感知自身状态和失败？
5. 我怎样守住自己的红线和免疫边界？
6. 我失败时谁被阻断，谁可以继续？
7. 我的经验如何进入规则、模板、样本或归档？
8. 用户最终能看到、查到、用到什么变化？
9. 我的失败属于哪一类：真实稳定退化、局部职责缺口、巡检口径偏差、证据不足，还是红线问题？
10. 我修复后如何证明原失败项已覆盖复验，并且不覆盖原始失败事实？
11. 用户反馈或下级实践是否暴露了我的规则盲点？
12. 我的经验是否已经上升为规则，或上位规则是否已经下沉成我能执行的动作？
13. 当前条件要证明的上位目标是什么？
14. 我能否提交比机械条件更贴近目标的客观证据？

## 五、问题分型与复核入账分层能力

这项能力必须在各层系统中以不同职责落地：

| 层级 | 必须具备的能力 |
|:---|:---|
| 总管系统 | 对失败进行 P1-A/B/C/D 分型，判断同日修复后是否可复核入账，维护样本代表性 |
| 智能系统 | 输出解释时保留“原始事实”和“修复后事实”两层表达，不把结论说死 |
| 扩展系统 | 识别失败是业务能力退化、公共入口分流缺口，还是巡检口径偏差 |
| 进化系统 | 把有效分型、修复复核、样本入账判断沉淀为规则、检查器和后续运行能力 |
| 子系统 | 在自身业务边界内完成失败归因、局部修复、复验回执和经验回流 |

业务子系统回执结构统一参考 `业务子系统问题分型与复核回执模板_v1.0.md/json`，至少包含原始事实、问题分型、根因候选、修复动作、复验证据、样本影响、经验回流和安全边界。

## 六、教学相长分层能力

教学相长在系统分层中表现为“上位规则下沉”和“下位经验上升”。

| 层级 | 必须具备的能力 |
|:---|:---|
| 总管系统 | 把用户反馈、并行窗口发现、子系统回执统一回收，判断是否升级为当前口径、规则或施工任务 |
| 智能系统 | 把解释过程中的用户困惑、反问、纠错沉淀为更清楚的表达、证据引用和事实双账 |
| 扩展系统 | 把业务入口的用户可感知问题上报为局部职责缺口、体验缺口或规则盲点 |
| 进化系统 | 把有效反馈提炼成规则、模板、检查器和能力吸收记录 |
| 子系统 | 既服从上位规则，也能把本层实践中验证有效的方法反哺上级系统 |

## 七、上位目标统摄下位条件分层能力

| 层级 | 必须具备的能力 |
|:---|:---|
| 总管系统 | 判断交付条件服务的上位目标，区分必要条件、默认条件、经验条件和可补强条件 |
| 智能系统 | 向用户解释“为什么需要这个条件”和“这个条件证明什么”，避免机械话术 |
| 扩展系统 | 提交能证明业务稳定、边界稳定、用户可感知稳定的等价客观证据 |
| 进化系统 | 把条件是否合理、是否可替代、是否被实践修正沉淀为规则升降级 |
| 子系统 | 不机械套上级条件，先判断自身证据能证明哪个上位目标，再提交给总管裁决 |

## 八、只读检查要求

后续应通过只读检查器定期检查：

- 四大系统是否具备基础目录和状态证据。
- 各子系统是否有配置、脚本、数据、日志、文档或回执。
- 是否存在边界、红线、只读、暂停、影子、验收、回执等证据。
- 是否能看出问题修复和进化记忆路径。
- 哪些系统只有文件结构，缺少内生能力证据。
- 是否具备问题分型、事实双账、修复复核、样本代表性判断的证据。
- 是否具备用户反馈回收、下级经验上升、上位规则下沉的教学相长证据。
- 是否具备条件服务目标、等价证据补强、严谨不僵化、灵活不降标的证据。

检查结果不得直接宣称正式上线，只能作为能力成熟度和下一步施工依据。

## 九、总则

```text
总系统有总系统的智能，
四大系统有四大系统的智能，
子系统有子系统的智能。

层层具备，层层服从，层层反馈，
杰哥智能系统才不是一个总管带着一堆零件，
而是一个由多层有机系统共同组成的智能体。
```
