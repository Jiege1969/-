# 自然日样本归因式判定规则

> 版本：v1.0  
> 生效日期：2026-05-09  
> 所属系统：03杰哥进化系统 / 规则库  
> 定位：纠正“按时间机械等待”的风险，明确自然日样本不是按钟点自动通过，而是按样本独立性、前置依赖、失败归因、红线和复验证据共同判定。

## 一、根本原则

自然日不是目的，样本代表性才是目的。

系统不得机械理解为“到了明天就通过”，也不得为了加速把同一天多次复跑冒充多个自然日。正确判断是：

```text
样本独立性条件
+ 前置样本证据
+ 当前系统状态
+ 失败归因能力
+ 红线安全边界
+ 复验证据完整性
=> 是否允许进入当日样本采集/入账
```

## 二、日期条件的真实含义

日期条件只代表“自然日独立性”，不是稳定性的充分证明。

| 错误理解 | 正确理解 |
|:---|:---|
| 时间到了就可以入账 | 时间只满足样本独立性的外部条件 |
| 今天不能做任何事，只能等 | 今天可以完成前置依赖、归因闸口、红线和回执一致性检查 |
| 明天开机后自动判定稳定 | 明天仍需通过开机自检、只读总回归、红线扫描、失败分型和样本代表性判断 |
| 未到日期就是机械等待 | 未到日期时应输出“前置归因是否已满足”，不是空等 |

## 三、第三自然日归因式闸口

第三自然日样本采集前，必须先判定：

1. 前两个自然日样本是否真实存在且可追溯。
2. 第二自然日若有同日修复后复核入账，原始失败和复核回执是否同时保留。
3. 当前开机施工准备自检是否通过。
4. 当前日常可用交付版一键只读总回归是否通过。
5. 当前是否存在未回收 P0/P1-A 稳定退化问题。
6. 红线是否全程关闭。
7. 当前日期是否已经满足第三个独立自然日。

其中第 1-6 项今天就可以判定；第 7 项只决定能否入账，不决定系统是否“空等”。

## 四、输出状态

归因式闸口只允许输出以下状态：

| 状态 | 含义 |
|:---|:---|
| `preconditions_ready_waiting_for_independent_natural_day` | 前置归因条件已满足，但自然日独立性尚未到，不能入账 |
| `ready_to_collect_third_day_sample` | 前置归因条件和自然日独立性均满足，可进入第三自然日采集 |
| `blocked_by_cause` | 被明确原因阻断，必须先修复或回收 |
| `needs_evidence` | 证据不足，不能按通过或失败处理 |

## 五、禁止事项

- 不得说“等明天再看”而不说明今天能判断什么、明天要验证什么。
- 不得把自然日条件当作唯一闸口。
- 不得在自然日未到时预生成未来样本。
- 不得在自然日已到后跳过归因、红线和复验。
- 不得把同一天多次运行算成多个自然日。
