# 多对话框并行分工与防遗忘规则 v1.0

## 一、定位

多对话框并行不是简单多开窗口，而是杰哥智能系统应具备的调度和记忆能力。

它的目标是：

1. 提高搭建和核查效率。
2. 分担单一对话的认知负荷。
3. 防止解决问题时忘记总结归纳。
4. 防止总结归纳后忘记落成系统能力。
5. 防止多窗口形成多头口径。

## 二、基本结构

```text
主对话框/总管窗口
-> 统一目标、边界、派工、口径、回收、入库

子对话框/专项窗口
-> 只读核查、专项验证、候选建议、证据回传
```

## 三、建议并行数量

常规并行：主窗口 + 3 个子窗口。

最多并行：主窗口 + 4 个子窗口。

超过 4 个子窗口时，冲突、重复、口径漂移和遗忘风险会明显上升，必须先建立任务队列和回收台账。

## 四、典型分工

| 窗口 | 职责 |
|:---|:---|
| 主窗口 | 总管裁决、面板/接续包、最终入账、冲突处理 |
| A窗口 | 当前问题专项核查与复验 |
| B窗口 | 规则库、能力契约、内生能力落点检查 |
| C窗口 | 面板、接续包、旧口径、旧债扫描 |
| D窗口 | 稳定版/日常版证据链、样本、回归结果核对 |

## 五、子窗口硬边界

子窗口默认只读，不得擅自：

- 修改总管面板。
- 修改一键接续包。
- 修改正式规则库。
- 修改服务脚本。
- 重启服务。
- 触发 n8n。
- 发送企业微信。
- 写正式库。
- 交易、税务办理、视频发布。

如确需修改，必须回传给主窗口，由主窗口统一判断。

## 六、统一回传格式

每个子窗口必须按以下格式回传：

```text
任务编号：
检查范围：
结论：
证据路径：
发现问题：
风险等级：
是否建议修改：
是否涉及红线：
是否需要规则入库：
是否需要同步面板/接续包：
```

## 七、防遗忘闭环

主窗口回收子窗口结果后，必须完成：

1. 去重。
2. 冲突扫描。
3. 事实核验。
4. 进度重算。
5. 规则入库判断。
6. 能力吸收判断。
7. 面板同步。
8. 接续包同步。
9. 下一轮派工或收口。

## 八、系统能力要求

杰哥智能系统以后应能自动识别：

- 什么时候需要并行。
- 哪些任务适合只读并行。
- 哪些任务必须留在总管窗口。
- 哪些结果需要回收成规则。
- 哪些结果只是一次性证据。
- 哪些并行结果互相冲突。

这不是 Codex 的临时工作方法，而是杰哥智能系统的调度、记忆和防遗忘能力。
