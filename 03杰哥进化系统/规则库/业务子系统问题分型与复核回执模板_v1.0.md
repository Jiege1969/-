# 业务子系统问题分型与复核回执模板

> 版本：v1.0  
> 生效日期：2026-05-09  
> 所属系统：03杰哥进化系统 / 规则库  
> 上位规则：`杰哥智能系统内生理念与能力契约_v1.0`、`四大系统与子系统内生能力分层落地规则_v1.0`、`同日修复后复核入账规则_v1.0`  
> 定位：把总管和进化系统的问题分型、事实双账、修复复核、经验回流能力，下沉到股票、税收、视频、企业微信公共接入层等业务子系统。

## 一、通用回执结构

每个业务子系统遇到失败、用户反馈、巡检异常或修复动作时，至少按以下结构提交回执：

| 字段 | 要求 |
|:---|:---|
| 子系统 | 股票、税收、视频、企业微信公共接入层、知识库、内容处理等 |
| 原始事实 | 失败发生时间、入口、输入、输出、失败项、原始回执路径 |
| 问题分型 | P1-A真实稳定退化、P1-B局部职责/路由缺口、P1-C巡检口径偏差、P1-D证据不足、P0红线问题 |
| 根因候选 | 当前可证据支持的原因，不得把猜测写成结论 |
| 修复动作 | 是否修改脚本、配置、规则、模板、巡检口径；是否重启服务 |
| 复验证据 | 原失败项是否覆盖复验、总回归是否通过、红线是否复扫 |
| 样本影响 | 入账、不入账、候选、需升级、与样本无关 |
| 经验回流 | 是否进入规则库、模板、检查器、面板、接续包或子系统能力 |
| 安全边界 | 是否触发 n8n、发送企业微信、写正式库、交易、办税、渲染发布、重启正式服务 |

## 二、股票研究系统模板

股票系统失败时，必须先区分：

| 类型 | 判断要点 | 默认边界 |
|:---|:---|:---|
| 行情/数据源问题 | 行情不可读、字段缺失、时间戳异常、样本不足 | 不接券商、不交易、不输出买卖建议 |
| 研究逻辑问题 | 指标计算、报告结构、证据链、风险提示不完整 | 只生成研究草案或只读报告 |
| 入口分流问题 | 企业微信、总管、股票桥接入口未正确路由 | 只修职责分流，不请求交易接口 |
| 展示/用户可感知问题 | 图文、短回复、摘要不清晰或误导 | 优先修输出模板和解释 |
| 巡检口径问题 | 检查器期待与当前安全边界不一致 | 只校准只读检查，不掩盖真实失败 |

## 三、税收业务系统模板

税收系统失败时，必须先区分：

| 类型 | 判断要点 | 默认边界 |
|:---|:---|:---|
| 证据不足 | 税种、期间、地区、主体、问题背景缺失 | 不生成正式税务意见 |
| 政策口径问题 | 上位法规、地方口径、基层流程冲突 | 标注依据层级和待复核 |
| 暂停边界问题 | 税收系统处于暂停态，但巡检仍期待业务草案 | 校准巡检口径，保留暂停免疫 |
| 办理红线问题 | 登录、申报、退税、开票、写正式库等动作 | 必须阻断并升级 |
| 用户可感知问题 | 草案解释不清、风险提示不足 | 只修表达和证据链 |

## 四、视频制作系统模板

视频系统失败时，必须先区分：

| 类型 | 判断要点 | 默认边界 |
|:---|:---|:---|
| 创意/脚本问题 | 主题、受众、平台、风格、分镜不清 | 只输出草案，不生成真实资产 |
| 素材问题 | 素材缺失、授权不明、格式不匹配 | 不读取真实未授权素材 |
| 任务链路问题 | 会话ID、任务ID、状态契约不一致 | 修任务契约和回执 |
| 生成/渲染门禁问题 | 引擎调用、转码、配音、封面、字幕 | 未放行前全部阻断 |
| 发布红线问题 | 上传、发布、对外分发 | 必须阻断并升级 |

## 五、企业微信公共接入层模板

企业微信公共接入层失败时，必须先区分：

| 类型 | 判断要点 | 默认边界 |
|:---|:---|:---|
| 公共通讯适配问题 | 回调、入口、URL、健康检查、加解密、格式适配 | 不接管业务判断 |
| 职责分流问题 | 系统管家、工作秘书、视频助理、股票入口转交错误 | 可做局部路由修复和同日复验 |
| 安全闸门问题 | real_send、n8n、正式库、外发状态不一致 | 红线优先，必要时阻断 |
| 巡检口径问题 | 巡检期望与当前暂停/只读/影子边界不一致 | 校准检查器，不掩盖真实路由缺口 |
| 旧06兼容问题 | 旧目录被误当成独立业务系统 | 回归公共组件权威路径 |

## 六、总管回收要求

子系统回执不得直接决定正式入账或正式交付。总管系统必须统一回收：

1. 原始事实是否保留。
2. 问题分型是否有证据。
3. 修复是否覆盖原失败项。
4. 红线是否全程关闭。
5. 样本代表性是否仍成立。
6. 经验是否已回流到规则、模板、检查器、面板或接续包。

## 七、禁止事项

- 不得用子系统局部成功直接宣告总系统稳定。
- 不得用修复后成功覆盖原始失败事实。
- 不得把红线关闭误判为能力不足。
- 不得把巡检口径偏差包装成真实系统退化。
- 不得把真实业务退化掩盖成口径问题。
- 不得把用户反馈留在对话里不入库。
