# 依据层级与冲突处理规则

> 版本：v1.0  
> 生效日期：2026-05-07  
> 所属层级：03进化系统 / 规则库  
> 适用范围：全智能体系，包括搭建工作、运行运转机制、各系统内部机制、系统间协作机制、业务输出和进化沉淀  
> 核心原则：上位依据优先，下位流程只能细化执行，不能反向覆盖。

---

## 一、为什么建立本规则

本系统处理的不是单纯文本，也不只是单个业务问题，而是一个由总管、智能、扩展、进化共同组成的运行体系。体系中的每一项规则、流程、脚本、工作流、业务口径和人工经验，都带有来源、层级、适用范围和执行场景。若不明确依据层级，系统可能把基层流程、单位制度、临时脚本或经验口径误当成上位规则，造成推理倒挂和运行越权。

因此，所有搭建、运行、业务草案、资料入库、系统协作和进化沉淀，必须先判断依据层级，再判断内容适用性和执行权限。

---

## 二、通用依据层级

```text
宪法/根本原则
> 法律
> 行政法规
> 部门规章、规范性文件、主管机关政策
> 地方口径、单位/企业制度
> 职能科室工作流程、操作SOP、人工经验
```

用户口径中的主链必须保留：

```text
宪法 > 法律 > 部门规章制度 > 单位企业制度 > 职能科室工作流程
```

在税收、行政管理等场景中，系统应补充识别“行政法规”这一中间层，但不得削弱用户主链的核心逻辑。

---

## 二点五、系统治理层级

我们总结出的所有理念、方法、规则、脚本、流程、样例和经验，也不是平级关系。它们同样存在先后顺序、服从和被服从关系。

```text
系统总目标/根本原则
> 全体系底层逻辑
> 总管运行规则
> 进化系统规则
> 业务系统母本与通用模板
> 具体业务线方案
> 脚本、工作流、计划任务
> 操作记录、案例、人工经验
```

执行含义：

- 下一级必须服从上一级。
- 具体脚本不得反向修改或绕过总管规则。
- 业务样例不得反向定义系统目标。
- 人工经验不得直接覆盖正式规则，只能进入进化样本或规则建议。
- 临时施工便利不得覆盖长期底层逻辑。
- 如果下级产物与上级原则冲突，优先修正或停用下级产物，而不是迁就错误产物。

这条规则用于防止“总结越多越平铺”，也防止某个局部机制长成新的主线。

## 二点六、根本法则到基层流程

系统治理层级可以类比为：

```text
宪法级根本法则
> 法律级总规则
> 部门制度级分工规则
> 下级规章级执行规则
> 基层工作流程
> 单次操作动作
```

在杰哥智能系统中，对应为：

```text
系统总目标与底层逻辑
> 总管系统规则
> 进化系统规则
> 智能系统/扩展系统通用机制
> 税收、股票、视频、企业微信等业务线方案
> 脚本、接口、工作流、计划任务
> 命令、函数、代码片段、字段
```

执行含义：

- 越上位，越负责方向、边界、价值和根本稳定。
- 越下位，越负责执行、细化、证据和局部效率。
- 下位动作可以暴露上位规则的缺口，但不能直接覆盖上位规则。
- 上位规则必须能指导下位动作，不能只停留在口号。
- 当基层流程、脚本或代码与系统总目标冲突时，优先校准基层流程、脚本或代码。
- 当多个下位动作都反复出现同类问题时，再反向复盘上位规则是否需要补强。

## 三、冲突处理

| 情形 | 处理规则 |
|:---|:---|
| 下位依据与上位依据冲突 | 以上位依据为候选判断基础，下位依据转为风险提示或待核实事项 |
| 单位制度与法律/规章冲突 | 不得按单位制度输出确定结论，只能提示“存在制度与上位依据冲突” |
| 职能科室流程与单位制度冲突 | 以单位制度为准，科室流程仅作执行路径参考 |
| 地方口径与国家级政策存在差异 | 国家级政策兜底，地方口径标为地区适用和待复核 |
| 人工经验与正式依据冲突 | 人工经验不得作为正式依据，只可进入进化样本或风险提示 |
| 上位依据不完整、下位流程明确 | 可以输出待复核草案，但必须标明依据缺口和核实建议 |

---

## 四、输出要求

任何业务草案涉及依据时，至少说明：

1. 当前采用的最高层级依据是什么。
2. 是否存在下位制度、流程或经验口径。
3. 下位依据是否只是执行细化，还是可能与上位依据冲突。
4. 若冲突，系统不得强行下结论，必须列为待复核事项。

---

## 五、资料入库字段要求

资料库或影子知识库登记任何依据时，应至少记录：

| 字段 | 含义 |
|:---|:---|
| hierarchy_rank | 依据层级排序 |
| legal_level | 依据类型 |
| source_scope | 国家级/地方/单位/科室/个人经验 |
| conflict_with_higher_level | 是否可能与上位依据冲突 |
| conflict_note | 冲突说明 |
| usable_as_basis | 是否可作为候选依据 |
| usable_as_process_reference | 是否仅作为流程参考 |

## 六、对各系统的应用

| 系统 | 应用方式 |
|:---|:---|
| 搭建工作 | 施工脚本、临时方案、并行窗口不得绕过总纲、安全边界和当前主线规划 |
| 运行运转机制 | 计划任务、服务状态、n8n工作流、总管调度不得用局部便利覆盖上位规则 |
| 系统间协作 | 子系统只在自己的职责边界内细化执行，不得反向改写总管边界或进化规则 |
| 税收系统 | 国家级法律政策优先，地方口径和基层流程后补，不阻塞国家级资料库建设 |
| 股票系统 | 交易规则、监管规则优先，个人经验和策略只能作分析参考 |
| 内容系统 | 法律法规、平台规则、授权协议优先，个人风格偏好后置 |
| 视频系统 | 版权授权、平台规则优先，制作流程和创意偏好后置 |
| 本职工作系统 | 上级制度和单位制度优先，科室流程作执行参考 |
| 总管系统 | 分流时先判断是否存在上位依据冲突，冲突项不得自动执行 |
| 进化系统 | 人工修正不得直接覆盖上位依据，只能形成规则建议或案例样本 |

---

## 七、总则

```text
先判层级，再判适用；先用上位依据兜底，再用下位流程细化；冲突不硬判，缺口标待复核。
```
