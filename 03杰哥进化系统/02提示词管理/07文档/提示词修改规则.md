# 提示词修改规则

时间：2026-05-06 07:28:00 +08:00

提示词是软代码。任何提示词修改都必须保留上一个版本，并写清楚为什么改、预期效果是什么、如何回滚。

## 规则

- 修改运行配置前，先在版本库生成新版本副本。
- 变更日志必须记录：改动内容、原因、预期效果、回滚版本。
- 上一个版本不得覆盖。
- 如果新提示词输出明显变差，直接回滚到上一个版本。
- n8n prompt 节点、总管消息模板、业务提示词也适用本规则。
- 已证实无当前依赖的旧提示词、旧接入口径、空壳候选，不登记为长期观察债；当轮删除或从索引移除。
- 修改失败时，先回滚到上一版本，再把失败原因沉淀为规则或验收项，不保留“以后再看”的悬空债。
