# 方向校准规则

> 版本：v1.0  
> 生效日期：2026-05-07  
> 定位：防止顺手清理、治理膨胀和扩展系统无序开工

## 1. 校准记录格式

每次触发高风险动作前，写入一行：

```text
方向校准：服务主线=是/否；增强能力=是/否；临时清理冲动=是/否；结论=执行/入待清队列/暂停讨论
```

## 2. 触发条件

以下动作必须触发方向校准：

- 删除、移动、覆盖、迁移。
- 修改源头脚本、计划任务、服务状态、自动化链路。
- 写正式库、外发、真实业务动作。
- 清理旧债或处理待清队列。
- 扩展系统从影子样例进入正式搭建。

## 3. 不触发条件

以下动作不触发清理三问，但仍需说明目的：

- R0只读调研。
- 普通文档补充。
- 理念资产回收。
- 接续包更新。
- 安全边界同步。

## 4. 跳过上限

连续5次方向校准均为：

```text
服务主线=是；增强能力=是；临时清理冲动=否；结论=执行
```

第6次必须暂停，由用户确认：

```text
继续自动通过 / 恢复逐次三问
```

## 5. 待清队列上限

待清队列最多20条。达到20条后，新发现清理项不得继续入队，必须安排清债轮次至少处理10条后，才能继续接收新条目。

## 6. 治理不得自我繁殖

新规则、新台账、新验收、新许可工具，必须回答：

> 它让系统更会做什么？

如果答案只是“更会证明自己安全”，暂停。
