# 第一批股票与企微资产吸收结论

生成时间: 2026-04-28
标识: first-batch-stock-wecom-asset-assimilation-summary

## 一、结论先行

F盘 `老系统可复用资产_20260426` 中的 `03_股票分析资产` 和 `05_企业微信与通讯接入` 具备直接吸收价值，且与当前新股票系统交付目标高度一致。

本轮只读审阅得出结论：旧系统的正确经验不是照搬脚本，而是吸收三条底层逻辑：

1. n8n 容器遇到外部行情接口限制时，可由宿主机本地服务做受控中转。
2. 股票查询链路要分成识别、查询、分析、回复、记录五段，方便定位故障。
3. 企业微信入口必须只做消息入口和出口，业务判断应下沉到股票助手与 n8n。

## 二、已确认可吸收逻辑

### 1. 股票数据源中转逻辑

旧系统资产中存在 `stock_api.py` 和 `stock_http_server.py`，其核心经验是：当 n8n 容器直接访问行情接口受限时，由宿主机本地服务监听 `127.0.0.1`，接收 n8n 请求后再访问公开行情接口。

新系统吸收方式:

- 不照搬旧端口和旧路径。
- 纳入新股票系统数据源降级策略。
- 作为“本机行情中转候选方案”，只在公开数据源直接访问不稳定时启用。
- 启用前必须通过只读探测、白名单URL登记、受控执行申请。

### 2. 股票查询分段逻辑

旧系统资产中存在股票机器人、股票脚本待分析模块，按功能可拆成:

- 感知: 识别用户输入中的股票名称或代码。
- 决策: 按规则和指标给出分析判断。
- 行动: 生成回复、触发下游流程。
- 记忆: 保存查询、判断、反馈和复盘。
- 通知: 面向企业微信返回结果。
- 每日简报: 盘后或定时输出摘要。

新系统已吸收情况:

- `/识别`、`/recognize` 已补入股票助手。
- `/技术分析`、`/technical` 已补入股票助手。
- 单股分析、技术指标、L5深度研究、复盘账本已存在。
- 每日包、状态摘要、候选池和数据健康度已存在。

继续吸收动作:

- 把“感知-决策-行动-记忆-通知-每日简报”作为新股票系统模块说明写入交付材料。
- 对照旧 `每日简报.py`，检查新 `股票日常使用包` 是否覆盖盘后摘要体验。
- 对照旧 `通知模块.py`，检查新统一消息出口是否覆盖格式、失败重试、短回复。

### 3. 企业微信通讯链路逻辑

旧系统资产中存在企业微信命令响应、企微主流程、大龙虾n8n联动方案、通讯工作流等资料。

新系统吸收方式:

- 企业微信只作为输入输出终端。
- OpenClaw 只做边缘消息代理。
- n8n 只做编排。
- 股票助手只做业务分析。
- 统一消息出口只做受控发送。

当前新系统已具备:

- n8n Webhook 本机灰度联通。
- 企业微信消息契约。
- 统一消息出口禁用态。
- 企业微信受控发送闸口。
- 真实灰度白名单测试申请与回滚材料。

## 三、敏感资料隔离边界

F盘 `05_企业微信与通讯接入`、`06_配置与密钥线索`、`04_n8n工作流与备份` 中存在凭据线索。后续处理规则:

1. 只登记资产位置、用途、风险等级。
2. 不把密钥、token、secret、webhook key 明文复制到新系统文档。
3. 不在工作日志中记录密钥值。
4. 不直接导入旧 n8n 数据库或工作流并激活。
5. 如需迁移凭据，必须另建“凭据轮换与重配申请”，优先重新生成新凭据。

## 四、对股票系统交付的直接影响

本轮吸收后，股票系统的“旧经验利用”不再停留于概念，已进入交付路径:

- 旧系统股票识别与技术分析接口经验已转化为新接口。
- 旧系统宿主机中转经验已进入新系统数据源降级候选。
- 旧系统企业微信链路经验已转化为 OpenClaw + n8n + 股票助手 + 统一消息出口的分层架构。
- 旧系统记忆与复盘经验已转化为系统判断账、人工决策账、结果验证账、经验提炼账。
