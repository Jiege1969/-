# 系统组成与依赖关系图谱

生成时间：2026-05-05 22:12

## 1. 系统总定位

`D:\杰哥智能化系统` 是本机私有化智能中台。它不是单个软件，而是一套由总管、智能底座、扩展业务、进化沉淀四大系统组成的本地运行体系。

核心作用：

- 通过企业微信与用户交互。
- 用本地模型、规则、脚本和数据处理能力完成股票分析、文稿处理、知识库问答、视频辅助等任务。
- 通过总管系统做启动、自检、进度、审计、回滚、清理和安全边界控制。
- 通过进化系统把经验、规则、问题复盘沉淀下来。

## 2. 四大主系统

| 主系统 | 路径 | 作用 | 当前状态 |
|---|---|---|---|
| 00总管系统 | `00杰哥系统总管` | 管全局状态、计划、启动、自检、验收、回滚、清理、口径统一 | 已运行并进入维护态 |
| 01智能系统 | `01杰哥智能系统` | 提供模型、Redis、n8n、智能体大脑、任务契约底座 | 核心底座运行中 |
| 02扩展系统 | `02杰哥扩展系统` | 承载具体业务：股票、视频、内容、税收、知识库等；企业微信作为公共通讯适配与安全闸门接入 | 股票成熟，其他多为影子/门禁态 |
| 03进化系统 | `03杰哥进化系统` | 负责经验卡片、提示词、模型评测、系统复盘和规则沉淀 | 规则沉淀可用，自动进化仍受控 |

## 4. 01智能系统组成

| 子系统 | 作用 | 端口/依赖 |
|---|---|---|
| Ollama模型服务 | 本地大模型和嵌入模型运行 | Docker `jiege_v3_ollama`，`29134->11434` |
| Redis | 轻量任务契约、缓存、未来队列基础 | Docker `jiege_v3_redis`，`26379->6379` |
| n8n | 可视化流程编排，当前以干跑和门禁为主 | Docker `jiege_v3_n8n`，`28679->5678` |
| v3智能体大脑 | 测试态智能体服务 | `127.0.0.1:28100` |
| 本机工具运行时 | Git、Python/工具软件等依赖 | `03数据\本机工具运行时` |

当前原则：智能系统提供底座，不抢总管职责；n8n 不做总脑；Redis 不接管正式主链；模型按需使用，避免资源失控。

股票关键入口：

- `19300`：股票助手本地服务。
- `19302`：股票企业微信桥接入口，也承接公网回调转发。
- 公网反向隧道：`43.167.210.211:80 -> 云端127.0.0.1:18080 -> 本机127.0.0.1:19302`。

企业微信关键入口（公共通讯适配层口径）：

- `/wecom/system-manager` -> 本机 `19310/wecom/system-manager`。
- `/wecom/work-secretary` -> 本机 `19310/wecom/work-secretary`。
- `/wecom/video-assistant` -> 本机 `19310/wecom/video-assistant`。
- `/wecom-bot/message` -> 股票桥接。

当前企业微信统一采用公网 URL 回调，不再采用长连接。架构权威口径为 `00公共组件\企业微信接入设置` 公共通讯适配层；旧 `06企业微信助手系统` 不再作为独立业务系统扩张，只保留兼容运行和历史证据追溯。

## 9. 关键依赖链路

### 开机链路

`Windows计划任务 -> wscript隐藏包装 -> PowerShell入口 -> Python/Docker服务 -> 开机自检 -> 右下角提示`

### 企业微信链路

`手机企业微信 -> 企业微信平台 -> 公网URL -> 云端Nginx -> 云端127.0.0.1:18080 SSH反向隧道 -> 本机127.0.0.1:19302 -> 19310或19300 -> 加密回复 -> 手机`

### 股票分析链路

`企业微信/本地请求 -> 19302桥接 -> 19300股票助手 -> 行情/历史K线/关注池/报告模板 -> 短回复或图文报告`

### 智能底座链路

`业务脚本 -> 任务契约/总管准入 -> Ollama/Redis/n8n/智能体大脑 -> 验收/日志/报告`

### 进化沉淀链路

`故障或施工记录 -> 运行状态报告 -> 经验提炼 -> 规则/提示词/复盘 -> 总管读取`

## 10. 当前设计边界

- 股票系统只分析，不交易。
- n8n 不自动执行正式业务。
- Redis 不接管正式主链。
- 企业微信真实发送和公网入口受控。
- 视频、内容、税收等真实动作仍需许可令和人工闸门。
- 旧 `jiege_*` Docker 容器为退出态历史残留，不自动启动、不直接删除数据。

## 11. 运维判断顺序

如果系统异常，按顺序看：

1. 计划任务是否存在且隐藏启动。
2. 端口是否监听：`19300/19302/19310/28100/26379/28679/29134`。
3. Docker 三件套是否运行：Ollama、Redis、n8n。
4. 公网反向隧道是否存在：云端 `127.0.0.1:18080` 是否监听；这不是本机旧 `18080`。
5. 企业微信后台 URL/Token/AESKey 是否仍对应当前配置。
6. 最近日志是否有 403、502、timeout、websocket mode not enabled。
