## 二、开机自检当前检查什么

| 类别 | 检查内容 |
|:---|:---|
| 机器资源 | CPU、内存、D盘空间、GPU、Docker 可用性 |
| 基础容器 | Ollama、Redis、n8n 容器是否运行 |
| 基础端口 | n8n `28679`、股票本地入口 `19300`、股票企微入口 `19302`、企业微信统一入口 `19310`、智能体大脑测试入口 `28100` |
| 基础服务 | Ollama API 是否可用、Redis ping 是否返回 |
| 总管施工上下文 | 注释检查、股票状态摘要、当前进度报告、只读状态检查 |
| 安全边界 | 不删除、不覆盖旧系统、不重启正式服务、不触发 n8n、不发送企业微信、不写正式库、不接券商、不交易 |

## 三、它目前不等于什么

开机自检通过，不等于：

- 税收业务已经正式可办税。
- 股票系统可以交易。
- 视频系统可以真实渲染、上传、发布。
- 企业微信可以真实外发。
- n8n 可以正式触发。
- 正式稳定交付版已经三日达标。
- 完全交付使用版或真正自主运行版已经完成。

## 四、正式稳定版应该怎么检查

正式稳定版应分四层检查：

| 层级 | 作用 | 当前状态 |
|:---|:---|:---|
| L1 开机自检 | 判断机器、容器、端口、基础链路是否可用 | 已有 |
| L2 日常只读总回归 | 判断关键模块只读检查是否全部通过 | 已有命令清单 |
| L3 自然日样本 | 判断不同自然日运行是否连续稳定 | 已有第 1 日，仍缺第 2/3 日 |
| L4 三日达标复核 | 样本齐备后生成正式稳定交付达标建议 | 已有模板，待样本齐备 |

## 五、当前建议

1. 保留现有开机自检作为“系统是否醒来”的第一道门。
2. 明天 2026-05-09 开机后，先看开机自检是否通过，再执行第二自然日只读样本。
3. 后天 2026-05-10 开机后，先看开机自检是否通过，再执行第三自然日只读样本。
4. 后续应把开机自检结果纳入自然日样本字段，做到“系统从启动到只读回归都可追溯”。
