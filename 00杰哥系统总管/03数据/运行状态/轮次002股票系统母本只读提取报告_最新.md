## 二、并行核实结果

### 骨架核实

股票系统目录为完整业务线骨架：

- `01配置`：120 个配置文件。
- `02脚本`：487 个脚本文件。
- `03数据`：252 个子目录，1638 个文件。
- `04日志`：173 个子目录，268 个文件。
- `05入口工具`：49 个人工入口。
- `07文档`：29 个文档。
- `09归档`：归档目录。

提取结论：新业务线应继承“配置、脚本、数据、日志、入口、文档、归档”的骨架，不继承股票当前编号细节和历史平铺债。

### 血脉核实

当前通用底座：

- `jiege_v3_ollama`：`127.0.0.1:29134`，本地模型底座。
- `jiege_v3_redis`：`127.0.0.1:26379`，Redis/任务契约底座。
- `jiege_v3_n8n`：`127.0.0.1:28679`，工作流底座，当前 5 个母样本均 inactive。

股票专有入口：

- `19300`：股票助手入口。
- `19302`：股票企业微信桥接入口。

提取结论：端口、容器、模型、Redis、n8n、企业微信桥接必须登记；n8n 和 Redis 不得被默认解释为正式主链已接管。

### 规则与安全核实

股票系统成熟安全做法：

- 硬闸门配置明确只分析不交易。
- 交易、券商、下单、仓位、目标价等意图被拦截。
- 企业微信真实发送与 n8n 启用均有人工确认和灰度许可。
- `response_url` 只记录指纹，不保存明文。
- C+++日常可用验收 81/81 通过，但真实主动消息仍按可信 IP 边界单独判断。

提取结论：新业务线必须有自己的“禁止动作”和“高风险意图拦截词表”，不能直接复用股票交易词表。

### 证据与资产核实

股票系统已形成：

- 当前状态锚点：状态摘要、日常使用包、交付总包、模型健康、质量面板等 `_最新` 文件。
- 账本：复盘闭环四本账、判断复盘账。
- 审计/回滚证据：真实灰度、交付验收、可信 IP、n8n未激活导入、人工确认回执。
- 可再生报告：大量生成型报告和预演包。
- 过程流水：日志目录中部分运行/验证过程记录。

提取结论：新业务线开工必须先定义资产身份，不能把所有输出都时间戳保存，也不能全部只写最新。

## 五、轮次002结论

股票系统可以作为成熟结构样本，但不能作为机械复制对象。

可复制的是：

- 标准业务线骨架。
- 只读预检。
- 人工闸口。
- 最新锚点。
- 安全硬闸门。
- 服务血脉登记。
- n8n禁用态母样本。
- 数据源注册表。
- 模型路由。
- 复盘闭环。
- 证据链资产身份。
- 交付验收分层。

不可直接复制的是：

- 股票行情高频逻辑。
- L5/L6/L7/L8股票分层。
- 股票交易意图词表。
- 企业微信股票问答格式。
- 股票真实灰度可信 IP 流程。
- 股票C+++交付硬判。
