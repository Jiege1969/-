# 公网反向隧道守护收口

记录时间：2026-05-06 05:46:00 +08:00

## 一、本次目标

落实第二轮并行核实的 P0 项：股票企业微信公网回调依赖 SSH 反向隧道，原来只有登录启动，没有持续守护；断线后不会自动拉起。

本次目标是建立“非业务 probe + 受控 repair”守护，不触发企业微信业务路径，不触发 n8n，不重启业务服务。

## 二、新增脚本

| 脚本 | 作用 |
|---|---|
| `D:\杰哥智能化系统\00杰哥系统总管\02脚本\探测股票公网反向隧道.ps1` | 只读探测本机 `19302/health`、SSH 隧道进程、到云端 `43.167.210.211:22` 的 TCP 连接、PID 记录和 stderr 断线提示。 |

## 三、计划任务

已注册计划任务：

- 名称：`杰哥智能化系统_公网反向隧道守护`
- 触发：登录时 + 每 3 分钟重复
- 动作：`wscript.exe "D:\杰哥智能化系统\00杰哥系统总管\02脚本\隐藏启动公网反向隧道守护.vbs"`
- 多实例策略：`IgnoreNew`
- 网络条件：`RunOnlyIfNetworkAvailable`
- 启动方式：隐藏后台

## 四、已处理的问题

1. 新增脚本初始为无 BOM UTF-8，Windows PowerShell `-File` 会误读中文路径/中文脚本，已转换为 UTF-8 BOM。
2. 首次 repair 时发现守护脚本等待原启动器返回会卡住；已改成异步启动 + 30 秒上限 + 二次 probe。
3. VBScript 直接调用中文脚本名时不稳定；已新增 ASCII 包装脚本 `guard_stock_public_tunnel.ps1`，VBS 只调用 ASCII 文件名。
4. VBS 初始为等待模式，计划任务显示运行中；已改成非等待模式，计划任务可正常返回。

## 六、安全边界

本轮做了 SSH 隧道受控拉起和守护任务注册，但没有触发业务动作：

- 未 POST 企业微信业务路径。
- 未触发 n8n。
- 未发送企业微信真实消息。
- 未重启 `19300/19302/19310/28100/28679/29134`。
- 未调用券商接口。
- 未开启或恢复自动交易。
