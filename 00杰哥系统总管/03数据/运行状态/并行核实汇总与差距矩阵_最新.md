## 5. C 基因核实

### 5.1 当前能力

- Windows 11 专业版。
- AMD Ryzen 7 7800X3D，8核16线程。
- 64GB 内存。
- RTX 3090，24GB 显存。
- Docker Desktop 4.68.0，Engine 29.3.1。
- WSL2 2.6.3.0，`docker-desktop` 和 `Ubuntu-24.04` 运行中。
- Python 3.14.4。
- Node 25.9.0，npm 11.12.1。
- Ollama `0.20.5`、Redis `7.2.5-alpine`、n8n `1.123.30`。

### 5.2 能力上限判断

这是一台很强的单卡本地 AI 工作站，不是多用户高并发服务器。RTX 3090 24GB 适合 7B/8B 稳定运行，14B 量化较舒服，30B 级别要看量化、上下文和并发，容易进入显存边缘。

### 5.3 主要风险

- D盘承载 Ollama 约 134GB、WSL2 约 189GB、Docker 本地卷约 71GB，继续增长会形成压力。
- Docker 本地卷 `71.47GB` 且 active=0，存在历史资产/漂移风险。
- 旧 `jiege_*` 容器多处于 `Exited (137)`，提示历史运行治理需要收口。
- 容器缺少 per-container CPU/内存限制。
- Python 3.14.4 和 Node 25.9.0 都偏新，第三方库兼容性需要锁定。
- 宿主机 Ollama CLI 不在 PATH，但实际由容器承载，需要明确唯一入口。

### 5.4 基因施工优先级

1. 建资源调度规则：股票时段、办公、视频重任务、日常使用分档。
2. 建 D盘增长监控：WSL2、Ollama、Docker 卷、日志和备份分别监控。
3. 建旧 Docker 卷/旧容器归属审计，不先删。
4. 建 Python/Node/容器版本锁定和升级窗口。
