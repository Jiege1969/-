# 日常运行观察台账模板

> 日期：2026-05-09  
> 所属：00杰哥系统总管 / 稳定版正式收口  
> 定位：稳定版达成后的日常运行观察记录模板。

## 一、记录原则

每次开机、接续、重大修复或业务线试用后，优先记录事实，再做归因，不用主观感觉代替证据。

## 二、台账字段

| 字段 | 填写要求 |
| --- | --- |
| 观察编号 | 例如 OBS-20260509-001 |
| 观察时间 | 使用真实本地时间，必要时补可信外部时间 |
| 触发原因 | 开机、接续、修复复验、用户业务请求、异常回收等 |
| 上位目标 | 本次观察服务哪个目标：稳定运行、日常交付、业务影子、规则进化 |
| 红线状态 | n8n、企业微信真实发送、正式库、券商、交易、税务办理、视频发布 |
| 依赖链状态 | 机器资源、Docker/WSL、容器、端口、API、业务入口 |
| 日常总回归 | pass/blocked/skip，并写明失败来源 |
| 问题分型 | 无问题、轻量问题、标准问题、宪法级问题 |
| 根因判断 | 现象、本质、规律、机制缺口 |
| 处理动作 | 修复、跳过、观察、升级、补规则、补检查器 |
| 复验结果 | 复验命令、结果、证据路径 |
| 是否入账 | 入账、未入账、同日修复后入账、仅作历史事实 |
| 经验回流 | 是否需要进入规则库、模板、检查器或接续包 |
| 用户可感知结论 | 用一句话说明用户现在能怎么用、不能怎么用 |

## 三、轻量记录模板

```text
观察编号：
观察时间：
触发原因：
上位目标：
红线状态：
依赖链状态：
日常总回归：
问题分型：
根因判断：
处理动作：
复验结果：
是否入账：
经验回流：
用户可感知结论：
```

## 四、禁止事项

- 不用“等到某天”替代稳定判断。
- 不用“失败数大于0”替代问题分型。
- 不用“写了规则”替代修复复验。
- 不用“并行很多窗口”替代总管裁决。
- 不修改系统时间制造自然日证据。
