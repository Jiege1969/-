# 杰哥智能化系统总体设计纲领与施工计划v3.1

生成日期：2026-04-30

## 一、当前结论

【杰哥智能化系统】仍沿用“四大系统”总体架构：00杰哥系统总管、01杰哥智能系统、02杰哥扩展系统、03杰哥进化系统。

本次v3.1不是推翻原设计，而是根据实际施工结果做阶段性校准：旧系统经验已经吸收并退役大部分D盘旧目录；股票研究系统先行交付使用；2000只标准大股票池从“远期设想”校正为股票研究系统的标准建设目标；税收业务恢复纳入整体搭建计划，但定位为问题驱动官方取证、证据台账、答案草案和人工复核系统，不恢复为自动税务结论系统；所有真实发送、n8n启用、正式写库、交易接口继续受闸口控制。

## 二、核心原则

1. 稳定优先：先形成可运行、可验收、可回滚的最小闭环，再扩展功能。
2. 复用优先：优先吸收旧系统可用逻辑、脚本经验和通讯方法，避免重造轮子。
3. 简单适用：不为完美而补丁堆叠，先找到问题根因，再决定是否新增规则或脚本。
4. 数据分层：轻扫描、候选筛选、深度分析、推送前候选、复盘验证分层处理。
5. 高风险闸口：删除、覆盖、重启正式服务、真实发送、写正式库、交易接口必须停下说明原因。
6. 经验能力化：经验教训不是只写文字，要进入脚本、规则、验收、开工提醒和进化系统。
7. 实践闭环：以真实业务系统为试验场，通过真实问题暴露系统家底，再把修复沉淀为规则、脚本、验收和经验。
8. 以点带面：先让一只股票、一个股票池、一个股票系统跑通，再推广到扩展系统和整体系统，不提前大而全铺开。
9. 方向校准：埋头拉车，也要抬头看路；解决具体问题时必须回看总目标、四系统分工、安全边界和闭环路线。
10. 脚本可治理：所有新建或改造的自有脚本、维护工具、验收脚本、工作流辅助脚本，必须在文件头部写明标准标头字段：名称、作用、触发方式、依赖、所属系统、输出、安全边界、标识；无标头脚本不得进入主线验收。

## 三、四大系统定位

### 00杰哥系统总管

定位：全局调度、目录治理、进度口径、验收汇总、开工上下文、备份退役和风险闸口。

当前重点：
- 维护总纲和分纲。
- 输出统一进度口径。
- 管理开工上下文提醒。
- 汇总四大系统和子系统状态。

### 01杰哥智能系统

定位：基础能力底座，包括Ollama、模型资源池、n8n、Redis、知识库、智能体大脑测试服务和基础执行器。

当前重点：
- 继续保证模型调用、知识库、n8n隔离导入件和本地执行器稳定。
- 不盲目扩大服务数量，优先保障资源占用和稳定性。
- 为02扩展系统和03进化系统提供统一基础能力。

### 02杰哥扩展系统

定位：对外业务能力和实际使用场景，包含股票研究、视频制作、本职工作、内容处理、税收业务、企业微信助手。

当前重点：
- 股票研究系统优先交付并持续增强。
- 企业微信助手作为外部输入输出终端，逐步统一消息出口。
- 视频制作、本职工作、内容处理、税收业务等其他扩展系统暂停推进，除非用户明确恢复。
- 税收业务历史上曾纳入低风险第二主线，但当前已按用户最新指令暂停，不再占用施工资源；真实抓取、正式入库、正式结论、外部提问、n8n触发和企业微信发送继续关闭。

### 03杰哥进化系统

定位：对内复盘、经验提炼、模型评测、提示词管理、问题卡片和系统自我升级。

当前重点：
- 把施工中的成功经验、失败教训、问题根因和解决逻辑沉淀为可复用能力。
- 建立样本清理标准：不是按时间清理，而是按是否已经提炼出有价值规律清理。
- 支撑股票研究系统形成“分析-观察-验证-提炼-再分析”的循环。

## 六、禁止误区

1. 不把文档数量当进度。
2. 不把脚本堆叠当智能。
3. 不把轻扫描候选当买卖建议。
4. 不把公网偶发502当结构性故障。
5. 不把旧系统经验停留在“看过”，必须转化为新系统能力。
6. 不因为局部功能可用就忽视总纲和闭环。
7. 不把无说明、无边界、无触发来源的脚本直接纳入主线；脚本没有标头，就等于后续系统无法判断它该不该运行、何时运行、能不能回滚。

## 八、2026-05-02 务实闭环原则补充

当前系统搭建进入新的阶段性认识：股票系统不是孤立业务工具，而是检验【杰哥智能化系统】能力上限的真实试验场。

施工总路线调整为：

```text
真实业务试验场 -> 问题暴露 -> 规则修正 -> 脚本固化 -> 验收护栏 -> 经验沉淀 -> 总管调度下一轮
```

四大系统的小闭环定位如下：

- 00总管：定边界、看验收、管接续、安排下一步。
- 01智能系统：保障模型、服务、工具、企业微信和运行时。
- 02扩展系统：承载股票等真实业务，把系统能力用起来。
- 03进化系统：把真实问题、修复经验和方法候选沉淀成可复用能力。

股票系统当前已经形成第一试验场：完全交付最终验收 5/5，C+++ 日常可用总验收 16/16，企微前台交互回归 20/20，报告数据口径检查通过。后续不再把优化仅视为局部修补，而要将每次真实问题转化为系统闭环能力。

## 十、2026-05-04 个人智能母系统交付口径补充

本轮讨论形成新的总目标口径：

杰哥智能化系统最终不是单个股票工具，也不是脚本集合，而是本地私有、单用户、按真实日常节奏运行的个人智能母系统。股票系统是第一个成品样板，后续税务、文稿、视频、资料整理等业务系统应按同一套方法复制搭建。

交付结果必须站在使用者角度判断：

- 用户日常使用时不感觉自己在测试系统。
- 系统给结果，不把后台过程和工程问题丢给用户。
- 系统角色清晰，助手、专家、总管、智能、进化、扩展不得混乱。
- 用户确认过的偏好、规则和失败教训必须固化成规则和验收，不靠用户反复提醒。
- 交付以完整业务周期、手机端、电脑端、企业微信入口、图文详情、报告内容、服务稳定和旧问题不复发为准。
- 自动维护是成熟产品保障，不是半成品补丁；核心交付范围内反复出错，优先视为搭建质量缺陷。
- 系统最终应能摆脱当前搭建者依赖，保留清楚的规则、验收、日志、状态面板、入口、接续和恢复路径。

后续搭建主梁统一为：

```text
调度 -> 边界 -> 验收 -> 复用
```

- 调度：按用户真实日常节奏、交易保护窗口、系统负载和任务优先级安排工作。
- 边界：明确系统、脚本、模型、工作流、数据、报告和用户授权边界。
- 验收：按真实使用结果和时间维度验收，防止假完成和旧口径误判。
- 复用：把股票系统合格经验抽象为新业务系统自动复制搭建能力。

真实日常节奏定义：

- A股交易日 `09:30-11:30`、`13:00-15:00` 为股票系统最高保护窗口；建议 `09:00-15:30` 作为交易日施工保护窗口。
- 节假日、周末、非交易日除外，但仍要遵守影子试验、回滚、验收和安全边界。
- 开市时间股票系统轻量待命，企业微信、查询和缓存可用，不做影响入口、服务、报告、数据链路或公网回调的施工。
- 收市后由系统选择合适时机收集交易信息、生成分析结果、形成可询问答案和图文报告。
- 夜间或空闲时做复盘、备份、文稿质检、学习提炼、影子试验和低风险维护。
- 用户使用电脑进行日常工作、视频制作或其他重任务时，系统应降载、排队或延后后台重任务。

搭建者职责补充：

- 用户负责定义目标、体验和重大边界；搭建者负责落地结果。
- 既定目标范围内的路径修复、旧入口纠偏、端口口径冲突、验收口径落后、脚本标头、日志同步和规则补齐，由搭建者自行处理，不反复询问用户。
- 旧方案、旧日志和旧脚本是参考，不是最高准绳；最新确认的总目标、正式可用链路和最新验收结果优先。
- 只有涉及删除迁移、覆盖正式数据、改变用户使用习惯、外部账号安全、不可逆动作或超出授权范围时才询问用户。

下一阶段计划调整：

1. 不推翻四系统架构；以四系统为正式骨架。
2. 股票系统继续作为第一个成品样板，优先保证正式使用不受施工影响。
3. 总管系统补齐交易保护、日节奏调度、旧口径冲突审计和时间维度验收。
4. 智能系统逐步收口模型、工具和运行时统一入口，避免扩展系统各自乱调模型。
5. 进化系统把有效经验转成候选规则，并跟踪引用效果，防止乱学和经验污染。
6. 扩展系统后续新业务必须按合格模板复制搭建，不从空白开始，也不复制旧问题。
