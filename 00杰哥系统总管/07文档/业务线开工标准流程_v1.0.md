# 业务线开工标准流程

> 版本：v1.0  
> 生成时间：2026-05-07 00:48:00 +08:00  
> 来源轮次：003-006  
> 适用范围：02扩展系统新业务线、既有业务线重启、跨业务线能力复用

---

## 一、定位

本流程用于把股票系统的成熟经验转成可复用方法，而不是机械复制股票系统目录、脚本或高频逻辑。

开工目标不是“先做一堆功能”，而是先建立一条最小可信闭环：

```text
候选比较 -> 开工契约 -> 最小样例 -> 证据链草案 -> 联动验收 -> 方法沉淀
```

---

## 二、六步流程

### 第一步：候选业务线适配比较

只读比较候选业务线的目录、配置、文档、已有数据和安全边界。

必须输出：

- 候选业务线清单。
- 风险和成熟度比较。
- 首条业务线选择理由。
- 后续业务线排队顺序。

不得直接进入施工。

### 第二步：业务线开工契约

按母本模板生成开工契约。

必须写清：

- 入口定义。
- 数据源。
- 处理逻辑。
- 交付物。
- 验收标准。
- 失败处理。
- 依赖清单。
- 母本通用能力覆盖。
- 不适配项说明。

没有开工契约，不得生成业务产物。

### 第三步：最小样例闭环

优先做最小样例，不做大而全。

推荐三类样例：

- 有证据可回答。
- 弱证据需降级。
- 无证据必须闭口。

必须形成：

- 问题样例。
- 证据片段或证据来源。
- 回答草案。
- 人工复核清单。
- 验收报告。
- 交付包。

### 第四步：高风险业务只做证据链草案

税收、法律、财务、投资等高风险业务不得直接输出正式结论。

只能输出：

- 问题样例。
- 证据来源。
- 回答草案。
- 降级/阻断口径。
- 人工复核清单。

必须明确“不是正式意见”。

### 第五步：跨业务线联动验收

当新业务线要接入知识库、内容、企业微信、n8n 或模型路由时，必须先做只读联动验收。

联动验收只检查：

- 字段是否能映射。
- 安全边界是否保留。
- 特有字段是否被摘要丢失。
- 禁止项是否仍关闭。

联动验收不代表正式接入。

### 第六步：方法沉淀

每条业务线完成最小闭环后，必须把经验沉淀到总管和进化。

沉淀内容：

- 哪些母本能力可复用。
- 哪些母本能力不适配。
- 哪些字段必须保留。
- 哪些动作必须人工复核。
- 哪些禁止项绝不能放开。

---

## 三、开工准入检查

| 检查项 | 必须满足 |
|:---|:---|
| 是否有候选比较报告 | 是 |
| 是否有开工契约 | 是 |
| 是否定义最小样例 | 是 |
| 是否写清禁止项 | 是 |
| 是否定义人工复核入口 | 是 |
| 是否说明不适配母本项 | 是 |
| 是否不触发外部链路 | 是 |

---

## 四、统一禁止项

默认禁止：

- 触发 n8n。
- 发送企业微信。
- 写正式库。
- 覆盖索引。
- 删除资料。
- 调用模型推理形成高风险判断。
- 调用外部接口补证。
- 调用券商接口。
- 自动交易。
- 输出正式税务、法律、财务或投资结论。

---

## 五、后续复用顺序

| 后续业务线 | 建议入口 |
|:---|:---|
| 内容处理系统 | 复用知识库系统下的可追溯问答框子模块，先做“原文-证据-改写草案-复核”闭环 |
| 视频制作系统 | 复用任务批次日志，先做“素材需求-脚本草案-分镜草案-人工复核”闭环 |
| 税收业务系统 | 继续证据链草案和人工复核，不直接进入正式税务意见 |
| 本职工作系统 | 待用户明确恢复后，只做草稿和复核清单 |
