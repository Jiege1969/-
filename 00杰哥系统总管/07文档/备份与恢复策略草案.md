# 备份与恢复策略草案

创建日期：2026-04-26

## 一、定位

本文件定义 v3 的备份和恢复原则。

当前只做策略设计，不执行备份。

## 二、备份分类

| 类型 | 内容 | 频率建议 | 位置建议 |
|---|---|---|---|
| 配置备份 | 配置文件、compose、注册表、端口表 | 每周或重大变更前 | `F:\系统备份` |
| 文档备份 | 宪章、蓝图、日志、ADR、设计文档 | 每周 | `F:\系统备份` |
| 工作流备份 | n8n 工作流 JSON 导出 | 每周或修改前 | `F:\系统备份` |
| 数据库备份 | PostgreSQL 逻辑备份 | 每周或重大变更前 | `F:\系统备份` |
| 模型清单备份 | 模型列表、manifest 清单 | 每周 | `F:\系统备份` |
| 模型文件备份 | 大模型权重 | 按需 | 专项评估 |

## 三、第一阶段备份原则

1. 先备配置和文档。
2. 数据库优先逻辑备份，不直接复制运行中的数据库目录。
3. n8n 优先导出工作流 JSON，不直接复制运行中的 SQLite。
4. 模型文件体积大，先记录清单和路径，不立即复制。
5. 备份脚本第一版必须只读检查，不自动删除旧备份。

## 四、恢复原则

任何恢复脚本必须包含：

1. 恢复对象。
2. 备份来源。
3. 恢复目标。
4. 覆盖风险。
5. 回滚方案。
6. 恢复后验证命令。

## 五、禁止事项

1. 禁止无确认覆盖生产数据。
2. 禁止自动删除模型。
3. 禁止自动删除数据库。
4. 禁止清理 `F:\系统备份`。
5. 禁止使用 `docker system prune -a` 作为常规清理。
