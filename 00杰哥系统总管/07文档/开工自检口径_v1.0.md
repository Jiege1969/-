# 开工自检口径 v1.0

> 层级：系统规则 / 总管执行口径  
> 状态：当前执行  
> 固化时间：2026-05-10  
> 适用范围：每次继续施工、恢复会话、启动新一轮系统治理或业务系统改造前。

## 一、定位

开工自检不是新的审批负担，而是让治理内核形成习惯：先确认系统是否活着、边界是否清楚、资产是否有据可查，再决定本轮做什么。

自检输出面向人读，不默认倾倒完整 JSON。完整 JSON 留作证据，简报负责决策。

## 二、默认汇报格式

每次开工默认输出三段：

1. 红黄绿状态
   - 绿：核心端口、核心 API、计划任务、治理总控均满足基线；可继续施工。
   - 黄：存在非阻断观察项，例如某个任务最近结果非 0、双格式裁定积压、历史资产未裁定；可继续，但需说明风险。
   - 红：核心端口离线、核心 API 不可达、计划任务缺失、血缘缺口、触及企微/n8n/交易/删除红线；必须先处理或人工确认。

2. 关键事实
   - 治理总控状态。
   - 核心端口状态。
   - 核心 API 状态。
   - 计划任务状态。
   - P0 真理来源待裁定数量。
   - 活跃入口脚本血缘缺口。

3. 本轮建议
   - 本轮是否可继续。
   - 是否需要先验收、先修复、先裁定或先暂停。
   - 明确本轮禁止触碰的边界。

## 四、红线边界

开工自检本身必须保持只读：

- 不发送企业微信。
- 不触发 n8n。
- 不调用券商接口。
- 不执行交易。
- 不删除、移动、改名资产。
- 不把进化建议直接改成生产规则。

## 五、内化期原则

当前阶段是治理内核验收与内化期，不追加新治理机制，不扩大自动化清理动作。

优先事项：

1. 审阅 P0 核心真理来源裁定任务单。
2. 确认治理健康基线。
3. 让施工门禁、资产台账、健康体检、开工自检成为每轮施工的固定习惯。

资产治理追求逻辑清晰，不追求文件系统表面整洁。规则是防止错误，不是制造束缚。
