# 杰哥智能化系统整体搭建部署总规划

> 版本：v1.0  
> 生效时间：2026-05-07 10:34:12 +08:00  
> 定位：全系统后续搭建、部署、扩展、进化的主控规划  
> 施工原则：先统筹，再施工；绿灯直接做，黄灯轻提醒，红灯强确认。

---

## 一、总目标

杰哥智能化系统不是要一次性做成无所不知的“大而全系统”，而是要形成一个底层逻辑正确、方法科学、证据诚实、边界清楚、能在人工复核和真实案例中逐步成长的本地智能体系统。

核心纲领：

> 有限智能，正确生长。  
> 可信输入，诚实推理。  
> 草案输出，人工复核。  
> 经验沉淀，持续进化。  
> 依据有序，上位优先。

---

## 二、总体架构

系统采用“一条主线、三大底座、多个业务扩展”的结构。

### 2.1 一条主线

主线是智能体能力建设，不是清债，不是治理文档，不是单个业务系统。

主线判断标准：

- 是否让系统更会理解用户意图？
- 是否让系统更会把业务场景转成可执行步骤？
- 是否让系统输出更可信、更可复核？
- 是否让人工修正能进入进化沉淀？

### 2.2 三大底座

| 底座 | 职责 | 当前重点 |
|:---|:---|:---|
| 00总管 | 分流、接续、边界、面板、调度 | 最高智能总管三色通行 |
| 01智能系统 | 理解、推理、输出、草案表达 | 待复核草案输出规范 |
| 03进化系统 | 策略锚点、案例、修正、规则建议 | 道术映射与经验沉淀 |

### 2.3 多个业务扩展

02扩展系统是业务能力区，不是盲建区。

| 业务线 | 当前定位 | 开工策略 |
|:---|:---|:---|
| 股票分析 | 已有成熟样本 | 回收母本，不机械复制 |
| 税收业务 | 方案讨论成熟，未正式施工 | 先建可信资料底座和影子样例 |
| 视频内容 | 预留 | 等需求、输入、输出、验收清楚后开工 |
| 本职工作 | 预留 | 先收集真实场景，不急于建功能 |
| 企业微信非股票入口 | 预留 | 先明确交互边界和外发风险 |

## 三、搭建哲学落地为工作方法

### 3.1 道

1. 人机共生，不替代人。
2. 诚实优于聪明。
3. 不全面不是错误，乱确定才是错误。
4. 每个结论都要有证据边界。
5. 安全是护栏，不是锁链。

### 3.2 术

所有业务系统按同一条能力链建设：

```text
用户场景
-> 可信输入
-> 结构化理解
-> 依据匹配
-> 推理草案
-> 风险和不确定项
-> 人工复核
-> 修正沉淀
-> 进化建议
```

### 3.3 用

不同业务线只在字段、来源、输出形态、风险边界上不同，不改变底层方法。

- 股票：行情、策略、风险、复盘。
- 税收：政策、文号、效力、适用条件、地方口径、待复核草案。
- 视频：素材、授权、脚本、分镜、渲染任务、人工确认。
- 本职工作：材料、任务、约束、行动建议、执行复盘。

### 3.4 依据秩序

依据层级是整个智能体系的底层逻辑，不限于税收。它约束搭建工作、运行机制、各系统内部机制、系统之间的协作机制和进化沉淀机制。

核心链条：

```text
宪法 > 法律 > 部门规章制度 > 单位企业制度 > 职能科室工作流程
```

通用展开：

```text
宪法/根本原则
-> 法律
-> 行政法规
-> 部门规章、规范性文件、主管机关政策
-> 地方口径、单位/企业制度
-> 职能科室工作流程、操作SOP、人工经验
```

落地要求：

- 搭建：下级脚本、工作流、临时方案不得绕过总纲、安全边界和系统级规则。
- 运行：服务、计划任务、n8n工作流不得用局部便利覆盖上位安全规则。
- 业务：下位制度、地方流程和人工经验只能细化执行或提示风险，不得反向覆盖法律政策或系统总纲。
- 进化：人工修正先进入案例和建议，不能直接覆盖正式规则。
- 冲突：自动动作降级为待复核，不输出确定结论，不执行高风险动作。

系统治理自身也有层级，不能把所有总结平铺：

```text
系统总目标/根本原则
-> 全体系底层逻辑
-> 总管运行规则
-> 进化系统规则
-> 业务系统母本与通用模板
-> 具体业务线方案
-> 脚本、工作流、计划任务
-> 操作记录、案例、人工经验
```

后续施工判断顺序必须从上往下。若下级脚本、流程、样例或经验与上级原则冲突，优先修正下级产物，不迁就错误产物。

## 四、阶段规划

### 阶段一：最高总管轻量入口稳定

目标：所有请求先被轻量分流，但不被流程拖住。

交付物：

- 最高智能总管三色通行规则。
- R0只读指令分流脚本。
- 当前施工面板与接续包同步。

验收：

- 总结类请求为绿灯。
- 方案类请求为黄灯。
- 正式施工和高风险动作为红灯。

### 阶段二：智能输出底座稳定

目标：让系统所有业务输出都具备“可信草案”形态。

交付物：

- 待复核草案模板。
- 不确定项表达规范。
- 候选依据和推理链表达规范。

验收：

- 不出现“无需复核”“系统已自动确认”等越界表达。
- 每份业务草案都能看见事实、依据、推理、风险、待补项。

### 阶段三：进化底座可调用

目标：让经验不只写在文档里，而是能被检索、调用、复用。

交付物：

- 策略锚点库最新索引。
- 道术映射工作流。
- 人工修正样本格式。

验收：

- 新理念入库前能查重。
- 人工修正不会自动升级为正式规则。
- 多次重复修正可以形成进化建议。

### 阶段四：股票母本回收

目标：从股票系统提取通用能力，而不是复制股票系统外壳。

交付物：

- 股票系统通用能力清单。
- 股票专有能力清单。
- 不适配场景说明。

验收：

- 明确哪些能力可复制到税收、内容、视频等业务线。
- 明确哪些能力仅适合股票。

### 阶段五：税收业务影子底座

目标：税收系统暂不进入上线阶段，先搭建可信资料底座和影子样例。

交付物：

- 总局政策资料来源清单。
- 税收资料元数据字段草案。
- 软件产品即征即退影子样例。
- 待复核草案输出样例。

验收：

- 能用国家税务总局等公开权威资料作为上位兜底。
- 地方口径、基层流程、实务差异被标记为待补，而不是成为停工障碍。
- 输出不冒充正式税务结论。

### 阶段六：扩展系统按需开工

目标：当真实需求成熟后，再逐个业务线正式施工。

开工条件：

- 需求清楚。
- 输入清楚。
- 输出清楚。
- 风险边界清楚。
- 第一阶段验收标准清楚。

禁止：

- 因为有想法就开新系统。
- 因为有目录就写业务脚本。
- 因为有样例就宣称正式可用。

## 五、具体工作流

### 5.1 每次施工前

```text
读取当前施工面板
-> 最高智能总管三色分流
-> 绿灯直接做
-> 黄灯轻提醒后做
-> 红灯暂停讨论或人工确认
```

### 5.2 每次业务场景转施工

```text
用户描述场景
-> 提炼道
-> 拆解术
-> 区分通用和专用
-> 决定是总结、方案、影子样例，还是正式施工
```

### 5.3 每次输出业务分析

```text
事实摘要
-> 候选依据
-> 判断过程
-> 风险点
-> 待核实事项
-> 待复核草案
-> 人工批注入口
```

### 5.4 每次经验沉淀

```text
先查策略锚点
-> 已存在则引用
-> 不存在则判断是否可调用
-> 可调用才入库
-> 不可调用只保留在当前对话或案例说明
```

## 六、并行施工规划

允许并行，但必须按写入边界拆开。

| 并行线 | 可做内容 | 禁止 |
|:---|:---|:---|
| A 总管线 | 面板、接续包、分流脚本、三色规则 | 同时多人改同一入口规则 |
| B 智能线 | 草案模板、输出规范、提示词结构 | 直接调用模型跑业务结论 |
| C 进化线 | 策略锚点、案例格式、修正样本 | 未查重就追加规则 |
| D 母本线 | 股票母本提取、通用/专用拆分 | 机械复制股票结构 |
| E 税收影子线 | 来源清单、字段草案、影子样例 | 正式入库、外发、上线 |
| F R0核验线 | 文件存在、JSON解析、关键词扫描 | 写状态、触发服务 |

并行结果必须回收到当前施工面板和一键接续包。

## 七、短期工作顺序

### 第一步：完成总管轻量入口稳定

状态：进行中。  
重点：三色通行继续校准，防止误拦和漏拦。

### 第二步：完善智能输出底座

重点：形成通用“待复核草案模板”，适用于股票、税收、内容等业务。

### 第三步：完善进化样本格式

重点：人工修正如何进入样本库，如何形成进化建议。

### 第四步：回收股票母本

重点：只读提取股票系统成功基因，形成通用能力和专有能力清单。

### 第五步：税收影子底座

重点：围绕总局政策公开资料建立可信资料字段和样例，不急于正式系统上线。

## 八、硬边界

以下动作不因“继续施工”自动执行：

- 删除文件。
- 清债实操。
- 启动 n8n。
- 发送企业微信。
- 写正式业务库。
- 调用券商接口。
- 自动交易。
- 重启服务。
- 外发数据。
- 正式上线扩展业务系统。

---

## 九、结论

后续工作不是在“治理”和“搭建”之间摇摆，而是按统一路线推进：

> 总管定方向，智能出草案，进化收经验，扩展按成熟度逐步开工。  
> 先让系统会正确地想、正确地说、正确地记，再让它逐步会做更多事。
