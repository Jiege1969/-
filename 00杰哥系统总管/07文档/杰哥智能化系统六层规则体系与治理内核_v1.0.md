# 杰哥智能化系统六层规则体系与治理内核 v1.0

固化日期：2026-05-10

## 一、核心判断

杰哥智能化系统不能只是一组脚本、计划任务和模型入口。它必须成为一个有层级、有边界、有裁决、有反馈、有证据的智能组织。

本方案把我们讨论形成的治理思想固定为六层规则体系：

```text
底层逻辑 -> 通用原则 -> 系统规则 -> 子系统规则 -> 流程脚本 -> 命令动作
```

这里不再把最高层正式命名为“宪法”。“宪法”只是一种比喻，容易让人误解为绝对不可修改。正式命名采用“底层逻辑”。它代表最高稳定层，接受实践检验，但不能被低层级脚本、局部经验或短期便利随意突破。

## 二、六层规则体系

| 层级 | 名称 | 回答的问题 | 稳定性 |
|---|---|---|---|
| 1 | 底层逻辑 | 系统为什么存在，最终服务谁，不能突破什么 | 最高 |
| 2 | 通用原则 | 所有系统共同怎么做 | 高 |
| 3 | 系统规则 | 总管、智能、扩展、进化如何分工协作 | 中高 |
| 4 | 子系统规则 | 股票、税务、视频等具体业务如何运行 | 中 |
| 5 | 流程脚本 | 如何把规则变成可执行流程 | 中低 |
| 6 | 命令动作 | 具体执行哪一步 | 最灵活 |

层级越高，适用范围越广，稳定性越强，修订门槛越高。层级越低，执行越具体，调整越灵活，但必须服从上级约束。

## 三、上下级关系

系统规则不是平铺关系，而是上下级关系：

```text
上级管下级，下级服从上级。
下级执行上级，上级通过下级落地。
```

相邻两层中，上级是下级的根本依据，下级是上级的执行转化。相邻三层中，前者提供根本依据，中间层提供转化规则，后者提供具体办法。

这套关系不是为了制造僵化，而是为了保证复杂系统不乱套。服从是执行关系，反馈是进化关系。下级不能越权推翻上级，但可以通过实践证据向上反馈，推动上级规则修订。

## 四、四大系统分工

| 系统 | 职责 |
|---|---|
| 00总管 | 调度、裁决、守门、证据归档、对外入口管理 |
| 01智能 | 理解、生成、推理、知识与模型能力支撑 |
| 02扩展 | 股票、税务、视频、内容、本职、企微助手、问答框等业务执行 |
| 03进化 | 复盘、提炼、提出规则优化草案，不绕过总管直接修改生产规则 |

总管是执行与裁决中心。进化系统是复盘与提案中心。扩展系统是业务执行中心。智能系统是理解与生成能力中心。杰哥本人保留最终确认、否决和红线解锁权。

## 五、治理内核的五项能力

### 1. 层级规则体系

解决“谁约束谁、谁解释谁、谁执行谁”的问题。任何脚本和命令，都必须能向上追溯到上级规则。

### 2. 施工门禁

每次施工前必须回答：

- 施工对象是什么；
- 影响哪个系统；
- 是否触碰企微真实发送、外网写入、交易、规则进化；
- 是否需要沙盒、影子、灰度、人工确认；
- 是否有回滚方案；
- 证据写到哪里；
- 失败是否阻断继续施工。

### 3. 治理闭环

门禁不是只负责拦截，也要复盘自己的判断质量：

```text
施工申请 -> 风险定级 -> 门禁检查 -> 执行或阻断 -> 证据归档 -> 结果复盘 -> 规则优化提案
```

进化系统负责分析通过率、阻断原因、复发问题、误放行和误阻断，提出规则优化草案。草案必须交总管评估，重大修订由杰哥确认。

### 4. 遗产先例库

老系统遗产不是垃圾，也不是教条。它们要被结构化为经验材料。

先例库的使用原则：

- 先例是参考，不是自动授权；
- 复用前必须重新判断当前场景；
- 优先借鉴理念、结构、验证方法，不机械照搬命令；
- 当前条件与先例不一致时，先例必须降权；
- 任何先例复用仍需重新经过施工门禁。

### 5. 规则血缘追踪

每个流程脚本至少要能回答：

- 它属于哪个子系统；
- 执行哪条子系统规则；
- 受哪条系统规则约束；
- 体现哪条通用原则；
- 不能突破哪条底层逻辑；
- 输出证据在哪里。

### 6. 单一真理来源

双格式文件不是越多越好。同一事实不能长期由 JSON 和 Markdown 同时手工维护，否则迟早产生冲突。

规则如下：

- 机器状态、巡检结果、台账数据：JSON 是当前真理来源；
- 人读纲领、底层逻辑、施工规范：Markdown 是当前真理来源；
- 另一种格式只有在明确需要时才保留，且必须标明是派生视图、索引、历史证据或归档文件；
- 已被吸收的旧文件不继续留在当前执行路径；
- 删除不是目的，防止错误才是目的。删除前必须确认无依赖、无唯一证据价值、无人工阅读价值。

## 六、实践检验原则

实践是检验真理的唯一标准。落实到系统里，就是：

- 规则不能因为写在文件里就永远正确；
- 方法不能因为过去成功就自动继续适用；
- 脚本不能因为曾经安全就免除当前检查；
- 先例不能因为存在就自动成为授权；
- 所有规则、流程、脚本和命令都必须接受日志、验收、运行结果和复盘检验。

底层逻辑是最高稳定层，不是不可修改的神像。它也可以被实践推动修订，但修订门槛最高，必须经过严格论证、总管评估和杰哥确认。
