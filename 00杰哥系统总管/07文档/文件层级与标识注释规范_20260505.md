# 文件层级与标识注释规范

## 目标

系统里的功能、维护、证据、配置、脚本都必须能被快速识别：它是什么、归谁管、怎么触发、有什么风险、出了问题怎么回退。

## 目录层级

四大系统按职责分层：

- `00杰哥系统总管`：总控、准入、巡检、进度、回滚、接续和全局文档。
- `01杰哥智能系统`：本地模型、智能中台、知识检索、异常处理和核心推理能力。
- `02杰哥扩展系统`：股票、视频、工作秘书、税收、知识库、企业微信助手等业务扩展。
- `03杰哥进化系统`：经验沉淀、提示词治理、模型评测、系统复盘和规则升级。

每个子系统优先使用统一目录：`01配置`、`02脚本`、`03数据`、`04日志`、`05备份`、`06临时`、`07文档`。没有对应内容时可以为空，但不能混放职责。

## 文件标识

新增或修改的主线脚本必须在文件头说明：

- 名称
- 作用
- 输入
- 输出
- 触发方式
- 依赖
- 安全边界
- 验收方式
- 回滚方式

配置文件应包含或配套说明：名称、用途、适用范围、是否正式启用、安全边界、最后更新依据。

文档文件应有一级标题。运行报告、验收报告、回收报告应写明时间、来源、结论、证据路径和下一步。

## 排除范围

第三方依赖、虚拟环境、工具解压目录、日志、备份、缓存、历史原始输出，不要求逐个补写业务标识，但需要由所在目录说明统一解释来源和清理规则。

## 补写优先级

1. 开机自检、企业微信入口、股票分析入口、任务契约层、备份恢复脚本。
2. 各子系统 README 和用户操作卡。
3. 当前仍被引用的 JSON 配置。
4. 历史回收报告、旧影子报告和过期草案。

## 清理原则

能复用的沉淀为经验或模板，不能复用但有审计价值的归档，明确无价值的临时缓存再删除。删除前必须避开业务数据、模型、数据库、备份、日志证据和正式配置。
