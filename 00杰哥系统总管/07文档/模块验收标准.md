# 模块验收标准

创建日期：2026-04-26

## 一、用途

本文件定义 v3 各系统和模块的验收标准。

后续迁移或新增模块，必须按验收标准判断是否完成。

## 二、通用验收标准

每个模块必须满足：

1. 目录结构完整。
2. 配置和代码分离。
3. 数据和日志有明确路径。
4. 有 README。
5. 有健康检查方式。
6. 有失败兜底方式。
7. 有备份说明。
8. 不私自绕过主系统基础能力。

## 三、00总管验收

| 能力 | 标准 |
|---|---|
| 服务注册 | 所有长期服务有登记 |
| 端口登记 | 所有宿主机端口有说明 |
| 禁区清单 | 高价值路径明确列出 |
| 状态检查 | 只读检查脚本可运行 |
| 日志 | 每次重要操作有记录 |
| ADR | 重要架构决策有记录 |

## 四、01主系统验收

| 能力 | 标准 |
|---|---|
| 网关 | 本地健康检查通过 |
| 大脑 | 可识别任务类型 |
| 模型路由 | 可按任务选择模型 |
| 数据库 | 可连接、可备份 |
| Redis | 可连接、可用于状态记录 |
| n8n | 可健康检查、可执行测试工作流 |
| 知识库 | 可入库、可检索、可回答 |
| 消息出口 | 可统一推送、可记录失败 |

## 五、02扩展模块验收

### 股票研究系统

1. 可单股分析。
2. 可生成报告。
3. 可说明风险。
4. 可通过统一消息出口推送。
5. 批量任务不阻塞即时问答。

### 视频制作系统

1. 可接收音视频文件。
2. 可转写文本。
3. 可生成摘要。
4. 长任务进入队列。
5. 输出文件有归档路径。

### 本职工作系统

1. 可检索工作资料。
2. 可生成摘要和报告草稿。
3. 可区分事实和推测。
4. 不编造知识库不存在的信息。

### 内容处理系统

1. 可摘要、改写、润色。
2. 可生成结构化提纲。
3. 可调用知识库上下文。
4. 输出格式稳定。

## 六、03进化系统验收

| 模块 | 标准 |
|---|---|
| 反馈提炼 | 可沉淀用户偏好和失败原因 |
| 提示词管理 | 有版本、原因、测试、回滚 |
| 模型评测 | 有题集、评分维度、建议 |
| 系统复盘 | 有现象、根因、方案、预防 |
