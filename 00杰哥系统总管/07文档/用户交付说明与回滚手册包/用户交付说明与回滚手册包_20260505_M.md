## 异常与回滚手册

### 通用异常

1. 先停止使用异常入口，不扩大样本，不追加真实动作许可。
2. 查 `03数据\并行回收` 中对应系统的最新回收报告，确认失败是否属于“安全阻断”还是“交付阻断”。
3. 查 `03数据\运行状态` 中对应验收 JSON/MD，确认是入口不可用、材料缺失、门禁未满足还是越权风险。
4. 若出现越权写入、真实外发、n8n 误触发、券商/交易相关意图未拦截，立即按 L3 异常处理：关闭入口、保留日志、不得继续自动推进。
5. 回滚后只允许恢复到只读、dry_run、影子或本地健康检查状态。

### 企业微信异常

- 查询入口异常：先改用本地股票助手 `19300` 和桥接健康 `19302` 核查，不启用批量主动发送。
- 统一指令异常：先停用统一指令入口的用户侧使用，保留本地日志，再查 `企业微信助手系统状态摘要` 和灰度门禁材料。
- 误外发风险：立即停止外发路径，保留企业微信返回和本地日志；未完成许可令复核前不得重新发送。

### n8n 异常

- 当前 n8n 正式导入、启用、触发仍关闭。
- 如发现 workflow 被启用，应执行人工回滚流程：强制恢复 `active=false`，导出状态验证，确认未触发真实 workflow。
- 已有回滚脚本仅用于人工明确确认后的回滚预演或保持未激活，不得当作放量入口。

### Redis / 队列异常

- 当前 Redis Streams 只允许影子映射，不允许正式队列接管。
- 如发现正式队列开关被打开，应恢复为 `formal_queue_enabled=false`、`redis_connection_allowed=false`，并要求完成 shadow replay、pending、重试、dead-letter 和人工回收演练后再评估。

### 股票异常

- 任何交易类意图未被拦截，按最高优先级异常处理。
- 立即回到 analysis-only 闸门：不允许券商接口、不允许自动交易、不允许下单、不允许资金账户、不允许目标价/仓位/买卖建议。
- 可继续保留只读分析和风险提示，但不得把交易语言转成执行动作。
