# 施工安全规则

## 一、总原则

所有新增脚本、工作流、计划任务、模型路由和业务线改造，默认先进入只读阶段。系统建设的目标是稳定、高效、可追踪、可回滚，不用复杂性换表面智能。

## 二、只读优先

任何新能力必须先交付 `_dryrun` 或只读版本，允许查询、扫描、采集、生成报告；不得创建、修改、删除正式数据，不得触发外部发送，不得调用交易接口。

进入可写或正式执行前，必须具备：

- 只读报告已生成。
- 影响范围已列出。
- 回滚方式已写明。
- 安全边界未被放宽。
- 相关子系统职责未越界。

## 三、最小试点

任何可能影响在线服务的操作，都先在影子目录、禁用工作流、样本数据或单一业务线试点。试点至少完成一个观察周期后，再决定是否扩大范围。

禁止直接全量执行：

- 批量删除或移动目录。
- 全量重启服务。
- 修改 Redis/n8n/Ollama 正式配置。
- 激活 n8n 正式工作流。
- 替换模型主路由。
- 清理 Docker 卷、镜像、模型、数据库和 F 盘备份。

## 四、事件链 ID

重大巡检、异常、施工、修复、验收必须使用事件链 ID。格式：

`EVT-YYYYMMDD-NNN-简述`

一次完整事件至少包含：

- 前件：定时、手动、预警或用户指令。
- 检查：探针数据、自检结果、依赖状态。
- 动作：执行了什么脚本或流程。
- 结果：成功、异常、超时、跳过。
- 验收：自动校验或人工结论。

## 五、人工超控

人的最终决策权高于任何自动化。后续总管入口必须支持：

- 指挥：普通任务指令，按规则执行。
- 否决：`暂缓`、`不做`，总管停止推进并记录原因。
- 刹车：`红灯`、`全停`，冻结所有自动化执行，只保留只读探针。
- 恢复：`绿灯`、`恢复`，经状态检查后恢复允许的自动化。

超控关键词必须在任务解析和模型调用之前硬匹配。

## 六、绝对禁止项

- 禁止自动交易。
- 禁止调用券商正式交易接口。
- 禁止把股票分析输出写成买卖指令。
- 禁止未经授权发送企业微信正式消息。
- 禁止触发 n8n 正式工作流做真实外部动作。
- 禁止无备份、无回滚、无验收的升级。
- 禁止直接执行 `docker system prune -a --volumes`。

## 七、允许系统自主执行的事项

- 只读探针。
- 日志轮转。
- 资源水位记录。
- 状态台账生成。
- 只读巡检报告。
- 已注册的隐藏本地守护任务。

这些动作不得越过“只读”边界。

## 八、清债不添新债

清债不是“留档、观察、以后处理”的堆叠游戏。施工安全不等于无限延期，治理动作本身也不得制造新债。

适用范围：

- 当前工作对象：旧目录、旧任务、旧配置、死路径、重复工作流、废弃资产。
- 施工者自身：Codex、总管、后台并行窗口和后续智能体。
- 系统环节：提示词、n8n、计划任务、Docker、备份、日志、接续包、面板、验收报告。

执行口径：

- 证据充分、无当前依赖、风险明确的旧项，导出最低必要证据后直接删除、修正或移除持久化入口。
- 只有依赖不明、影响不明、需要停机窗口、涉及正式高价值数据一致性或外部硬闸门时，才允许进入观察或受控窗口。
- 施工者不得把可由扫描判断的技术问题推回给用户确认。
- 施工者自己引入的副作用必须同轮修复。
- 报告、台账、面板和接续包必须减少真实尾巴，不得堆出新的“待处理债务”。

每轮收口必须说明：

- 已清掉什么。
- 已修正什么。
- 已补什么备份。
- 新增或更新了什么规则。
- 仍剩什么真差距。
- 为什么剩余差距不能当轮解决。
