# 共享政策证据源调配草案

> 版本：v1.0  
> 日期：2026-05-07  
> 资产身份：总管调配设计草案  
> 风险等级：W1  
> 边界：不是正式总管规则，不是生产接口配置；总管只做登记、调配和提醒，不直接生成业务结论。  

## 一、定位

税收业务系统沉淀的政策知识库，可以逐步升级为扩展系统内部可查询的共享政策证据源。

当前阶段不把总管做成每次调用的执行者，也不优先建立 n8n 工作流。更简单有效的方式是：扩展系统内部只读调配，总管只登记能力和边界。

总管系统不直接承接政策查询，也不替业务系统分析结论。总管只负责三件事：

1. 登记哪些证据源可共享。
2. 提醒哪个系统可以按什么边界查询。
3. 对高风险调用触发暂停确认。

## 二、调配模型

```text
用户或业务系统提出政策相关问题
-> 扩展系统内部判断是否需要政策证据
-> 读取共享证据源注册草案和调用契约
-> 业务系统按只读契约查询税收政策证据底座
-> 业务系统在本业务契约内生成待复核草案
-> 总管只在接续包和面板中记录共享能力与边界
```

## 三、总管不做的事

| 不做 | 原因 |
|:---|:---|
| 不直接查询外部网站 | 防止总管变成抓取执行器 |
| 不直接修改政策库 | 政策库由证据底座维护 |
| 不生成专业业务结论 | 结论应由业务系统在本领域契约内生成 |
| 不绕过人工复核 | 跨系统调用容易扩大误判影响 |
| 不把待核验证据升级为确认依据 | 证据状态必须保真 |
| 第一阶段不建 n8n 自动化 | 当前调用范围少，n8n会提前增加W3风险和维护成本 |

## 四、共享证据源注册字段

| 字段 | 说明 |
|:---|:---|
| source_id | 证据源编号 |
| source_name | 证据源名称 |
| owning_system | 维护系统，如税收业务系统 |
| asset_identity | 影子库、候选层、正式配置等 |
| allowed_query_systems | 允许查询的系统 |
| allowed_query_scope | 可查询范围 |
| forbidden_use | 禁止用途 |
| risk_level | 调用风险等级 |
| human_gate_required | 是否需要人工闸口 |
| source_index_path | 本地索引路径 |

## 五、当前建议注册项

| source_id | source_name | owning_system | 当前身份 | 可服务系统 | 边界 |
|:---|:---|:---|:---|:---|:---|
| SHARED-POLICY-EVIDENCE-001 | 税收政策知识库/政策证据底座 | 税收业务系统 | 影子库/政策证据候选层 | 税务、股票、本职工作、视频、总管 | 只读查询，返回证据，不返回业务结论 |

## 六、触发暂停条件

| 情况 | 处理 |
|:---|:---|
| 其他系统要求写入政策库 | 暂停，W3 |
| 要把共享证据接入正式配置 | 暂停，W3 |
| 要接 n8n、企业微信、自动调度、外发 | 暂停，W3 |
| 要让政策库直接返回最终结论 | 暂停，方向纠偏 |
| 要使用待核验证据作为确认依据 | 暂停，证据状态纠偏 |

## 七、第一阶段落地

第一阶段只做影子层：

1. 维护共享政策证据源调配草案。
2. 维护跨系统调用契约草案。
3. 先采用扩展系统内部轻量只读调配，不上 n8n。
4. 为税务、股票、本职工作、视频分别做一个只读调用样例。
5. 验证各业务系统都保留 evidence_level、validity_status、source_url、missing 和 forbidden_use。
6. 不写生产接口、不写正式共享配置。
7. 等调用频率和字段稳定后，再评估是否值得建立 n8n 编排。

## 八、结论

当前最优方式是：扩展系统内部轻量只读调配优先；总管只做登记、边界提醒和接续记录；n8n后置。这样比一开始建设工作流更简单、更有效，也更符合政策知识库专业但调用面有限的现状。
