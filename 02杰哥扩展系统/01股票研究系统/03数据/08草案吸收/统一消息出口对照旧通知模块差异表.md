# 统一消息出口对照旧通知模块差异表

生成时间: 2026-04-28
标识: unified-message-outlet-vs-old-notify-module-diff

## 一、结论先行

旧 `通知模块.py` 的优点是简单直接，能把文本发到企业微信；缺点是直接内置Webhook地址、缺少白名单、缺少限流、缺少灰度、缺少消息合并和权限边界。

新系统不能照搬旧通知模块。正确吸收方式是保留“统一发送入口”的思想，但用 `统一消息出口 + 企业微信受控发送闸口 + 白名单灰度 + 日志记录` 重构。

## 二、能力对照

| 能力 | 旧通知模块 | 新统一消息出口设计 | 结论 |
|---|---|---|---|
| 文本发送 | 支持 | 支持，受控发送 | 思路已吸收 |
| 凭据管理 | 明文写入脚本 | 配置隔离，禁止明文入日志 | 新系统更安全 |
| 白名单 | 无 | 有白名单和首轮灰度限制 | 新系统更稳 |
| 限流 | 无 | 设计为受控闸口 | 新系统更稳 |
| 消息合并 | 无 | 统一出口预留合并能力 | 新系统更适合长期运行 |
| 日志 | 本地简单日志 | 系统日志、灰度记录、回滚预案 | 新系统更可追溯 |
| 失败处理 | 打印失败 | 需进入回滚和诊断链路 | 新系统更符合无人值守 |

## 三、已吸收内容

- 所有面向用户的消息应走统一出口。
- 企业微信是当前最现实的移动端交互终端。
- 通知模块必须能记录发送结果。
- 测试消息必须有单独入口。

## 四、明确废弃内容

- 废弃脚本内硬编码企业微信Webhook。
- 废弃任意脚本直接调用企业微信接口。
- 废弃无白名单的主动推送。
- 废弃业务脚本自行发送消息。

## 五、对股票系统交付的要求

股票系统通过企业微信交付时，必须满足:

1. 股票助手生成回复，不直接发送。
2. n8n 编排消息，不保存密钥明文。
3. 统一消息出口发送消息。
4. 企业微信受控发送闸口限制白名单和测试次数。
5. 首轮真实灰度不超过5条消息。
6. 所有发送结果写入新系统日志。

## 六、后续施工建议

优先完成企业微信查询闭环，不恢复旧通知模块。旧通知模块只作为“为什么要统一出口”的经验材料。
