# 股票日常使用包对照旧每日简报差异表

生成时间: 2026-04-28
标识: stock-daily-package-vs-old-daily-brief-diff

## 一、结论先行

旧 `每日简报.py` 的核心价值是“每日系统状态 + AI短建议 + 主动通知”。新 `股票研究日常使用包` 的核心价值是“股票研究结果 + L5候选 + 复盘入口 + 数据健康度”。

两者不是谁替代谁。正确吸收方式是：股票系统交付时保留新日常使用包为主体，同时在企业微信回复和状态摘要中补充系统健康状态入口。

## 二、能力对照

| 能力 | 旧每日简报 | 新股票日常使用包 | 结论 |
|---|---|---|---|
| 系统状态 | CPU、内存、D盘、Docker、Ollama | 未直接展示，另有状态摘要链路 | 需要在入口说明中关联状态摘要 |
| 股票研究 | 无系统化股票分层 | L5/L6/L7、评分、技术依据、风险 | 新系统更强 |
| AI短建议 | 50字以内系统建议 | 结构化研究建议 | 新系统更适合股票研究 |
| 主动通知 | 直接调用通知模块发送 | 当前不主动发送，企业微信需灰度放行 | 新系统更安全 |
| 数据健康 | 无 | 指标成功率、健康等级、降级说明 | 新系统更强 |
| 复盘闭环 | 无 | 系统判断账、人工决策账、结果验证账、经验提炼账 | 新系统更强 |
| 安全边界 | 直接发送企业微信 | 默认不发送、不触发n8n、不接交易 | 新系统更稳 |

## 三、吸收结论

已吸收:

- 每日简报“每天可读”的思路。
- 系统状态应当进入使用入口的思路。
- AI建议必须简短、可读、有结论的思路。

新系统增强:

- 把“泛系统状态简报”升级为“股票研究日常使用包”。
- 加入数据健康度，避免数据异常时误导分析。
- 加入L5/L6/L7分层和复盘账本。

需要补齐:

- 在企业微信短回复中增加“系统状态摘要可查询”的入口提示。
- 在交付说明中说明：股票日常包看研究，状态摘要看系统健康。

## 四、暂不吸收

旧每日简报的直接主动推送暂不吸收。原因:

1. 真实企业微信发送属于高风险动作。
2. 主动推送需要白名单、限流、合并、优先级控制。
3. 股票系统交付前，先保证用户主动查询无障碍。

## 五、施工建议

当前阶段不新增主动定时推送。先完成:

1. 企业微信主动查询股票。
2. 企业微信查询数据健康度。
3. 企业微信查询状态摘要。
4. 交付后再把每日简报纳入 n8n 定时任务。
