# 旧资产第一批股票企微吸收结论

生成时间: 2026-04-28
标识: first-batch-stock-wecom-assimilation-for-stock-system

## 一、结论先行

F盘老系统可复用资产包中的股票和企业微信资料，已经转化为新股票研究系统的四个施工方向:

1. 股票识别与技术分析接口补齐。
2. 数据源降级时的本机中转候选方案。
3. 企业微信消息入口、n8n编排、股票助手分析、统一消息出口的分层闭环。
4. 查询历史、人工反馈、结果验证、经验提炼的复盘闭环。

## 二、已落地吸收项

| 旧资产经验 | 新系统落点 | 当前状态 |
|---|---|---|
| 股票名称/代码识别 | 股票助手 `/识别`、`/recognize` | 已补齐 |
| 技术指标独立查询 | 股票助手 `/技术分析`、`/technical` | 已补齐 |
| 股票查询和回复分段 | 股票助手、n8n Webhook、统一消息出口 | 已吸收 |
| 企业微信作为终端 | 企业微信助手系统、OpenClaw契约、n8n灰度入口 | 已吸收 |
| 查询历史和记忆 | 复盘账本、反馈账、经验提炼账 | 已升级 |
| 宿主机行情中转 | 数据源降级候选方案 | 已登记，未启用 |

## 三、暂缓吸收项

| 旧资产经验 | 暂缓原因 | 后续处理 |
|---|---|---|
| 旧 n8n 工作流直接导入 | 直接导入有激活和凭据风险 | 只读拆解节点逻辑后重构 |
| 旧企业微信凭据复用 | 存在密钥安全和权限边界风险 | 重新生成或人工配置 |
| 旧数据库恢复 | 会污染新系统正式数据 | 只做结构和经验参考 |
| 图片报告 | 当前交付优先级低于文字和企业微信闭环 | 股票系统交付后增强 |

## 四、对当前交付的作用

股票系统交付前，重点不再是继续扩展功能，而是确保以下闭环稳定:

1. 企业微信输入能进入新系统灰度入口。
2. n8n 能把消息交给股票助手。
3. 股票助手能识别、分析、返回短回复和深度报告入口。
4. 统一消息出口能受控发送，不越权。
5. 查询和反馈能进入复盘账本。

## 五、下一步

优先生成两个差异表:

- 股票日常使用包对照旧每日简报差异表。
- 统一消息出口对照旧通知模块差异表。

这两个差异表完成后，股票系统的“旧经验吸收”就能从架构层进入交付验收层。
