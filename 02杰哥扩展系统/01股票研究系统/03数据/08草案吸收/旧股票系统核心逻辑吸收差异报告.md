# 旧股票系统核心逻辑吸收差异报告

生成时间: 2026-04-28
标识: old-stock-core-logic-assimilation-diff

## 一、结论先行

旧 `D:\杰哥智能体操作系统` 的股票系统核心逻辑已经被新 `01股票研究系统` 吸收了一部分，尤其是企业微信查询、单股分析、重点关注池、技术指标、报告和复盘闭环。

但还没有全部吸收完。旧系统中仍有三类值得继续优化进新系统：独立技术分析接口、股票识别调试接口、报告图片能力。

## 二、已吸收内容

| 旧系统能力 | 旧系统位置 | 新系统落点 | 状态 |
|---|---|---|---|
| 企业微信作为输入输出终端 | 智能体网关、云转发隧道、n8n工作流资料 | 企业微信助手、统一消息出口、n8n Webhook灰度入口 | 已吸收并重构 |
| 单股分析入口 | 股票分析服务 `/分析` | 股票助手 `/分析`、`/analyze` | 已吸收 |
| 行情查询 | 新浪行情、东方财富K线 | 公开行情快照、单股即时报告、数据健康度 | 已吸收并扩展 |
| 技术指标 | MA、RSI、MACD、成交量、趋势评分 | 技术指标链路、候选池、L5深度研究 | 已吸收并扩展 |
| 自选股思路 | 旧自选股.json | 新重点关注池、动态样本池 | 已吸收并升级 |
| 模型解释 | Ollama 默认股票模型 | 模型资源池、L5深度研究、报告生成 | 已吸收 |
| 记忆与复盘 | SQLite 股票记忆、查询历史 | 系统判断账、人工决策账、结果验证账、经验提炼账 | 已升级 |

## 三、未完全吸收内容

### 1. 独立技术分析接口

旧系统有 `/技术分析`，便于只返回技术指标，适合 n8n 调试和批量筛选。

新系统已有技术指标链路，但股票助手入口还没有直接对外提供同等简洁接口。

建议: 新增 `/技术分析` 和 `/technical` 只读接口，返回指定股票的指标、数据健康、分层建议。

### 2. 股票识别调试接口

旧系统有 `/识别`，用于检查“用户说的话到底识别成哪只股票”。

新系统已有 `find_stock` 和语音容错脚本，但入口层没有单独暴露识别接口。

建议: 新增 `/识别` 和 `/recognize` 接口，企业微信语音歧义时可先走识别确认。

### 3. 图片报告能力

旧系统可以生成图片报告，适合企业微信移动端阅读。

新系统目前以 Markdown、JSON、短回复为主，图片报告能力尚未纳入交付主线。

建议: 先不立即做图片渲染。股票系统交付后，将图片报告作为体验增强项，避免当前交付阶段复杂度上升。

## 四、明确不照搬内容

1. 不照搬旧系统目录结构。
2. 不直接迁移旧 SQLite 作为正式库。
3. 不直接搬运旧 Ollama 模型数据。
4. 不让 OpenClaw 承担业务判断。
5. 不接券商接口，不做自动交易。

## 五、下一步吸收施工项

1. 在新股票助手入口增加 `/识别`、`/recognize` 接口。
2. 在新股票助手入口增加 `/技术分析`、`/technical` 接口。
3. 将上述两个接口纳入本地验收。
4. 暂存图片报告能力为后续体验增强，不阻塞股票系统交付。

## 六、释放旧股票系统前置判断

旧股票系统在以下条件满足前仍有参考价值:

1. 新系统企业微信查询闭环可用。
2. 新系统具备单股分析、技术分析、股票识别、状态摘要、L5报告能力。
3. 新系统完成首轮真实灰度测试。
4. 旧系统股票服务、网关、语音、运维经验已标注为已吸收或已废弃。
