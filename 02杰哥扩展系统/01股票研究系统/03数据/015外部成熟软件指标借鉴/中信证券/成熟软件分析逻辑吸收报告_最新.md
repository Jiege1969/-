# 成熟软件分析逻辑吸收报告

- 生成时间：2026-05-12 14:02:19
- 参考对象：中信证券本机软件结构
- 结论：通过

## 一句话结论

中信这类成熟软件的价值不在于某一个神奇指标，而在于它把股票分析组织成“场景入口 + 分层判断 + 风险闭环 + 持续跟踪”的工作流。我们要吸收的是这个底层逻辑。

## 核心提炼

- 成熟软件的入口不是单个技术指标，而是分析场景。：市场转折、涨跌停、板块联动、龙虎榜、融资融券、公告日历、个股资料等都是围绕具体问题建立的入口。 对本系统启发：我们要从指标驱动升级为场景驱动：每次分析先判断问题场景，再选择主导指标组合。
- 成熟软件先解决发现问题，再解决解释问题。：涨停、热点、排行、板块、异动用于发现；F10、财务、资金、公告、研报用于解释。 对本系统启发：推荐榜不能只给高分，要区分发现层信号和解释层证据。发现层只产生候选，解释层才决定研究等级。
- 成熟软件把市场、板块、个股、事件、交易行为分层组织。：市场状态、行业板块、个股形态、资金交易、事件日历各自独立又相互校验。 对本系统启发：市场环境、行业强弱、行业内个股筛选、趋势阶段、风险刹车必须是并行判断线，不能压缩成一个总分。
- 成熟软件强调看盘实时性和收盘复盘两套节奏。：盘中看异动、涨跌停、资金和排行；盘后看完整日线、公告、财报和复盘。 对本系统启发：本系统要区分盘中观察信号与盘后正式结论，盘中不能污染历史底座，盘后才能进入正式分析。
- 成熟软件有用户工作台逻辑。：自选股、预警、近期浏览、条件筛选不是分析公式，而是持续跟踪机制。 对本系统启发：股票顾问不能只生成一次性报告，还要形成关注池、观察条件、触发提醒、复盘闭环。

## 六层方法骨架

- 1. 发现层：今天/近期市场哪里发生了值得注意的变化？ 落地：市场宽度, 涨停跌停生态, 行业涨跌排名, 行业成交额占比, 异动股票清单。权限：只能发现候选，不能直接给重点研究结论
- 2. 归因层：它为什么强，是市场带动、行业带动、个股独立强，还是事件刺激？ 落地：行业归因, 相对行业强度, 残差强度, 公告/财报/行业证据, 主题重叠。权限：决定研究理由和证据完整度
- 3. 结构层：个股现在处在什么技术阶段，趋势、突破、回踩、收缩、过热还是破位？ 落地：第二阶段趋势模板, 均线斜率, 箱体突破, VCP收缩, 回踩不破, 距高低点位置。权限：决定观察条件，不单独决定研究等级
- 4. 承接层：资金和成交是否支持这个结构，是真承接还是假异动？ 落地：成交额5_20比, 成交额20_60比, 量比, 换手拥挤度, 龙虎榜/融资融券占位。权限：能提升或压低可信度，不能越过风险刹车
- 5. 风险层：有什么条件会让前面的强势判断失效？ 落地：失败对照, 行业失败集中, 高拥挤预警, 数据缺口, 事件日历, 财务质量闸门。权限：最高权限，能直接降级或暂缓
- 6. 跟踪层：之后什么时候重新判断，什么信号触发提醒？ 落地：关注池, 观察条件, 触发价位, 成交活跃阈值, 复盘账本。权限：决定系统持续学习和用户前台推送

## 系统补强动作

- P0 技术指标较多，但分析场景入口不够清晰。 -> 新增发现层、归因层、结构层、承接层、风险层、跟踪层六层方法骨架。 落地：01配置/股票指标智能选择与方法切换规则 + 282股票指标智能选择引擎
- P0 个股高分容易掩盖市场/行业/事件/风险的层级差异。 -> 推荐等级由多层权限共同决定：发现层只给候选，归因和结构给理由，风险层决定上限。 落地：推荐评分/报告结论上限/风险刹车
- P0 盘中数据和盘后正式数据容易混用。 -> 盘中只做观察和预警，盘后完整日线才进入正式历史底座和正式报告。 落地：数据源注册表/历史日线库/盘中观察库
- P1 资金、事件、日历类证据不足。 -> 把龙虎榜、融资融券、解禁、分红、公告、业绩披露作为P1证据补充层，不依赖时先占位标缺口。 落地：证据补充层/公告财报行业事件核验
- P1 报告偏静态，持续跟踪机制不足。 -> 每只输出股票必须形成观察条件、触发条件、风险条件和复盘任务。 落地：关注池/观察条件/复盘账本/企业微信前台

## 方法总原则

- 先场景，后指标。
- 先发现，后解释。
- 先市场和行业，后个股。
- 先数据完整性，后分析结论。
- 盘中只观察，盘后才定论。
- 风险层权限高于评分层。
- 前台报告只呈现结论和条件，后台保留完整分析链。

## 边界

- 只借鉴分析结构和场景逻辑，不复制、不执行中信公式正文。
- 中信本机数据作为授权本机辅助源，不作为黑箱决策源。
- 所有吸收后的规则必须转写为本系统可解释、可复盘、可验证的自有规则。
- 任何新增方法不得绕过数据质量、风险刹车、安全边界和不构成投资建议边界。
