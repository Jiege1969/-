# 分层股票池L8-L5规则与施工方案

版本：v1.0
日期：2026-05-01
状态：已确认，可进入施工

## 一、核心原则

1. L8指数基底池使用沪深300 + 中证500，作为客观监控底盘，不掺杂主观偏好。
2. 用户增强观察池为123只重点关注股票，单独维护，不混入L8，仅在L6/L5排序中加权和标记。
3. L8、L7、L6、L5均只读生成，不反写上游。
4. L5不是推荐池，而是深度研究候选池；必须先生成待核验清单，经人工确认后再触发AI分析。
5. 股票系统当前只在内部沉淀方法，暂不推广到全系统。

## 二、分层结构

| 层级 | 名称 | 内容 | 数量 | 更新方式 |
|---|---|---|---|---|
| L8 | 指数基底池 | 沪深300 + 中证500 | 约800只 | 按中证指数公司正式调仓公告或数据源更新时间执行，默认每季度检查一次 |
| L7 | 可交易过滤池 | 剔除ST、停牌、低成交、数据不足 | 400-600只 | 每日只读生成 |
| L6 | 行业主题观察池 | 行业强度 + 资金活跃 + 用户增强 + 异常强势 | 50-100只，初始80只 | 每日只读生成 |
| L5 | 深度研究池 | 人工确认前的AI分析候选池 | 默认10只，可配置5-15只 | 每日生成待核验清单 |

## 三、用户增强观察池

用户增强观察池以 `重点关注股票池.json` 的123只为全集，以 `19名单股票池.json` 的111只作为行业、细分领域、名单分类等补充源。

输出位置：

`03数据/131用户增强观察池/用户增强观察池_最新.json`

生成脚本：

`02脚本/生成用户增强观察池.py`

规则：

- 内部代码统一为 `sh/sz/bj + 六位数字`。
- 展示代码保留 `.SH/.SZ/.BJ` 后缀。
- 用户增强加权默认为 `+0.2`，只影响排序，不覆盖原始评分。
- 源文件只读，派生产物可覆盖。

## 四、L7过滤规则

L7从L8读取，按规则剔除不可交易或质量不足的股票。

剔除项：

- ST/*ST。
- 当日停牌。
- 连续停牌超过5个交易日。
- 近20日日均成交额低于3000万元，可配置2000-5000万元。
- 近20个交易日中有效交易日少于15天。

仅标记不剔除：

- 涨停_强。
- 跌停_风险。

## 五、L6排序规则

行业强度采用：

`当日涨跌幅 * 40% + 近5日涨跌幅 * 40% + 近20日相对强弱 * 20%`

近20日相对强弱使用差值法：

`行业近20日涨跌幅 - 沪深300近20日涨跌幅`

资金活跃度采用：

`环比放量率 * 60% + 成交额规模分 * 20% + 换手率分位数 * 20%`

L6组成目标比例为：

- 强势行业 + 资金活跃：70%。
- 用户增强观察池：20%。
- 异常强势个股：10%。

该比例为目标配比，不是硬约束；某类不足时，空余名额回流到总排序池。

## 六、L5选取规则

默认数量为10只，可配置5-15只。

执行顺序：

1. 从L6生成候选排序池。
2. 应用最低分门槛：5分制下 `adjusted_score < 3.0` 不得进入L5。
3. 应用冷却期：进入L5后的下一个交易日起，连续3个A股交易日不得再次进入L5。
4. 行业限流：同一申万一级行业不超过 `ceil(N * 30%)`。
5. 用户增强优先席位：最多2只，必须通过L7且不在冷却期。
6. 异常强势破格席位：最多2只，必须通过L7、最低分和数据完整性过滤。
7. 去重、补位、截断到N。
8. 输出待核验清单。

破格只突破研究优先级，不突破安全过滤边界。

## 七、人工闸口

待核验清单输出MD和JSON：

`03数据/135分层日报/待核验清单_YYYYMMDD.md`

人工命令：

- `确认开始`
- `剔除 sh688041`
- `追加 sz000858`
- `取消今日AI分析`

追加股票必须已通过L7；不在L7的股票只能进入人工追加待审，不得直接进入L5。

## 八、AI模型路由

v1.0自动主流程只启用三档模型：

| 用途 | 模型 |
|---|---|
| 默认分析 | `qwen3:14b` |
| 复杂风险复核 | `deepseek-r1:32b` |
| 快速兜底 | `qwen2.5:7b` |

每只股票AI分析结果必须记录：

- `model_used`
- `is_fallback`
- `latency_ms`
- `error_msg`

其他模型分阶段使用：

- 金融专项复核：`mychen76/Fin-R1:Q5`、`martain7r/finance-llama-8b:q4_k_m`。
- 相似案例库：`qwen3-embedding:4b`、`bge-m3`、`sam860/qwen3-reranker`。
- 交叉评审：`qwen3:30b`、`gemma3:27b`、`glm4:latest`。
- 开发维护：`qwen3-coder:30b`。

所有模型必须有明确任务位置、触发条件、输出文件和验收标准；未定义用途的模型不得进入自动流程。

## 九、脚本施工原则

股票分层池相关脚本必须遵守：

`07文档/股票分层池脚本施工原则与代码要求_20260501.md`

关键要求：

- 不写死绝对路径。
- 关键输入强校验。
- 同时输出时间戳文件和 `_最新` 文件。
- 源文件只读，派生产物可覆盖。
- 必须记录安全边界、实际动作和数据健康度。
- 不触发n8n，不发送企业微信，不调用券商接口，不自动交易。

## 十、施工顺序

1. 生成用户增强观察池。
2. 生成L8指数基底池，含离线兜底。
3. 生成L7可交易过滤池。
4. 生成L6行业主题观察池。
5. 生成L5深度研究池和待核验清单。
6. 人工确认链路稳定后，接入L5 AI分析。
7. 本地手动链路稳定至少一周后，再考虑n8n定时触发和企业微信命令响应。

## 十一、安全边界

本方案是股票研究系统内部施工依据，不构成投资建议，不接券商接口，不自动下单，不生成收益承诺。企业微信真实推送必须继续受白名单、数量限制和人工闸口控制。
## 十四、综合样本池封装补充

为避免日常使用复杂化，同时解决用户增强池中指数外重点股无法进入主流程的问题，入口层新增综合样本池封装：

```text
L8A 指数基底池
L8B 扩展战略样本池
L8U 用户增强观察池
        ↓
L8X 综合候选池
        ↓
L7 可交易过滤池
```

### 14.1 分工

- L8A：保持客观基底，沪深300+中证500。
- L8U：保持用户关注、加权和报告标记。
- L8B：负责把指数外重点股、后续行业龙头和新锐企业接入主流程。
- L8X：作为L7统一入口，保留多来源标记。

### 14.2 第一阶段

第一阶段不直接扩展到1200只，不新增大规模主观名单。

`L8B派生版 = 用户增强观察池中不在L8指数基底池内的股票`

### 14.3 L8X字段要求

每只股票至少保留：

```json
{
  "sources": ["index_base", "user_enhance", "strategic"],
  "是否指数基底": true,
  "是否用户增强": true,
  "是否战略样本": false,
  "来源优先级": "user_enhance"
}
```

### 14.4 L7读取规则

L7后续优先读取 `L8X综合候选池_最新.json`，若文件不存在或读取失败，回退到 `L8指数基底池_最新.json`。

### 14.5 n8n边界

n8n未来仅负责编排和提醒，不承载样本合并、评分、过滤等复杂逻辑。
