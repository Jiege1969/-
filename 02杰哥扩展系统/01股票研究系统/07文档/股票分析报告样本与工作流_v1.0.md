# 股票分析报告样本与工作流

> 版本：v1.0  
> 生效日期：2026-05-07  
> 所属系统：02杰哥扩展系统 / 01股票研究系统  
> 资产身份：样本系统工作流方案  
> 定位：把股票分析系统沉淀为其他业务系统可借鉴的样本，不把股票专有逻辑机械复制到其他系统。  

## 一、为什么建立这份样本

股票分析系统是当前最成熟的样本系统。它不能只表现为“能回答股票问题”，还要沉淀出一套可复用的方法：用户用自然语言提问，系统识别对象、调取证据、形成判断、输出业务语言报告、留下复盘材料，并在人工修正中进化。

本文件解决三个问题：

| 问题 | 处理 |
|:---|:---|
| 股票报告该按什么链条生成 | 固化为“对象识别 -> 证据调取 -> 判断生成 -> 前台短答 -> 后台报告 -> 复盘进化”工作流 |
| 其他业务系统能借鉴什么 | 借鉴底层方法，不复制股票行情、交易、价位等专有字段 |
| 用户体验如何兜底 | 用户不必记机器人分工；系统按意图路由，并在回复第一行明确分析对象 |

## 二、底层原则

| 原则 | 股票系统落法 | 可迁移方法 |
|:---|:---|:---|
| 对象先明确 | 单股分析必须识别股票名称和代码；回复首行写“分析对象” | 税收先明确政策/业务事实，视频先明确素材/任务对象 |
| 证据先于判断 | 行情、技术指标、候选池、公司快照、行业景气、财报证据分层接入 | 所有系统先建可信资料和证据层，再生成草案 |
| 结论先给用户 | 企业微信短答先给当前判断、策略、关注条件、风险线 | 前台用业务语言，不把后台指标甩给用户 |
| 不确定要明说 | 数据缺口、行业映射、财报缺口只作为待核验，不强行下结论 | 税收可提示“地方口径待核实”，不是错误 |
| 缺证据不输出横杠 | 行情、技术指标或风险观察线缺失时，明确写“证据待补齐”，不把 `-` 当作承接、转强或风险条件 | 其他系统缺资料时写待补、待核实、待复核，不用空值冒充判断 |
| 可公开只读补证 | 本地快照没有单股行情时，可按需读取已登记的公开行情源，只读补证，不写旧系统、不触发外部动作 | 税收可按需查公开政策库，视频可按需读本地素材元数据，前提是数据源已登记且边界清楚 |
| 安全边界常开 | 只做研究，不交易、不下单、不连券商接口 | 高风险业务必须有本业务的硬闸门 |
| 复盘沉淀进化 | 判断复盘账、人工修正、经验候选账分层存放 | 人工修正进入案例/策略锚点，不自动变正式规则 |

## 三、股票分析报告标准工作流

```text
用户提问
-> 意图识别：单股分析 / 推荐总览 / 持仓诊断 / 状态查询 / 交易意图
-> 对象解析：股票名称、代码、别名；未知则显式待补或追问
-> 证据调取：行情、技术指标、候选池、公司快照、行业景气、财报、风险观察线
-> 判断生成：分层、评分、研究信号、当前判断、风险等级
-> 前台短答：分析对象、当前判断、操作策略、关注条件、转强条件、成交标准、风险线、图文详情
-> 后台报告：图形报告、证据补充、长期成长质量框架、后续跟踪重点
-> 复盘进化：记录问题、识别对象、系统判断、人工评价、结果验证、经验候选
```

## 四、入口与路由规则

| 用户说法 | 系统识别 | 处理入口 |
|:---|:---|:---|
| “分析一下002428” | 单股分析 | 股票分析助手 |
| “请分析一下云南锗业” | 单股分析 | 即使从股票专家入口进入，也转股票分析助手 |
| “今日推荐” | 推荐总览 | 股票分析专家 |
| “现在市场方向怎么看” | 市场总览 | 股票分析专家 |
| “买入/卖出/下单/清仓” | 交易意图 | 直接拦截，不调用交易链路 |

关键规则：用户不需要记住机器人分工。系统按意图路由；若路由失败，属于系统问题，不归咎于用户问法。

## 五、前台短答硬字段

单股分析给企业微信或手机端时，字段顺序固定：

1. 分析对象：股票名称（代码）
2. 当前判断：等级、星级、强度
3. 现价
4. 操作策略
5. 关注条件
6. 转强条件
7. 成交标准
8. 风险线
9. 结论
10. 补充核验
11. 图文详情

### 标准样例

```text
分析对象：云南锗业（sz002428）
云南锗业(sz002428)
当前判断：观察等待 ⭐⭐；强度：0/5
现价：-

操作策略：
- 观察等待，但现价不追
- 低位看承接区能否稳住
- 上攻看转强线能否站上

关注条件：
- 价格回到承接区后不跌破风险线
- 当天收盘价或当前实时价重新站上承接价，视为承接成立

转强条件：
- 当天收盘价或当前实时价高于转强线
- 更稳妥看连续2个交易日收盘价都高于转强线
- 近5日成交活跃度达到平时的1.10倍以上

成交标准：
- 成交活跃就是近5日成交活跃度达到平时的1.10倍以上
- 明显活跃就是近5日成交活跃度达到平时的1.30倍以上

风险线：
- 跌破风险线
- 跌回承接价下方且成交不足，转为谨慎观察

结论：只等两个信号：一是承接区按标准成立；二是站上转强线且成交活跃度达标。
图文详情：http://43.167.210.211/wecom-bot/message?ask=分析云南锗业
```

## 六、后台报告骨架

后台报告可以比前台复杂，但必须服务前台判断，不得用指标堆叠替代结论。

| 模块 | 作用 |
|:---|:---|
| 图形报告 | 手机端快速识别对象、等级、信号 |
| 结论 | 说明当前属于重点关注、观察等待、风险复核等哪一档 |
| 逻辑 | 行业逻辑、公司卡位、主要矛盾 |
| 财务 | 营收、利润、现金流、ROE、估值等支撑情况 |
| 观察条件 | 价格区间、N日M次收盘、成交额或量比标准 |
| 转强条件 | 突破价、连续天数、成交活跃标准 |
| 失败条件 | 风险线、跌破后的修复期限、降级处理 |
| 证据缺口 | 哪些证据未接入，不能据此强行下结论 |
| 跟踪重点 | 下一轮系统要自动核验什么 |

## 七、复盘与进化

每次生成报告后，至少保留以下可追溯材料：

| 材料 | 资产身份 | 处理方式 |
|:---|:---|:---|
| 本次问题和识别股票 | 复盘材料 | 进入助手入口日志 |
| 系统判断、评分、分层 | 账本 | 进入判断复盘账 |
| 标准报告v2 | 可再生报告 + 当前锚点 | 写本次报告和最新报告 |
| 人工评价 | 账本/经验材料 | 后续进入人工决策账或经验候选账 |
| 交易意图拦截 | 安全审计 | 保留拦截记录，不触发交易 |

人工修正只能进入经验候选，不得自动修改正式规则。只有同类修正积累到阈值并经人工确认，才能进入规则层。

## 八、可复用到其他业务系统的方法

| 股票样本方法 | 税收系统映射 | 视频/内容/本职工作映射 |
|:---|:---|:---|
| 股票名称/代码对象解析 | 政策文号、税种、业务事实对象解析 | 素材、文稿、任务对象解析 |
| 行情/财报/行业证据 | 总局政策、地方口径、案例、流程证据 | 素材来源、授权、需求、验收证据 |
| 单股短答 | 待复核业务草案 | 任务建议、脚本草案、分镜草案 |
| 风险线/失败条件 | 不确定事项、需咨询当地机关 | 版权风险、质量风险、交付风险 |
| 判断复盘账 | 人工复核修正账 | 修改记录、验收反馈、经验样本 |

迁移时只复制“方法链”，不复制股票专有词：行情、转强线、成交活跃、交易时段、券商接口等只属于股票系统。

## 九、验收清单

| 验收项 | 标准 |
|:---|:---|
| 单股对象显示 | 回复和报告首屏必须出现“分析对象：名称（代码）” |
| 路由正确 | 股票名称/代码从任何股票入口进入，均按单股分析处理 |
| 专家不抢单股 | 股票专家只处理推荐/总览；单股请求转助手 |
| 交易拦截 | 买卖、下单、仓位、券商类指令必须拦截 |
| 前台可读 | 手机端先结论、再条件，不堆后台指标 |
| 缺证据诚实降级 | 未接入行情、技术指标或风险观察线时，不输出横杠价位，必须说明先补证据再给价位型判断 |
| 后台可追溯 | 生成报告、判断账、日志、证据缺口均可查 |
| 进化不过界 | 人工修正进入候选，不自动改正式规则 |

## 十、当前已落实的样本修正

2026-05-07 针对“分析一下002428未显示云南锗业、专家入口返回旧报告”的问题，已落实：

- `股票简称补充映射.json`：建立对象解析补充配置，当前补充 `002428 / sz002428 / 云南锗业` 映射，避免把个股简称长期硬编码到脚本里。
- `股票助手入口.py`：读取补充映射；单股回复和报告强制显示分析对象。
- `股票企业微信桥接入口.py`：新增单股分析意图识别；专家入口收到单股问题时转股票分析助手。
- `股票前台输出标准_v2.json`：把“分析对象：股票名称（代码）”写入单股查询和单股短答首字段。
- `股票助手入口.py`：单股不在本地行情快照时，按需只读东方财富公开行情，避免可公开补证时直接降级为空值报告。

这次修正不是孤立补丁，而是本工作流中“对象先明确、意图自动路由、前台第一行说明分析对象”的具体落地。
