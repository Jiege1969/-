## 一、施工原则

本项工作是股票分析系统的继续优化，不是新开一个系统。

核心目标：

```text
让每一份股票分析报告不仅能给用户看，还能沉淀为后续复盘、经验提炼和规则优化的学习资料。
```

总原则：

1. 继续以股票分析报告 v2 为主线。
2. 前台报告保持结论驱动，不堆砌技术指标。
3. 后台保留数据、指标、证据和复盘材料。
4. 学习闭环只做结构化账本，不做复杂机器学习。
5. 系统可以生成验证建议和经验候选，但不自动修改规则。
6. 规则微调必须由用户或人工确认后执行。

## 二、免确认施工授权

用户已明确授权：本项搭建过程不需要每一步停下来确认，自动施工直到完成交付。

因此，下列动作默认允许自动执行：

- 新增或修改股票系统内部脚本。
- 新增或修改股票系统内部文档。

- 生成样板报告、复盘账、验证建议、经验候选账。
- 更新接续文件、施工记录、总管上下文。

继续保持关闭，不纳入本次免确认范围：

- 企业微信真实主动发送。

## 六、判断主因规则

判断主因固定为五类：

1. 技术/资金
2. 行业景气
3. 公司品质
4. 事件/催化剂
5. 风险复核

允许辅因，但每条记录必须有一个主因。

初期自动判定规则：

- 风险标记存在或风险等级高：风险复核
- 行业景气为上行且行业强度靠前：行业景气
- 资金放量率明显、评分变化明显：技术/资金
- 公司品质档位为优秀/良好且财报已接入：公司品质
- 有公告/财报/解禁事件：事件/催化剂
- 都不明显：技术/资金

## 七、验证周期规则

不同主因对应不同验证周期：

| 判断主因 | 验证周期 |
|---|---|
| 技术/资金 | T5、T10 |
| 行业景气 | T20、T60 |
| 公司品质 | T60、T120、财报后 |
| 事件/催化剂 | 事件后 |
| 风险复核 | T5、公告后 |

说明：

技术信号是概率，只能短周期验证；公司品质是底层锚，必须中长期或财报后验证。

## 八、自动化边界

自动脚本可以做：

- 写判断复盘账。
- 生成验证建议预览。
- 生成经验候选。
- 生成周/月复盘摘要。
- 输出待人工确认清单。

自动脚本不能做：

- 自动确认验证结果。
- 自动修改评分规则。
- 自动调整权重。
- 自动生成交易结论。
- 自动触发真实推送。
- 自动交易。

## 九、施工顺序

### 阶段1：账本骨架

1. 建立公司品质档案初始模板。
2. 建立判断复盘账初始模板。
3. 建立验证结果账初始模板。
4. 建立经验候选账初始模板。
5. 建立指数样本学习账初始模板。

### 阶段2：报告写入判断复盘账

1. 标准报告 v2 生成时写入判断复盘账。
2. 单股查询生成标准报告 v2 时写入判断复盘账。
3. L5入选时也可写入判断记录。
4. 同一股票 + 同一日期 + 同一判断来源去重。

### 阶段3：验证建议预览

1. 读取判断复盘账。
2. 判断哪些记录到达T5/T20/T60/T120。
3. 计算相对沪深300表现、行业是否延续、分层状态变化。
4. 输出验证建议预览，不直接写正式验证结果。

### 阶段4：经验候选

1. 读取已确认验证结果。
2. 按判断主因、公司品质、行业状态分组统计。
3. 生成候选经验。
4. 状态默认为“待人工确认”。

### 阶段5：规则微调

1. 用户确认经验候选。
2. 人工修改L6/L5权重、冷却期、用户增强加权等规则。
3. 记录规则变更日志。
