# 股票分层池脚本施工原则与代码要求

版本：v1.0
日期：2026-05-01
适用范围：用户增强观察池、L8指数基底池、L7可交易过滤池、L6行业主题观察池、L5深度研究池、待核验清单、AI分析报告、日志与复盘相关脚本。

## 一、路径与目录原则

1. 不写死 `D:\...` 绝对路径。
2. 默认脚本放在 `股票研究系统/02脚本/` 下，通过 `Path(__file__).resolve().parents[1]` 获取股票研究系统根目录。
3. 若脚本未来放入更深子目录，必须改为向上查找 `01配置`、`02脚本`、`03数据` 等锚点目录。
4. 规则文件放 `01配置`，脚本放 `02脚本`，生成结果放 `03数据`，运行日志放 `04日志`，方案文档放 `07文档`。

## 二、输入文件原则

1. 关键输入文件必须强校验，不允许静默返回空对象。
2. `load_json(path, required=True)` 读取关键源文件；缺失时必须抛出明确错误。
3. JSON读取统一使用 `utf-8-sig`，写入统一使用 `utf-8`。
4. 源文件和派生产物必须区分：
   - 源文件：如 `重点关注股票池.json`、`19名单股票池.json`，脚本默认只读，不自动修改。
   - 派生产物：如 `用户增强观察池_最新.json`，可以由脚本覆盖生成。

## 三、输出文件原则

1. 每个生成脚本同时输出时间戳文件和 `_最新` 文件。
2. 示例：
   - `用户增强观察池_20260501_091500.json`
   - `用户增强观察池_最新.json`
3. 输出文件必须包含：
   - 名称
   - 版本
   - 数据日期
   - 生成时间
   - 数据源
   - 生成工具
   - 数据健康度
   - 安全边界
   - 实际动作
4. 不允许只覆盖 `_最新` 而不保留历史版本。

## 四、数据完整性原则

1. 必须记录预期数量、输入数量、输出数量。
2. 必须统计并输出：
   - 无效代码数
   - 重复代码数
   - 待补充字段数量
   - 待补充字段股票清单
3. `是否完整` 不得只看输出非空，至少应满足：
   - 输出数量等于预期数量
   - 无效代码数为0
   - 重复代码数为0
   - 输出数量大于0
4. 对缺失字段必须记录原因，例如：
   - 不在补充源中，且主源未提供完整字段。
   - 在补充源中，但对应字段仍缺失。

## 五、代码字段原则

1. 内部代码统一为 `sh/sz/bj + 六位数字`，如 `sh600519`。
2. 展示代码保留交易所后缀，如 `600519.SH`。
3. 所有脚本必须通过统一函数标准化代码，不得混用 `600519.SH`、`sh600519`、`600519`。
4. 北交所代码暂不作为主流程重点，但标准化函数应保留 `bj` 兼容能力。

## 六、来源与日期原则

1. 单股 `来源` 只记录真实来源，例如：
   - 用户确认
   - 用户补充全行业龙头样本池_20260501
   - 历史重点关注
2. 生成脚本名称不写入单股来源，应写入顶层 `生成工具`。
3. `加入日期` 优先继承源文件已有字段；源文件没有时才使用当前日期或默认版本日期。
4. 不得因为脚本重跑而覆盖历史加入日期。

## 七、标签生成原则

1. 标签来源可以包括：
   - 名单分类
   - 行业
   - 细分领域拆分词
   - 源文件已有标签
2. 标签必须去重。
3. 标签中应过滤非实质性内容：
   - 待补充
   - 历史重点关注
4. 不根据股票名称胡乱猜标签；无法确认的字段标记为 `待补充`。

## 八、安全边界原则

1. 低风险生成脚本默认只能：
   - 读取本模块配置
   - 写入本模块 `03数据`
   - 写入本模块 `04日志`
2. 默认禁止：
   - 自动交易
   - 调用券商接口
   - 触发n8n
   - 企业微信真实发送
   - 写旧系统
   - 写正式库
   - 重启正式服务
3. 输出文件必须显式记录 `安全边界` 和 `实际动作`。
4. 若未来脚本需要触发企业微信、n8n或外部接口，必须单独设置人工闸口和确认记录。

## 九、只读生成原则

1. L8、L7、L6、L5各层只读上游，生成本层产物，不反写上游。
2. 用户增强观察池是派生产物，可以由脚本生成；但不得自动修改源池。
3. 过滤、加权、排序结果只能写入新产物，不得覆盖原始数据。

## 十、可追溯与可复盘原则

1. 任何生成结果必须能追溯：
   - 使用了哪些输入文件
   - 生成时间
   - 生成工具
   - 数据健康度
   - 是否使用降级或兜底
2. 与人工确认有关的脚本必须记录：
   - 清单ID
   - 人工命令
   - 剔除/追加/取消原因
   - 操作时间
3. AI分析脚本必须记录：
   - model_used
   - is_fallback
   - latency_ms
   - error_msg

## 十一、错误处理原则

1. 关键源文件缺失必须失败退出，不生成虚假空结果。
2. 非关键补充数据缺失可以降级，但必须写入 `降级说明`。
3. 失败时不得触发企业微信真实发送、n8n、交易或正式库写入。

## 十二、施工结论

以后编写股票分层池相关脚本时，必须优先遵守本文件。若某个脚本确实需要突破上述原则，必须在脚本文件头、规则文件和运行日志中明确说明原因，并经过人工确认。
