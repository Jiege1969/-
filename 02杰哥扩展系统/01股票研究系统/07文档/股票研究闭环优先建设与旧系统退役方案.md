# 股票研究闭环优先建设与旧系统退役方案

## 一、结论
应当先建立股票研究系统的最小闭环，再考虑删除 D 盘旧系统。

原因很简单：旧系统目前仍有两类价值，一是可复用经验，二是兜底参照。只有当新系统具备“分析、观察、验证、提炼、优化”的独立闭环，并确认企业微信查询、图形报告、技术指标、复盘账本都能独立运行后，旧系统才真正失去运行价值。

## 二、当前空间状态
- D 盘剩余空间：约 241GB。
- 新系统 `D:\杰哥智能化系统`：约 134.55GB。
- 旧股票/智能体系统 `D:\杰哥智能体操作系统`：约 126.93GB。
- 旧基础系统 `D:\01杰哥智能系统`：约 288.73GB。

空间压力已经存在，后续必须进入“先验证、再退役、再清理”的节奏，不能让样本、日志、图形报告和旧系统长期并存无边界增长。

## 三、股票研究最小闭环
### 1. 分析
输入行情、历史K线、技术指标、候选池规则，输出单股分析、星级信号、关键依据和图形报告。

对应能力：
- 行情快照
- 技术指标计算
- 候选池生成
- 企业微信即时问答
- 单股图文报告

### 2. 观察
记录系统在当时的判断，不只记录结论，还记录当时的价格、评分、分层、依据、风险和图形报告文件。

对应账本：
- 系统判断账
- 人工决策账
- 查询历史

### 3. 验证
按 1日、3日、5日、10日等周期回看结果，检查当初判断是否有效。

验证内容：
- 判断后价格变化
- 是否触发风险
- 买入机会信号是否兑现
- 卖出风险信号是否规避损失
- 技术指标是否滞后或误判

### 4. 提炼
把成功和失败都转成经验候选，而不是直接改规则。

提炼内容：
- 哪类指标组合有效
- 哪类指标组合容易误判
- 哪些股票特征需要单独处理
- 哪些风险来自数据源缺失、新闻缺失或财务缺失

### 5. 优化
经验候选经人工确认后，再进入配置、评分权重、提示词或候选池规则。

边界：
- 系统可推荐优化项。
- 系统不得自动改核心规则。
- 系统不得接交易接口。
- 系统不得自动下单。

## 四、n8n 工作流设计
n8n 不负责复杂分析，n8n 只负责调度和状态流转。

建议拆成 5 条未激活工作流，先导入、验证、再决定是否启用：

1. 股票每日分析工作流
   - 触发：盘后或人工触发。
   - 执行：行情快照、技术指标、候选池、L5报告。
   - 输出：日报、候选池、系统判断账。

2. 股票即时问答工作流
   - 触发：企业微信消息。
   - 执行：股票识别、单股分析、图形报告、回复生成。
   - 输出：企业微信图文回复。

3. 股票结果验证工作流
   - 触发：定时或人工触发。
   - 执行：读取历史判断，抓取后续行情，生成验证结果。
   - 输出：结果验证账。

4. 股票经验提炼工作流
   - 触发：每周或样本达到阈值。
   - 执行：读取系统判断账、人工反馈账、结果验证账。
   - 输出：经验提炼候选账。

5. 股票规则优化建议工作流
   - 触发：人工触发。
   - 执行：归纳经验候选，生成规则调整建议。
   - 输出：规则优化建议，不自动修改正式规则。

## 五、旧系统退役前置条件
满足以下条件后，才进入旧系统删除申请：

1. 企业微信问股票，新系统能稳定返回图文报告。
2. 单股图片与文字绑定本次报告文件，不再发生缓存错配。
3. 技术指标、候选池、L5报告可独立生成。
4. 系统判断账、人工反馈账、结果验证账、经验提炼账均可读写。
5. 至少完成一次“分析-观察-验证-提炼”的本地闭环演练。
6. F 盘备份中确认存在旧系统可恢复副本和一键恢复说明。
7. 新系统不再读取旧系统文件作为运行依赖。

特别边界：
- `D:\杰哥智能系统` 是用户明确要求保留的独立系统，不纳入旧系统删除范围。
- D盘根目录下旧 `00/01/02/03` 系统、`D:\杰哥智能体操作系统` 仅作为经验库和退役候选，不到条件不删除。
- 乱码异常目录 `D:\鏉板摜鏅鸿兘鍖栫郴缁焅01鏉板摜鏅鸿兘绯荤粺` 暂时冻结，需单独判定来源后再处理。

## 六、删除策略
旧系统删除属于破坏性操作，必须单独申请确认。

建议顺序：
1. 只读盘点旧系统可复用资产。
2. 生成旧系统依赖断开报告。
3. 校验 F 盘备份和恢复说明。
4. 将旧系统标记为“冻结，不再运行”。
5. 观察新系统独立运行。
6. 用户确认后再删除旧系统。

## 七、执行优先级
当前优先级：
1. 建立股票研究最小闭环。
2. 建立 n8n 未激活工作流草案。
3. 做本地闭环演练。
4. 输出旧系统依赖断开报告。
5. 再进入旧系统删除申请。

这条路线不影响整体【杰哥智能化系统】搭建，反而是整体系统“进化机制”的首个业务样板。
