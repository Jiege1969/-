版本：v2.0  
日期：2026-05-01  
定位：为“股票标准报告 v2 前台模板”倒推后台字段、现有系统来源、缺口和施工优先级。  

## 一、字段分层

字段分为三类：

1. 前台展示字段：用户直接看到。
2. 后台分析字段：用于计算判断，不直接铺在报告里。
3. 追溯字段：用于日志、证据、复盘。

## 四、数据状态标记

报告字段必须标注数据状态：

```text
已接入：系统已自动生成且可追溯。
部分接入：有数据但口径不完整或未完全映射。
待接入：当前无自动数据来源。
人工核验：需要用户或人工材料确认。
暂不接入：当前阶段不做。
```

## 四点一、公共来源可信度字段

股票标准报告 v2 的追溯字段必须接入公共来源判断机制：

```text
D:/杰哥智能化系统/02杰哥扩展系统/00公共组件/01配置/信息来源可信度分层规则.json
D:/杰哥智能化系统/02杰哥扩展系统/00公共组件/02脚本/信息来源智能鉴别器.py
```

每条公告、财报、新闻、研报、行情或人工登记材料，至少记录以下字段：

| 字段 | 股票场景口径 |
|---|---|
| 可信度等级 | S1-S6或待判定 |
| 来源类型 | 监管披露、交易所公告、上市公司公告、行情接口、学术研究、主流媒体、商业门户、本地人工材料等 |
| 来源用途边界 | 正式证据候选、行情校验、事件线索、舆情线索、研究背景或待核验 |
| 是否需要反向追溯 | 媒体、门户、研报摘要和本地摘录默认需要追到公告、财报、监管披露或原始材料 |
| 是否可作正式依据候选 | 只有监管、交易所、法定披露和已核验公告财报可进入正式证据候选 |

东方财富、腾讯、新浪等公开平台不是“不可信”，但在股票系统里默认承担行情校验、线索和辅助信息作用；涉及业绩、重大事项、风险提示和投资结论时，必须反向追溯到公告、财报、交易所或监管披露。

## 五、优先施工清单

### P0

1. 公司经营快照文件或数据源。
2. 行业景气结论字段。
3. 数据状态与证据完整度。
4. 前台报告六段模板样板。
5. 分层排序分和系统评分的口径统一。

### P1

1. 财报日历。
2. 公告事件。
3. 解禁减持。
4. 融资融券/北向资金。
5. 人工复核状态日志。

### P2

1. 宏观定调。
2. 机构一致预期。
3. 券商研报交叉验证。
4. 历史相似案例库。
