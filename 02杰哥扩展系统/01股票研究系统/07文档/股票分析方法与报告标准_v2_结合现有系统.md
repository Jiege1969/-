# 股票分析方法与报告标准 v2（结合现有系统）

版本：v2.0  
日期：2026-05-01  
定位：在现有股票分析系统基础上，统一分析方法、报告呈现、数据来源、评分口径和后续施工方向。  

## 一、总原则

本系统不是单纯生成技术指标报告，而是形成一套固定的研究流程：

```text
样本池 -> 可交易过滤 -> 行业主题观察 -> 深度研究池 -> 后台分析 -> 前台结论报告 -> 企业微信/本地查看 -> 反馈复盘
```

核心原则：

1. 后台深分析，前台给结论。
2. 技术指标服务于判断，不在前台堆砌。
3. 前台报告必须让用户一眼看懂：公司是谁、行业怎样、基本面如何、走势状态、主要风险、后续看什么。
4. 所有结论必须标注证据完整度或待核验状态。
5. 严格区分 `用户关注`、`战略样本`、`分层排序分`、`系统评分`、`星级`。
6. 不输出交易指令，不写买入、卖出、仓位、目标价、止损等指令性表述。

### 通用分析判断机制

2026-05-10 起，所有股票分析判断统一继承：

- `01配置/股票通用分析判断机制_v1.0.json`
- `07文档/股票通用分析判断机制_v1.0.md`
- `01配置/股票指标智能选择与方法切换规则_v1.0.json`

这套机制是本系统的上位分析规则。它要求每一次分析先回答：

1. 本次问题是什么类型：趋势延续、长期研究、行业判断、事件驱动，还是前台短答。
2. 当前客观环境是什么：强势市、震荡市、弱势市、事件驱动或长期研究。
3. 哪些指标在本场景下是主指标，哪些只是辅助指标，哪些需要降权或否决。
4. 证据法阶是什么：宪法层、法律层、规章层、案例层谁先谁后。
5. 结论如何投影到前台：只给结论、观察条件、风险边界和证据完整度。

因此，系统不得因为“某只股票大部分指标满足”就机械把它排到前面；也不得在牛市里让满足条件的股票全部进入重点。市场环境会改变指标主次：牛市收紧重点门槛，熊市强化风险闸门，震荡市重视结构和相对强度，长期研究以基本面和反证风险为主。

指标智能选择引擎负责把这套思想落成动作：每次先根据客观环境选择方法组合，再把指标分成主导、辅助、降权和否决四类，并在后台保存为什么选择、什么时候切换。

术语统一：

| 禁用/慎用表达 | 统一表达 |
|---|---|
| 买入 | 机会研究信号 |
| 卖出 | 风险/退出研究信号 |
| 持有 | 继续观察 |
| 仓位 | 关注优先级 |
| 止损 | 技术破位观察线 |
| 目标价 | 压力位 / 情景参考位 |
| 推荐 | 研究提示 |
| 强烈推荐 | 高优先级研究对象 |

固定声明：

```text
本报告仅提供研究信息参考，不构成任何交易指令。用户需独立判断并承担风险。
```

## 三、后台分析方法

后台分析维度为六类：

| 后台维度 | 当前系统基础 | 后续增强方向 |
|---|---|---|
| 公司画像 | 用户增强池、19名单、股票池模板、单股问答 | 核心业务、细分领域、行业地位、主营构成 |
| 行业景气 | L6行业主题观察池、行业分类 | 申万行业指数1/5/20日强弱，相对沪深300 |
| 基本面 | 当前较弱，部分依赖人工/后续财报数据 | 营收、扣非/归母净利、毛利率、ROE、现金流 |
| 技术走势 | 股票助手、技术指标、图形报告 | 均线、趋势、关键观察线、指标一致性 |
| 资金活跃 | L6资金活跃度、成交额、换手率 | 北向、融资融券、资金持续性 |
| 风险催化 | 300只候选事件核验、人工核验链路 | 财报日历、公告、解禁、减持、行业价格 |

后台可以保留详细指标，但前台只输出结论性判断。例如：

```text
短线放量反弹，但中期均线尚未修复。
量能明显提升，短期关注度上升，但持续性待确认。
行业处于下行震荡，跑输大盘。
利润受周期影响下滑，需核验毛利率修复。
```

### 柏基长期成长框架接入

2026-05-06 起，股票系统新增一层“长期成长质量框架”。它不是看 K 线的技术分析，也不替代现有价格、成交额、财务和风险线，而是用于回答：这家公司是否处在足够大的长期技术浪潮中，是否拥有多主题重叠的战略位置，以及正面逻辑能否经受反证风险攻击。

接入后的后台流程为：

```text
技术成熟度扫描 -> 欧拉图主题重叠 -> 尽调十问质量复核 -> 魔鬼代言人反证 -> 报告降级或保留观察
```

固定口径：

1. 技术成熟度只判断赛道是否存在成本下降、性能提升或规模学习曲线，不直接给交易结论。
2. 欧拉图只识别 AI 与数字化、能源转型、生物革命、未来出行、消费线上化、关键基础设施等主题重叠，不因为概念命中就提高评分。
3. 尽调十问压缩为四个模块：市场潜力、文化与创始力、社会贡献护城河、财务纪律。
4. 魔鬼代言人必须输出反证清单，至少包含技术路线、估值透支、竞争格局、政策/地缘、管理层或财务纪律中的关键风险。
5. 证据不足时，报告只能写“待核验”或“长期成长观察（证据不足）”，不得写强结论。

对应配置：

- `01配置/柏基长期成长分析框架_v1.json`
- `01配置/股票前台输出标准_v2.json` 的 `柏基长期成长框架`
- `01配置/股票报告模板.json` 的 `柏基长期成长框架`

前台报告新增“长期成长质量框架”章节，只输出雷达结论、技术成熟度、欧拉图主题、尽调缺口、反证清单和安全边界。本框架不改变系统评分，不构成买卖建议。

## 四、前台报告标准

前台报告采用 6 段结构：

1. 结论
2. 公司概况
3. 行业与基本面
4. 走势与资金状态
5. 风险与待核验
6. 后续跟踪重点

设计原则：

```text
分析内容涉及技术指标的，应该1-2句言简意赅概括和总结，不宜太细；技术细节是后台分析的事，呈现的是结论。
```

### 1. 结论

输出内容：

- 一句话判断
- 关注等级
- 证据完整度

关注等级只允许以下四类：

```text
高优先级研究对象
常规跟踪对象
暂缓跟踪
风险复核对象
```

### 2. 公司概况

输出内容：

- 公司核心业务
- 申万一级行业
- 细分行业
- 行业地位或主要特征

示例：

```text
天齐锂业是锂资源和锂化工产品生产商，业务与新能源电池产业链高度相关。公司具备较强资源弹性，但经营业绩受锂价周期波动影响明显。
```

### 3. 行业与基本面

输出内容：

- 行业景气状态：上行 / 震荡 / 下行 / 中性
- 核心驱动因子
- 财报关键指标摘要
- 数据缺失标记

初期允许财报部分标记为：

```text
财报数据待接入
财报数据部分接入
财报数据待人工核验
```

### 4. 走势与资金状态

输出内容：

- 技术面结论
- 资金面结论
- 分层状态

不在前台罗列全部 MACD、RSI、KDJ、布林带细节。

### 5. 风险与待核验

输出内容：

- 主要风险
- 数据缺失项
- 需要人工核验的信息

风险表达必须使用研究语言，例如：

```text
若价格有效跌破下方技术观察线，技术形态转弱。
```

不使用：

```text
止损离场
卖出
清仓
```

### 6. 后续跟踪重点

输出内容：

- 后续催化剂
- 关键观察线
- 下次复核时间或触发条件

## 五、评分和标记口径

这是必须固定的系统规则：

| 字段 | 含义 | 是否代表推荐等级 |
|---|---|---|
| 用户关注 | 股票在用户增强观察池中 | 否 |
| 战略样本 | 股票在扩展战略样本池中 | 否 |
| 分层排序分 | L6/L5候选池排序分，通常0-5 | 否，表示筛选优先级 |
| 系统评分 | 单股即时分析评分，0-100 | 是，表示单股机会/风险强弱 |
| 星级 | 由系统评分转换 | 是，但仅用于研究信号强弱 |

企业微信摘要必须写：

```text
用户关注=在你的增强观察池；分层排序分=进入L5候选池的排序分，不等同于单股系统评分。单股系统评分请点股票名称查看。
```

## 六、快报、标准报告、深度复核触发机制

### 快报

用于企业微信主动摘要。只推变化，不天天重复推静态结论。

建议触发条件：

1. 系统评分较前一交易日变化 >= 5分。
2. 分层状态变化，例如 L6 -> L5。
3. 用户增强池股票首次进入 L5。
4. 成交量异常，近5日均量 >= 近20日均量2倍。
5. 涨跌幅异常或涨跌停，仅标记，不强化结论。

去重规则：

```text
同一股票同一触发原因，3个交易日内不重复推送。
```

### 标准报告

触发条件：

1. 用户点击企业微信摘要中的股票名称。
2. 用户在企业微信输入“分析XX”。
3. 用户本地打开股票报告。

标准报告采用 6 段前台结构。

### 深度复核

触发条件：

1. 财报披露。
2. 涨跌停。
3. 成交量极端异常。
4. 公告重大事件。
5. 用户输入“深度复核XX”。

深度复核结果独立存储，不直接混入前台标准报告。

## 十二、融合升级标准接入（2026-05-04）

本次将“原报告骨架 + 新前台结论标准 + 复盘闭环”合并为股票分析报告 v2.1 执行口径。

新增权威执行文档：

```text
07文档/股票分析报告v2融合升级执行标准_20260504.md
```

核心变化：

1. 原报告的公司、行业、财务、资金、风险、后续跟踪结构继续保留，作为后台完整分析层和详情页材料。
2. 企业微信和手机端不照搬完整报告，只输出结论短文。
3. 微信短文固定为“结论、逻辑、财务、观察条件、转强条件、失败条件、风险”。
4. 技术指标继续在后台计算，前台只输出价格、天数、成交额阈值和失败处理。
