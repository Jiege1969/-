# 02杰哥扩展系统

## 定位

本系统承载具体业务能力，是 v3 的业务应用层。

## 第一批模块

1. `01股票研究系统`
2. `02视频制作系统`
3. `03本职工作系统`
4. `04内容处理系统`

## 目录编号说明

本目录存在两类同层编号：

1. 系统级七目录：`01配置`、`02脚本`、`03数据`、`04日志`、`05备份`、`06临时`、`07文档`。
2. 业务模块目录：`01股票研究系统`、`02视频制作系统`、`03本职工作系统`、`04内容处理系统`、`05税收业务系统`、`07知识库系统`。其中可追溯问答框已归集为 `07知识库系统\08可追溯问答框` 子模块，不再作为并列业务系统维护。
3. 公共接入与适配目录：`00公共组件\企业微信接入设置`。该目录只负责企业微信通讯适配、回调路径、密钥引用、安全边界和路由转发，不作为独立业务系统。

这些编号不是全系统唯一编号，只在同一语义域内排序。读取职责时必须看完整目录名和本 README，不得只按数字判断。

`02杰哥扩展系统` 的定位是业务应用层。业务模块内部应尽量继续保持七目录骨架，但业务逻辑不得反向写入 `00总管`、不得绕过 `01智能系统` 的模型和中台边界。

## 通用规则

1. 每个业务模块必须采用七目录骨架。
2. 每个业务模块必须复用 `01杰哥智能系统` 的基础能力。
3. 每个业务模块必须有配置、数据、日志、文档边界。
4. 每个业务模块新增前必须评估资源影响、备份策略和消息出口。
5. 信息来源判断必须优先复用 `00公共组件` 的可信度分层机制，统一规则文件为 `D:/杰哥智能化系统/02杰哥扩展系统/00公共组件/01配置/信息来源可信度分层规则.json`，再按业务系统定义用途边界，不得在单个业务模块里各自发明互相矛盾的来源等级。
6. 可信来源不等于可直接形成业务结论；国家官方、学术权威、主流媒体、大型门户等来源必须按来源等级、原始性、可追溯性和业务用途分层处理。

## 禁止事项

1. 不重复部署 Ollama、Redis、PostgreSQL、n8n。
2. 不私自调用企业微信接口。
3. 不把临时脚本长期留在模块根目录。
4. 不跨模块直接读写其他模块数据。
