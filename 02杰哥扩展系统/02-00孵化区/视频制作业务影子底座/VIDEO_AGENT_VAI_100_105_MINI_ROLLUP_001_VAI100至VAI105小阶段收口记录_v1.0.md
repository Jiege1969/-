## 1. 收口范围

本记录收口 VAI100 至 VAI105：

1. VAI100：VAI094 至 VAI099 小阶段收口记录。
2. VAI101：发布前最终确认缺口清单模板。
3. VAI102：企业微信最终确认待补材料回执样例。
4. VAI103：最终确认缺口关闭条件清单。
5. VAI104：企业微信最终确认缺口已补齐但需人工确认回执样例。
6. VAI105：VAI001 至 VAI102 本线资产索引草案 v7。

## 2. 小阶段结论

VAI100 至 VAI105 已把“最终确认前缺材料”拆成三层：

- 缺什么：由缺口清单列出。
- 怎么补：由缺口关闭条件定义。
- 怎么回复用户：由企业微信回执样例表达。

这一阶段的核心不是推进发布，而是防止“材料看似补齐”被误判为“可以发布”。

## 3. 已形成能力

| 能力 | 影子资产 | 当前边界 |
|---|---|---|
| 最终确认缺口汇总 | 缺口清单模板 | 只记录待补项，不放行 |
| 缺口关闭判断 | 关闭条件清单 | 只判断材料是否补齐，不发布 |
| 待补材料回复 | 企业微信待补材料回执样例 | 只定义话术，不真实发送 |
| 补齐待确认回复 | 企业微信缺口已补齐回执样例 | 只进入人工确认，不自动发布 |
| 资产分层索引 | 本线资产索引 v7 | 只整理本线，不写总管 |

## 4. 遗留问题

1. 需要“提交总管判断缺口卡”承接红线或越权事项。
2. 需要企业微信“提交总管判断”阻断回执样例，避免用户以为系统已自动提交。
3. 需要后续索引继续追到 VAI108。
