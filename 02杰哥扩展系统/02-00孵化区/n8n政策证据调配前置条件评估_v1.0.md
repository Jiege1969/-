# n8n 政策证据调配前置条件评估

> 版本：v1.0  
> 日期：2026-05-07  
> 资产身份：n8n 后置评估影子报告  
> 风险等级：R0/W1  
> 边界：只做评估，不创建 n8n 工作流，不导入配置，不触发自动化。  

## 一、评估结论

```text
当前不具备建立 n8n 政策证据调配工作流的条件。
```

继续采用：

```text
扩展系统内部轻量只读调配优先
总管只登记能力和边界
n8n 后置
```

## 二、前置条件检查

| 条件 | 当前状态 | 结论 |
|:---|:---|:---|
| 至少 3 个业务系统有稳定重复调用 | 有4条样例，但未证明稳定重复 | 未满足 |
| 调用字段稳定 | 已有模板，但未多轮验证 | 未满足 |
| 每条样例通过 3 轮人工复核 | 0轮人工填写 | 未满足 |
| 无证据误写成业务结论案例 | 当前样例未发现，但样本少 | 暂不足 |
| 用户明确要求自动化编排 | 用户倾向轻量，不要求立即 n8n | 未满足 |
| W3 确认和验收 | 未进入 | 未满足 |

## 三、风险判断

| 风险 | 说明 |
|:---|:---|
| 过早自动化 | 低频调用被做成工作流工程，增加维护成本 |
| 边界放大 | n8n 容易连接外发、企业微信或自动调度 |
| 证据误用 | 待核验证据可能被自动传递为确认依据 |
| 责任混淆 | 政策库、业务系统、总管之间职责可能被工作流混在一起 |

## 四、当前建议

1. 不创建 n8n 工作流。
2. 不导入 n8n 配置。
3. 不接企业微信、外发、自动调度。
4. 继续补只读样例和人工复核。
5. 三轮复核后再重新评估。

## 五、重新评估触发条件

只有同时满足以下情况，才重新讨论 n8n：

- 至少 3 个业务系统连续使用同一类政策证据调用。
- 字段、来源、层级、状态、禁止用途全部稳定。
- 至少 3 轮人工复核通过。
- 用户明确要求自动化编排。
- 按 W3 暂停确认。
