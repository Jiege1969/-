# 影子底座统一验收清单

> 版本：v1.0
> 状态：孵化区影子验收清单，不是正式业务验收规则
> 边界声明：不接 n8n，不接企业微信，不写正式库，不触发真实业务动作。

## 1. 适用范围

适用于孵化区内的税收业务、本职工作业务、视频制作业务及后续新增影子业务线。

## 2. 最小结构验收

| 检查项 | 标准 | 不通过处理 |
|:---|:---|:---|
| 五问校准 | 有需求、输入、输出、风险、验收五项 | 补五问，不进入正式设计 |
| 资料来源清单 | 说明资料来源类型、状态和使用边界 | 标待补，不主动抓取 |
| 数据源清单 | 区分用户提供、公开来源、禁止接入源 | 禁止接入项不得绕行 |
| 需求草案 | 明确第一阶段范围和暂不做事项 | 不完整则只做讨论 |
| 场景拆解 | 至少列出候选场景、输入、输出、风险 | 待用户确认 |
| 工作流草案 | 节点含输入、输出、人工确认点 | 不得转成自动化流程 |

## 3. 边界验收

| 边界 | 必须满足 |
|:---|:---|
| 影子状态 | 文件显式标注影子、草案、待复核或待确认 |
| 无正式能力声明 | 不写“已上线”“可用业务系统”“自动执行” |
| 无真实链路 | 不接 n8n、企业微信、正式库、真实系统 |
| 无外发 | 不发送、发布、申报、报送、上传 |
| 无真实处理 | 不执行交易、申报、审批、渲染、转码、剪辑等动作 |

## 4. R0自检建议

```text
目录存在
-> 预期Markdown文件存在
-> 每个文件含影子/草案状态
-> 每个文件含边界声明
-> 无可执行脚本
-> 无正式能力声明
```

## 5. 不通过时的动作

- 只补缺口，不删除旧文件。
- 不顺手清理历史材料。
- 不把待补项写成已完成。
- 如发现重复影子目录，先记录并只读核实，不直接合并或删除。
