# 税收前台输出字段草案

> 版本：v1.0  
> 日期：2026-05-07  
> 资产身份：涉税业务分析助手前台输出字段影子草案  
> 风险等级：W1  
> 边界：前台输出仅为待复核分析草案，不是正式税务意见，不外发。  

## 一、定位

本草案规定涉税业务分析助手给用户看的前台输出字段。目标是像股票系统先给“分析对象”和“当前判断”一样，税务系统先给用户能读懂的政策顾问式分析结论，同时明确依据、缺口和复核点。

## 二、字段顺序

| 顺序 | 字段 | 说明 |
|---:|:---|:---|
| 1 | 分析对象 | 税种、政策文号、业务事项、地区、期间；未知项写待补 |
| 2 | 分析结论 | draft / evidence_ready / pending_review / human_reviewed 对应的待复核结论 |
| 3 | 政策依据 | 主要依据名称、文号、层级、有效状态 |
| 4 | 业务事实 | 主体、事项、期间、地区、材料状态等事实拆解 |
| 5 | 适用条件 | 已满足、待证明、不适用风险分开写 |
| 6 | 资料缺口 | 需要补充或核验的资料 |
| 7 | 测算前置字段 | 涉及测算时列字段和口径，不给未经复核确定金额 |
| 8 | 风险提示 | 依据冲突、地方口径、时效、资料缺失、不可外发等 |
| 9 | 人工复核问题 | 需要用户或专业人员确认的问题 |
| 10 | 下一步 | 补证据、补资料、人工复核、沉淀样例 |

## 三、标准前台骨架

```text
分析对象：{税种/政策/业务事项/地区/期间}
分析结论：{待复核分析结论 + 状态}

政策依据：
- {政策名称/文号/层级/有效状态}

业务事实：
- {已知事实}
- {待补事实}

适用条件：
- 已满足：{条件}
- 待证明：{条件}
- 不适用风险：{条件}

资料缺口：
- {资料或字段}

风险提示：
- {风险}

人工复核问题：
- {问题}

下一步：
- {建议动作}
```

## 四、禁止输出

| 禁止项 | 原因 |
|:---|:---|
| “一定适用” | 未经人工复核容易变成正式结论 |
| “可以直接享受” | 涉及具体税务处理，不应由影子系统直接确认 |
| “金额确定为...” | 字段、口径和人工复核不足时不可给确定金额 |
| “已确认无风险” | 税务风险不能由系统单方清零 |
| 可外发正式意见格式 | 当前阶段不是正式意见系统 |

## 五、验收标准

| 验收项 | 标准 |
|:---|:---|
| 用户可读 | 先给分析对象和结论，不先堆政策原文 |
| 依据可追溯 | 至少列出主要政策依据、层级和有效状态 |
| 缺口显式 | 缺资料、缺地区、缺期间、缺原文时必须写明 |
| 风险不隐藏 | 地方口径、时效、资料不足不得省略 |
| 不越权 | 不输出正式税务意见、确定金额或可直接执行结论 |
