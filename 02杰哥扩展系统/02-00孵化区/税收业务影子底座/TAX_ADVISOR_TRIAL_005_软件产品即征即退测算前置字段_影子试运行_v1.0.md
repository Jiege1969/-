| 草案状态 | draft |

## 三、测算前置字段

| 分组 | 字段 | 说明 | 缺失时处理 |
|:---|:---|:---|:---|
| 期间地区 | tax_period | 纳税所属期/申报期 | 列入待核实事项 |
| 期间地区 | local_tax_authority | 主管税务机关及地区 | 不判断地方口径 |
| 税率口径 | applicable_vat_rate | 现行适用税率及依据 | 不直接测算 |
| 收入口径 | software_sales_amount_excl_vat | 软件产品不含税销售额 | 可列为待补字段，不假设 |
| 税额口径 | output_vat | 当期软件产品销项税额 | 缺失则不能得出准确退税额 |
| 税额口径 | input_vat_creditable | 可抵扣进项税额 | 缺失则不能得出准确退税额 |
| 税额口径 | vat_payable | 当期软件产品应纳税额 | 缺失则只能给测算公式 |
| 收入拆分 | income_split | 软件、服务、硬件、第三方软件收入拆分 | 缺失则提示拆分风险 |
| 进项分摊 | input_vat_allocation_method | 进项税额分摊方式 | 缺失则提示核算风险 |
| 材料条件 | software_certificate_status | 软件著作权、检测证明、登记材料或当地替代材料 | 缺失则提示条件风险 |
| 特殊情形 | embedded_software_flag | 是否嵌入式软件 | 缺失则提示适用差异 |
| 特殊情形 | commissioned_development_flag | 是否受托开发或转让著作权 | 缺失则提示定性风险 |
| 地方口径 | local_filing_requirement | 当地备案、留存备查或办理要求 | 缺失则提示咨询主管机关 |

## 四、公式口径

可写的公式口径：

```text
软件产品增值税即征即退测算应先确认当期软件产品实际税负。
政策线索中提到“实际税负超过3%的部分”作为候选口径。
在销项税额、可抵扣进项税额、应纳税额、收入拆分、期间和地方口径缺失时，只能列字段和公式思路，不能给具体金额。
```

不得写：

- 预计可退金额。
- 申报表填报数。
- “应退”“可退”“建议申报”的确定话术。
- 任何替代主管税务机关或专业复核的结论。

## 五、当前缺口判断

| 缺口 | 影响 |
|:---|:---|
| 缺所属期和地区 | 无法判断政策期间与地方执行口径 |
| 缺软件产品收入拆分 | 无法确认测算基数 |
| 缺销项、进项、应纳税额 | 无法计算实际税负 |
| 缺进项分摊方法 | 混合收入场景下可能影响应纳税额 |
| 缺软件产品材料 | 条件是否成立仍待证明 |
| 缺主管税务机关要求 | 不能输出办理或申报建议 |

## 六、输出限制

本样例可以输出：

1. 测算前置字段清单。
2. 公式口径和测算思路。
3. 缺口和风险提示。
4. 面向用户的补资料问题。

本样例不得输出：

- 具体退税金额。
- 申报建议。
- 正式税务意见。
- 对主管税务机关口径的替代判断。

## 七、人工复核问题

1. 本次测算对应哪个纳税所属期和申报期？
2. 软件产品不含税销售额是否已经独立核算？
3. 当期软件产品销项税额、可抵扣进项税额、应纳税额分别是多少？
4. 软件、硬件、服务、维护、培训收入是否已经拆分？
5. 进项税额分摊方法是否有内部资料或主管机关认可依据？
6. 是否存在嵌入式软件、受托开发、代理销售等特殊情形？
7. 当地主管税务机关对测算口径和材料是否有补充要求？
