# 税收适用条件字段化样例：软件产品即征即退

> 版本：v1.0  
> 日期：2026-05-07  
> 资产身份：税收适用条件字段化影子样例  
> 风险等级：W1  
> 边界：只做影子字段拆解，不写正式税收库，不生成正式税务结论，不申报、不退税、不外发、不接 n8n。  

## 一、用途

本样例把“软件产品增值税即征即退”相关政策证据拆成可复核字段，供涉税业务分析契约中的 `extracted_conditions`、`evidence_gap`、`review_questions` 调用。

它不是适用性结论，只回答：判断这类业务前，系统应先核对哪些条件、证据和缺口。

## 三、字段化条件

| 条件组 | 字段 | 候选要求 | 当前状态 | 复核说明 |
|:---|:---|:---|:---|:---|
| 主体条件 | taxpayer_type | 增值税一般纳税人 | pending_review | 需用户提供纳税人身份或主管税务机关认定材料 |
| 产品条件 | product_type | 软件产品 | pending_review | 需确认是否属于政策所称软件产品 |
| 研发生产条件 | development_mode | 自行开发生产，或进口软件本地化改造后对外销售 | pending_review | 需区分自研、外购、代理、嵌入式软件、本地化改造 |
| 销售条件 | transaction_type | 销售软件产品 | pending_review | 需收入合同、发票、收入科目或业务说明 |
| 税负条件 | actual_vat_burden | 实际税负超过3%的部分可作为候选测算对象 | pending_review | 需销项、进项、税率、收入拆分等测算字段 |
| 材料条件 | supporting_documents | 软件著作权、检测证明、登记材料或当地要求材料待核实 | missing | 地方口径和材料清单未补齐 |
| 期间条件 | applicable_period | 所属期与政策有效期间需匹配 | pending_review | 需确认业务发生期间、申报期、政策时效 |
| 地区条件 | local_practice | 地方执行口径待补 | missing | 不得用经验口径替代官方或主管税务机关要求 |

## 四、排除或风险字段

| 风险 | 说明 | 处理 |
|:---|:---|:---|
| 非一般纳税人 | 主体身份不满足时可能无法适用 | 列入不适用风险，待复核 |
| 非软件产品收入 | 硬件、服务、维护、培训等收入混同可能影响判断 | 要求收入拆分 |
| 外购转售 | 不是自行开发生产时需谨慎 | 标为待核实 |
| 嵌入式软件 | 需要拆分软件与硬件价值 | 标为高风险待复核 |
| 地方材料差异 | 各地资料要求可能不同 | 标为地方口径待补 |
| 有效状态未复核 | 仅登记元数据不能等于当前有效确认 | 回到官方政策法规库复核 |

## 五、输出映射

| 契约字段 | 可写内容 |
|:---|:---|
| extracted_conditions | 主体、产品、开发生产、销售、税负、材料、期间、地区条件 |
| evidence_gap | 纳税人身份、收入拆分、软件材料、地方口径、有效状态、测算字段 |
| applicability_analysis | 只能写“候选匹配/待证明/风险项”，不得写确定适用 |
| calculation_prerequisites | 只列字段和公式口径，不给未经复核金额 |
| review_questions | 面向用户和专业人员的复核问题 |
| confidence | draft 或 pending_review |

## 六、人工复核问题

1. 企业是否为增值税一般纳税人？
2. 收入是否来自自行开发生产的软件产品？
3. 软件产品收入、硬件收入、服务收入、维护培训收入是否已拆分？
4. 是否具备软件著作权、检测证明、登记材料或当地要求材料？
5. 所属期、申报期和政策有效期间是否匹配？
6. 当地主管税务机关对材料、流程、口径是否有补充要求？
7. 是否涉及嵌入式软件、进口软件本地化改造或代理销售等复杂情形？

## 七、禁止事项

- 不输出“可以享受即征即退”。
- 不输出“应退金额为某数”。
- 不替代申报、退税、开票、审批或主管税务机关口径。
- 不把本字段化样例写入正式规则库。
