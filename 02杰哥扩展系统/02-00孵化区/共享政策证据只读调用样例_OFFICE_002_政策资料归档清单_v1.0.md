# 共享政策证据只读调用样例 OFFICE 002：政策资料归档清单

> 版本：v1.0  
> 日期：2026-05-07  
> 资产身份：本职工作系统只读政策证据调用影子样例  
> 风险等级：W1  
> 边界：只读样例，不替代审批，不外发，不写正式库，不接 n8n，不触发真实办公流程。  

## 一、调用意图

本职工作系统在整理涉税相关资料时，可以只读调用税收政策知识库，把政策依据转成“待归档资料清单”和“待复核字段”。本样例只验证归档结构，不生成正式制度解释、审批意见或税务结论。

## 二、调用输入

| 字段 | 内容 |
|:---|:---|
| requesting_system | 本职工作业务 |
| query_intent | 政策资料归档清单/依据留痕 |
| topic_keywords | 软件产品、增值税、即征即退、政策归档、资料留痕 |
| expected_evidence_level | 国家级政策依据、官方指引、待核验地方口径 |
| source | `SHARED-POLICY-EVIDENCE-001` 税收政策知识库/政策证据底座 |
| business_context | 待补；需用户提供具体内部归档流程和资料模板 |

## 四、本职工作系统可生成的草案

| 归档项 | 草案内容 | 状态 |
|:---|:---|:---|
| 政策原文留痕 | 记录标题、文号、发文机关、官方链接、本地元数据卡路径 | draft |
| 依据层级记录 | 标注国家级主管机关规范性文件，不提升为法律或行政法规 | draft |
| 有效状态记录 | 写“以官方政策法规库展示为准”，不写 confirmed | pending_review |
| 适用条件摘录 | 摘录软件产品、一般纳税人、自行开发生产等关键词 | pending_review |
| 材料缺口 | 地方资料要求、检测证明、软件著作权/登记材料、收入拆分资料 | pending_review |
| 内部归档位置 | 待用户提供内部目录、编号规则和审批流 | missing |

## 五、禁止输出

- 不写“资料已完成正式归档”。
- 不写“该业务审批通过”。
- 不写“该政策必然适用本单位业务”。
- 不生成可外发正式意见。
- 不接 OA、ERP、财务系统、企业微信或 n8n。

## 六、人工复核问题

1. 本单位内部归档目录和编号规则是什么？
2. 政策原文、政策解读、地方口径和业务资料是否需要分层归档？
3. 当前政策在官方政策法规库展示的有效状态是什么？
4. 是否已有本单位软件产品、收入拆分、著作权或检测证明等资料？
5. 涉税资料归档是否需要法务、财务、税务或办公室复核？

## 七、下一步

- 若要把归档清单接入真实办公流程，必须暂停并按 W2/W3 规则重新确认。
