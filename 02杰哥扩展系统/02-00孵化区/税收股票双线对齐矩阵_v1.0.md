# 税收股票双线对齐矩阵

> 版本：v1.0  
> 日期：2026-05-07  
> 资产身份：跨业务线影子对齐草案  
> 风险等级：W1  
> 边界：不修改股票正式配置，不上线税收系统，不写正式库，不触发 n8n，不外发。  

## 一、为什么需要对齐

股票分析系统正在形成“对象识别 -> 证据调取 -> 判断生成 -> 前台输出 -> 后台报告 -> 复盘进化”的成熟链条。税收业务系统仍处于影子孵化阶段，如果两条线各自推进，容易出现两个问题：

| 风险 | 表现 | 本矩阵处理 |
|:---|:---|:---|
| 各干各的 | 股票沉淀了报告工作流，税收仍只停留在政策卡和样例卡 | 把可迁移方法抽象为税收影子报告工作流 |
| 机械套壳 | 把股票行情、转强线、交易拦截等专有字段复制到税收 | 明确只迁移方法链，不迁移股票专有字段 |

## 二、共同方法链

| 通用环节 | 股票系统现有落法 | 税收影子系统对应落法 | 当前状态 |
|:---|:---|:---|:---|
| 对象先明确 | 识别股票名称、代码、别名，前台首行显示分析对象 | 识别政策文号、税种、业务事项、企业事实口径 | 税收已补涉税业务分析工作流草案 |
| 证据先于判断 | 行情、技术指标、候选池、财报、政策事件、市场风格 | 法律、行政法规、政策文件、地方口径、企业资料、人工复核 | 税收已有政策卡和来源清单 |
| 依据分层 | 结构化证据优先，缺口显式展示 | 宪法/法律/行政法规/部门规章/地方口径/企业资料分层 | 税收已接依据层级规则 |
| 前台业务语言 | 先给结论、策略、条件、风险线 | 先给政策顾问式分析结论、适用条件、缺口、需人工确认事项 | 待补税收前台字段草案 |
| 缺证据诚实降级 | 缺行情或风险观察线时写证据待补齐 | 地方口径、企业数据或原文缺失时写待补/待核实 | 已在税收需求草案中体现 |
| 人工复核 | 修正进入经验候选，不自动改正式规则 | 复核意见进入税收人工修正样本或进化候选 | 已有空白复核样本和回执 |
| 复盘进化 | 判断复盘账、人工决策账、经验候选账 | 政策适用样例、复核修正、口径差异样本 | 待形成税收复盘字段 |

## 三、不能从股票迁移的内容

| 股票专有内容 | 不迁移原因 | 税收替代口径 |
|:---|:---|:---|
| 行情实时刷新 | 税收不是市场行情业务 | 政策有效性、发布日期、适用期间、废止状态 |
| 转强线、承接价、风险线 | 这是交易研究语言 | 适用条件、风险事项、地方待核实、材料缺口 |
| 成交活跃、量比、N日收盘 | 属于股票技术指标 | 申报期间、所属期、政策生效日、备案/资料要求 |
| 券商接口、下单拦截 | 税收业务不存在交易接口 | 税收系统目标不是申报、退税、开票；定位是政策顾问和涉税业务分析专家助手 |
| 单股代码语义 | 税收对象不是证券代码 | 政策文号、税种、事项、企业事实、地区口径 |

## 五、对齐结论

应该对齐，但对齐方式是“共享方法链、保留业务专有边界”。

税收线应吸收股票线已经跑通的对象识别、证据分层、结论前置、缺口显式、人工复核、复盘进化六类能力；落点是“依据国家政策分析具体涉税业务”的专家助手，不吸收行情、交易、价位、券商接口等股票专用逻辑。

本轮只落影子草案，不改股票系统正式配置，不把税收系统推进到正式上线。
