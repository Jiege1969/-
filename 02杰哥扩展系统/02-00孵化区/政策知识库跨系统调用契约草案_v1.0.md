# 政策知识库跨系统调用契约草案

> 版本：v1.0  
> 日期：2026-05-07  
> 资产身份：跨扩展系统共享证据调用契约草案  
> 风险等级：W1  
> 边界：设计草案，不是生产接口；不接 n8n，不接企业微信，不写正式库，不触发真实业务动作。  

## 一、定位

税收业务系统中的政策知识库不应只服务税务业务分析。它更准确的身份是：

```text
政策证据底座
```

它可以被其他业务系统只读查询，用来获取政策依据、有效状态、依据层级、主题标签、适用条件摘录和待核验项。但它不能直接替其他系统生成业务结论。

## 二、推荐架构

当前阶段推荐采用更轻的内部调配方式：

```text
扩展系统内部政策证据调配
-> 税收政策知识库提供只读证据
-> 其他扩展系统按需查询少量政策证据
-> 各系统在自己的业务契约里解释
-> 总管只登记这个共享能力和边界
```

不建议第一阶段直接上 n8n。n8n适合后续稳定后的自动化编排，但现在政策知识库仍在影子/候选层，其他系统能读取和实际需要读取的政策证据并不多；用 n8n 会把一个轻量只读能力提前做成工作流工程，增加维护和 W3 风险。

```text
总管系统
-> 记录共享证据源注册表
-> 判断哪个系统可以查什么
-> 提醒边界和风险

扩展系统内部
-> 通过只读查询契约调用政策证据底座
-> 各业务系统拿到证据后，在本业务分析契约内生成待复核草案

政策证据底座
-> 提供政策标题、文号、来源、有效状态、依据层级、适用条件、待核验项
-> 不输出正式业务结论
```

结论：总管负责“登记和调配”，扩展系统负责“只读调用和业务内分析”，政策知识库负责“证据供给”。

更精确地说：第一阶段总管只负责登记和提醒，不参与每次调用；扩展系统内部完成轻量只读调配。

## 三、调用原则

| 原则 | 要求 |
|:---|:---|
| 只读调用 | 其他系统只能查询，不得写入、覆盖、删除政策库内容 |
| 证据不等于结论 | 政策库返回的是依据和状态，不返回“该业务一定适用” |
| 业务内解释 | 股票、本职工作、视频、税务等系统必须用自己的分析契约解释证据 |
| 层级保真 | 调用结果必须保留法律、行政法规、规范性文件、地方口径等层级 |
| 状态保真 | 有效、废止、失效、待核验等状态不得被调用方省略 |
| 来源可追溯 | 必须保留官方链接、抓取时间、登记路径或来源卡 |
| 待核验不升级 | 待核验资料不能被调用方写成确认依据 |

## 四、调用输入

| 字段 | 说明 |
|:---|:---|
| requesting_system | 请求系统，如股票研究系统、税务业务分析助手、本职工作业务 |
| query_intent | 查询意图，如政策依据、政策事件、行业监管、制度依据、适用条件 |
| business_context | 业务上下文，必须脱敏或不含敏感正文 |
| topic_keywords | 主题关键词 |
| expected_evidence_level | 希望查询的依据层级 |
| region | 地区口径，未知则待补 |
| time_scope | 生效期、发布日期、所属期等 |

## 五、调用输出

| 字段 | 说明 |
|:---|:---|
| evidence_id | 政策或资料编号 |
| title | 政策标题 |
| document_number | 文号 |
| issuing_authority | 发文机关 |
| evidence_level | 依据层级 |
| validity_status | 有效状态 |
| source_url | 官方来源链接 |
| source_path | 本地登记路径 |
| extracted_conditions | 适用条件摘录 |
| topic_tags | 主题标签 |
| risk_flags | 时效缺失、来源异常、地方口径待核等 |
| allowed_use | 可作当前依据、仅解释材料、仅线索、待人工复核 |
| forbidden_use | 不得直接生成结论、不得外发、不得写正式规则 |

## 六、各系统使用方式

| 调用方 | 可使用内容 | 不可使用内容 |
|:---|:---|:---|
| 税务业务分析助手 | 政策依据、适用条件、资料缺口、待复核报告 | 直接生成正式税务意见 |
| 股票研究系统 | 政策事件、行业监管、宏观政策、产业政策证据 | 把税务适用结论套进股票评分 |
| 本职工作业务 | 制度依据、流程依据、合规提示、资料清单 | 替代审批或盖章流程 |
| 视频制作业务 | 平台规则、版权政策、素材授权政策线索 | 自动发布、自动判定版权安全 |
| 总管系统 | 证据源登记、调用边界、风险提醒 | 直接替业务系统生成专业结论 |

## 七、风险分级

| 动作 | 风险 |
|:---|:---|
| 读取共享证据注册表 | R0 |
| 生成跨系统调用设计草案 | W1 |
| 生成只读查询样例 | W1 |
| 扩展系统内部轻量只读调配 | W1 |
| 写正式共享查询配置 | W3 |
| 修改政策库抓取脚本 | W3 |
| 允许其他系统写入政策库 | W3，默认禁止 |
| 建立 n8n 自动化工作流 | W3，后置，必须暂停确认 |
| 接企业微信/外发通道 | W3，必须暂停确认 |

## 八、落地路线

1. 先建立共享证据源注册草案。
2. 再建立跨系统只读调用契约。
3. 在扩展系统内部建立轻量只读调配清单，不上 n8n。
4. 每个业务系统只接收证据，不接收结论。
5. 先用影子样例演练：税务查政策、股票查政策事件、本职工作查制度依据。
6. 等调用频率、字段、边界和验收都稳定后，才讨论 n8n 或正式查询配置。

## 九、硬边界

- 不允许跨系统互相写库。
- 不允许税务政策库直接输出其他业务结论。
- 不允许调用方省略依据层级和有效状态。
- 不允许待核验资料被升级为确认依据。
- 不允许未确认前接入 n8n、企业微信、自动调度或外发。
