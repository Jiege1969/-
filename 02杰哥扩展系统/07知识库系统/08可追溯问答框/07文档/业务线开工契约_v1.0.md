# 知识库可追溯问答框业务线开工契约

> 版本：v1.0  
> 生成时间：2026-05-07 00:08:00 +08:00  
> 所属轮次：轮次003  
> 来源依据：股票系统母本模板 v1.0、知识库系统 README、知识库可追溯问答框 README、日常任务放行规则

---

## 一、业务线名称

知识库可追溯问答框。

---

## 二、入口定义

当前阶段只允许本地只读入口：

- 输入：人工提供的问题样例、已有知识库资料索引、证据片段、已授权文档路径。
- 输出：回答草案、引用来源、无证据降级话术、人工复核清单、验收结论。
- 不接正式企业微信问答。
- 不触发 n8n 正式工作流。
- 不写正式知识库、向量库或业务库。

---

## 三、数据源

| 类型 | 当前策略 | 要求 |
|:---|:---|:---|
| 已授权本地资料 | 可作为只读输入 | 必须保留来源路径、时间、适用范围 |
| 知识库索引/样例 | 可只读引用 | 不覆盖索引，不删除资料 |
| 外部资料 | 本轮不新增 | 未经授权不得放入交付框 |
| 税收政策资料 | 本轮仅作为后续依赖目标 | 不输出正式税务判断 |

---

## 四、处理逻辑

最小闭环为：

```text
问题样例
-> 只读检索/证据片段选择
-> 回答草案
-> 引用来源标注
-> 无证据或弱证据降级
-> 人工复核清单
-> 验收报告
```

处理原则：

1. 有来源才形成事实性回答。
2. 无来源时必须降级为“未检索到足够依据”，不能编造。
3. 高风险领域只输出辅助分析和证据，不替代人工判断。
4. 每个交付包必须能回看问题、证据、草案、复核和验收结果。

| 交付包最新锚点 | `03数据\交付包_最新.md` | 当前状态 |

---

## 六、验收标准

一次最小闭环成功必须同时满足：

1. 问题、证据、草案、降级话术、复核清单、验收结论六项齐全。
2. 每条事实性回答至少能追溯到一个来源。
3. 无证据问题必须明确降级，不能输出确定结论。
4. 高风险问题必须标记“需人工复核”。
5. 交付包不得触发 n8n、不得发送企业微信、不得写正式库、不得覆盖索引、不得删除资料。

---

## 七、失败处理

| 失败类型 | 处理方式 |
|:---|:---|
| 找不到证据 | 输出无证据降级话术，记录待补证问题 |
| 引用来源不完整 | 本轮验收失败，返回补齐来源 |
| 草案与证据不一致 | 本轮验收失败，标记为人工复核 |
| 高风险问题未标注复核 | 本轮验收失败 |
| 试图写正式库或触发外部链路 | 立即闭口，记录红色事件 |

## 九、通用能力覆盖

| 母本通用能力 | 本业务线落地方式 |
|:---|:---|
| 只读预检 | 开始前检查问题样例、来源路径、引用字段是否存在 |
| 人工闸口 | 高风险、弱证据、正式接入前必须人工复核 |
| 最新锚点 | 只保存当前交付包索引，不把草案当正式结论 |
| 失败闭口 | 无证据、引用不全、外部链路触发意图均闭口 |
| 接续包 | 每轮交付包记录问题、证据、草案、验收状态 |
| 安全硬闸门 | 不写正式库、不对外发送、不绕过总管准入 |
| 数据源注册 | 每个来源记录路径、时间、适用范围 |
| 复盘闭环 | 记录回答质量、降级原因、人工复核结果 |
| 验收双通道 | 本轮为搭建轮次，但验收采用 R0 静态验收 |

## 十一、下一轮最小施工任务

轮次004之前，本业务线只允许准备最小样例闭环：

1. 建立 3 个问题样例：有证据、弱证据、无证据。
2. 建立 3 份证据片段清单。
3. 生成 3 份回答草案。
4. 生成 1 份人工复核清单。
5. 生成 1 份 R0 静态验收报告。

全部动作必须保持本地、只读、草稿化；不得进入正式外部链路。
