# 税收官方政策生态证据化行动方案

## 一、定位

本方案把国家税务总局等官方网站从“资料下载来源”升级为“政策证据生态来源”。系统后续不再只保存 PDF、网页或附件，而是把每份资料登记为可引用、可追溯、可复核、可关联的证据节点。

当前施工对象是涉税业务分析专家助手的政策证据底座，不是税务结论库，也不是办税执行系统。历史目录名“正式依据库”仅表示当前适用依据候选层/政策证据层，不代表生产正式库，不代表正式业务结论库，不直接生成适用结论。

核心原则：

```text
资料不是文件，资料是证据节点。
系统不是下载器，系统是证据关系管理器。
```

税收系统的目标不是替代专业税务判断，而是形成“答案草案 + 官方依据 + 场景解释 + 关系风险 + 人工复核”的闭环。

## 二、四类资料分层

| 资料层 | 官网材料 | 系统角色 | 使用边界 |
|---|---|---|---|
| 正式依据 | 法律、行政法规、国务院文件、规章、税务规范性文件、财税文件 | 结论硬边界 | 只有来源官方、时效明确、元数据完整且当前有效，才可支撑当前适用结论 |
| 解释材料 | 文字解读、图解、视频解读、政策宣讲、税费政策我来讲 | 理解辅助线 | 只能帮助解释政策意图和适用口径，不得替代正式依据 |
| 答疑材料 | 政策问答、税问我答、办税便利贴、12366公开问答 | 场景教科书 | 只能作为场景样本，必须反向关联正式依据或标记依据待补 |
| 关联材料 | 相关政策链接、附件、申报表、废止修改说明、地方口径、公报 | 政策全貌图 | 用于提示废止、修改、替代、附件和地方差异，不单独形成结论 |

## 三、证据卡机制

每份资料入库时都要形成证据卡。最小字段包括：

- 证据ID、资料类别、标题、文号、发文机关。
- 发布日期、施行日期、文件时效。
- 来源名称、来源链接、最终链接。
- 适用税种、关键词、摘要。
- 下载时间、原文哈希、本地原文路径、本地解析文本路径、本地元数据路径。
- 依据层级、适用主体、适用事项、适用期间、关键条件、排除条件、所需资料、待人工复核项。
- 是否可作当前适用依据、阻断原因、关联证据ID列表。

这套字段的意义是：以后回答问题时，不只说“根据某政策”，而是能确认“这条政策从哪里来、现在是否有效、本地保存在哪里、它和哪些解读/问答/附件有关”。

证据卡不得继承被引用文件的身份字段。解释材料、案例、问答或政策正文中引用了其他政策的文号时，该文号只能进入“引用关系/关联证据/待复核线索”，不得自动写入当前资料的文号字段；否则会把案例或解读误升格为正式依据。

## 四、政策关系图谱

第一版关系类型不做复杂知识图谱，只做够用的政策关系边：

| 关系 | 含义 |
|---|---|
| 解释 | 解读材料解释某正式依据 |
| 答疑 | 答疑材料对应某正式依据或某类场景 |
| 关联 | 同主题或官网相关链接 |
| 修改 | 新文件修改旧文件 |
| 废止 | 新文件废止旧文件或旧文件失效 |
| 替代 | 新文件替代旧文件 |
| 引用 | 文件引用另一份文件 |
| 附件 | 正文与附件、申报表、表单之间的关系 |
| 地方补充 | 地方税务局对国家政策的执行口径或补充说明 |
| 同主题 | 同一税种、同一业务场景、同一优惠事项 |

## 五、分层回答模式

### 微信端

微信端只输出短答案草案：

```text
结论：
依据：
适用条件：
风险：
详情入口：
人工复核：
```

微信端不输出冗长政策原文，不冒充最终税务结论，不把答疑样本扩大成通用规则。

### 本地详情页

本地详情页输出完整依据链：

- 正式依据清单。
- 官方解读和答疑样本。
- 相关政策、附件、废止修改关系。
- 文件时效和地方差异。
- 待补事实和待复核项。

### 无依据场景

本地和官网都没有找到可用官方依据时，必须明确说：

```text
未找到可用官方依据，当前不能形成可复核答案草案。
```

不得编造政策、文号、链接、文件时效或适用条件。

## 六、落地行动

### A. 已完成：规则固化

- 固化资料四层：正式依据、解释材料、答疑材料、关联材料。
- 固化证据卡字段。
- 固化政策关系类型。
- 固化分层回答规则。
- 固化安全边界：不触发 n8n、不发送企业微信、不写向量库、不调用模型推理、不生成正式税务结论。

### B. 下一步：正式依据索引转证据卡

读取 `03数据\13智能政策下载管道\正式依据库\正式依据索引_最新.json`，为已经下载入库的正式依据生成证据卡预览。

本阶段只生成预览，不写向量库，不接企业微信，不触发 n8n。

### C. 后续：关联链接抽取

从已下载官方页面中抽取：

- 附件链接。
- 相关政策链接。
- 政策解读链接。
- 问答或案例链接。
- 废止、修改、替代关系。

抽到的关系先进入证据关系预览区，缺少时效或来源字段的资料进入异常待核验区。

### D. 后续：税收问答草案本地依据包装

问答草案先走本地正式依据库：

```text
问题 -> 本地正式依据检索 -> 解释/答疑辅助 -> 依据链生成 -> 答案草案 -> 人工复核
```

本地不足时，才受控调用国家税务总局政策法规库查询下载管道。

### E. 后续：RAG 和企业微信灰度

只有在证据卡、关系边、答案草案和人工复核机制都通过后，才允许进入小样本 RAG 和企业微信税收入口灰度。

该阶段必须另行停下报告，不能由当前方案自动放行。

## 七、复用到其他系统

这套方法不是税收专用，而是扩展系统复制骨架的一部分。

| 通用层 | 税收系统 | 股票系统 | 文稿系统 |
|---|---|---|---|
| 正式依据 | 政策、法规、规范性文件 | 财报、公告、审计报告 | 用户确认事实、原始资料 |
| 解释材料 | 官方解读、政策宣讲 | 行业报告、研报、财报解读 | 风格指南、修改意图 |
| 答疑材料 | 税问我答、办税问答 | 董秘互动、投资者交流纪要 | 历史反馈、常见问题 |
| 关联材料 | 附件、废止修改、地方口径 | 同业对比、产业链、风险事件 | 版本关系、旧模板、弃用表达 |

最终目标是让所有业务系统都从“文件堆积”走向“证据节点 + 关系图谱 + 回答闭环”。

## 八、当前边界

本方案只固化机制和下一步行动，不代表税收问答正式上线。

当前仍禁止：

- 生成正式税务结论。
- 自动向企业微信发送税收答案。
- 触发 n8n 正式工作流。
- 写 ChromaDB、Qdrant 或其他向量库。
- 调用模型推理形成税务判断。
- 修改股票系统或影响股票日常使用。
