# 税收问题驱动官方取证与答案草案系统计划

## 定位

本系统不定位为“自动税务结论系统”，而定位为“问题驱动的官方依据检索、资料留痕、证据台账、答案草案和人工复核系统”。

用户输入一个具体税收业务问题后，系统负责把问题拆成场景、税种、关键词、官方检索任务、资料下载计划、证据台账和答案草案。最终结论必须经过人工复核后，才能进入可复用案例库。

## 为什么重新纳入

原税收系统暂停的根因，是自动化容易越过正式税务判断边界：来源有效性、地方口径、具体事实差异、政策时效和专业复核都不能省略。

现在改造后的路线不再让系统直接拍板，而是让系统完成证据工作流：

```text
问题输入 -> 场景识别 -> 官方检索计划 -> 资料下载清单 -> 下载闸口 -> 证据台账 -> 答案草案 -> 人工复核 -> 可复用案例库
```

这样可以恢复纳入整体搭建，但必须保持受控边界。

## 分阶段路线

### 第一阶段：离线规划层

目标：不联网、不下载、不外发，只生成问题任务包和答案草案模板。

应形成：
- 业务问题输入模板。
- 问题场景识别规则。
- 税种识别和关键词拆解规则。
- 官方来源优先级规则。
- 检索任务包模板。
- 证据台账模板。
- 答案草案模板。
- 人工复核单模板。

边界：
- 不访问真实网站。
- 不下载资料。
- 不写正式政策库。
- 不生成正式税务结论。

### 第二阶段：官方白名单只读检索层

目标：只访问官方白名单入口，生成候选来源清单。

应形成：
- 国家税务总局、政策法规库、财政部、地方税务局来源白名单。
- 只读检索计划。
- 候选网页和附件清单。
- 非官方来源拦截记录。
- 检索日志。

边界：
- 不绕过验证码、登录、反爬或访问限制。
- 不高频请求。
- 不向外部问答窗口提交真实问题。

### 第三阶段：受控下载和路径登记层

目标：下载前必须有清单、选择模板和下载闸口；下载后记录路径。

已具备基础：
- 人工入口资料下载器。
- 网址填写模板。
- 待下载清单。
- 下载选择模板。
- 下载申请单。
- 下载闸口。

后续补齐：
- 按问题ID归档下载资料。
- 记录来源网址、标题、下载时间、保存路径、文件摘要和哈希。
- 将“正式依据候选”和“参考资料”分开。

边界：
- 下载只进预演或问题证据目录。
- 不自动写正式政策库。
- 不自动标记正式依据。

### 第四阶段：证据台账和答案草案层

目标：系统根据证据生成可复核答案草案。

答案草案必须包含：
- 业务问题原文。
- 场景假设。
- 初步结论草案。
- 适用条件。
- 官方依据清单。
- 本地文件路径。
- 地方口径和时效风险。
- 需要人工补充事实。
- 待人工复核项。

边界：
- 草案不得命名为正式结论。
- 草案不得对外发送。
- 草案不得替代专业税务判断。

### 第五阶段：人工复核和案例库层

目标：人工复核通过后，形成可复用案例。

应形成：
- 复核记录。
- 复核人、时间、结论。
- 适用范围。
- 不适用范围。
- 引用证据路径。
- 后续失效复核日期。

边界：
- 未复核案例不得进入正式案例库。
- 政策失效、地方口径变化后必须重新复核。

## 示例场景

用户问题：

```text
一般纳税人销售使用过的固定资产，增值税能否简易计税？能不能开专票？
```

系统应拆解：
- 税种：增值税。
- 业务场景：销售使用过的固定资产。
- 主体：一般纳税人。
- 关键问题：简易计税、征收率、发票类型、是否可开专票。
- 检索关键词：销售使用过的固定资产、简易计税、3%减按2%、专用发票、增值税。
- 官方来源：国家税务总局政策法规库、国家税务总局官网、12366官方问答、地方税务局口径。

系统应输出：
- 检索任务清单。
- 候选政策文件清单。
- 候选问答案例清单。
- 下载选择模板。
- 证据台账。
- 答案草案。
- 人工复核单。

## 当前纳入状态

从2026-04-30起，税收业务系统恢复纳入整体搭建计划，但仅恢复为“问题驱动官方取证与答案草案系统”的低风险建设路线。

当前允许：
- 本地计划。
- 本地模板。
- 本地任务包。
- 本地证据台账。
- 本地答案草案模板。
- 官方白名单和闸口设计。

当前仍禁止：
- 自动正式税务结论。
- 自动真实抓取。
- 自动下载进入正式库。
- 自动向税务局问答窗口提问。
- 自动触发n8n。
- 自动企业微信发送。
- 自动写正式知识库或向量库。

## 当前施工优先级

当前仅推进税收业务系统本线：政策证据底座、官方来源登记、有效性核验、适用条件字段化、异常待核验管理和涉税业务分析契约影子样例。不得把其他业务线的评分、推荐或入口口径带入税务系统。
