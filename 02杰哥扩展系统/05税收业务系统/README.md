# 税收业务系统说明

## 定位

税收业务系统面向税收政策、资料整理、口径查询和人工复核辅助。当前按规划和影子验证推进，正式答复必须保留人工复核闸口。

当前施工定位是“涉税业务分析专家助手的政策证据底座”，不是税务结论库，也不是办税执行系统。它负责提供可信政策资料、依据层级、有效状态、适用条件字段和待核验项；后续涉税业务分析助手再基于这些证据生成待复核分析草案。

目录中历史沿用的“正式依据库”仅表示政策资料进入了较高可信度的依据候选层。对外统一解释为“当前适用依据候选库 / 政策证据层 / 正式依据候选层”，不代表生产正式库，不代表正式业务结论库，不直接生成适用结论。

## 目录职责

- `01配置`：税收问答、证据来源、禁区和输出口径配置。
- `02脚本`：政策资料处理、证据关系预览、答复草案生成与验收脚本。
- `03数据`：政策资料索引、草案问题包、人工复核清单和只读证据。
- `04日志`：运行、验收和异常记录。
- `07文档`：用户说明、业务口径、交付报告和复盘材料。

## 安全边界

系统可以生成草案、证据链和问题清单，但不能替代专业判断作出最终税务结论。涉及申报、处罚、争议处理、重大税务安排时，必须人工确认。

系统不登录电子税务局，不接财税软件，不申报、不退税、不开票，不外发正式税务意见，不自动把抓取结果写成正式业务规则。企业微信正式入口属于受控建设项，只允许发送待复核摘要、门禁状态、资料缺口和人工复核提示；真实发送必须另行通过入口门禁和凭据校验。

## 维护要求

新增脚本需写明用途、输入、输出、依赖、触发方式、安全边界、验收方式和回滚方式。新增政策资料需保留来源、时间和适用范围。

政策查询下载管道采用运行快照分流：每次运行均保留时间戳报告；成功运行才刷新稳定 `报告_最新` 和 `报告_最近成功`；官方查询失败只写入 `报告_最近失败`，不得覆盖稳定最新报告。网络超时、接口异常等失败记录只能作为待复核运行线索，不得解释为政策不存在、政策失效或可直接降级结论。
