# 税收企业微信人工复核填写规范与状态机规则

- 生成时间：2026-05-08 12:12:37
- 资产身份：dry-run规则草案，不是真实状态回写，不是正式入口放行，不是税务结论。
- 回执模板数量：5
- 既有回写预演数量：5
- 必填人工复核字段数量：10

## 必填人工复核字段

- 人工复核人：填写内部复核责任人姓名或工号；不得填写客户身份证、手机号、银行卡等敏感信息。
- 人工复核时间：使用 YYYY-MM-DD HH:MM:SS；必须晚于阅读包生成时间。
- 政策依据层级与有效状态复核：按法律、行政法规、部门规章、税务规范性文件、财税文件、政策解读、地方口径、案例、人工经验分层，并标注全文有效、已修改、废止、失效、尚未生效或待核验。
- 业务事实充分性复核：说明业务事实是否足以进入涉税业务分析契约；必须保留 missing 字段。
- 资料缺口复核：逐项核对资料缺口，保留未补齐项和补充资料建议。
- 风险点复核：标注政策时效、依据层级、地方口径、事实缺失和企业微信误读风险。
- 是否需要补充资料：只能填写 yes、no 或 unknown；unknown 视同需要补充资料。
- 是否进入当前适用依据候选层：只能填写 evidence_ready、pending_review 或 blocked；不得写成税务结论确认。
- 是否允许进入后续待复核分析草案：只能填写 allow_draft_preview、need_more_info 或 block；allow 也只代表可进入待复核草案，不代表正式结论。
- 人工复核意见：写明依据、事实、缺口、风险和下一步处理建议；禁止写正式税务意见或确定金额。

## 状态机规则

- blank_pending_human_fill -> pending_human_review：人工填写区任一必填字段为空白、待人工填写或格式不合规。；动作=no_op_shadow_preview。
- pending_human_review -> pending_review：10 个必填字段均已填写，但存在待核验、需要补充资料或证据未达 evidence_ready。；动作=shadow_status_preview_only。
- pending_human_review -> evidence_ready：依据层级和有效状态为 evidence_ready，业务事实可进入草案，且允许进入后续待复核分析草案。；动作=shadow_status_preview_only。
- pending_human_review -> blocked：政策依据被阻断、业务事实被阻断、风险被阻断或人工复核意见明确不允许进入草案。；动作=shadow_status_preview_only。

## 回写护栏

- 本规则只描述状态流，不执行状态变更。
- 任何状态预演均不得写入草案源文件或正式业务库。
- human_reviewed 只能表示人工已复核流程记录完成，不代表税务结论确认。
- evidence_ready 只能表示证据可供后续待复核草案引用，不代表业务一定适用。
- 空白、不合规、含禁止短语或含敏感信息的回执一律阻断。

## 禁止短语

- confirmed_conclusion
- 正式税务结论
- 正式税务意见
- 一定适用
- 可以享受
- 金额确定
- 自动申报
- 自动退税
- 自动开票
