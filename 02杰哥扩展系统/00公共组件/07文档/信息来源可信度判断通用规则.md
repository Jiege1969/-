# 信息来源可信度判断通用规则

- 生成日期：2026-05-07
- 归属：02扩展系统 / 00公共组件
- 适用范围：股票研究、税收业务、文稿处理、知识库、本职工作、企业微信助手等扩展系统
- 文件性质：通用来源治理规则，不属于任何单一业务系统

## 一、定位

这是全扩展系统的底层信息来源判断机制，不是税务系统专用规则。

税务系统只是例子。股票、文稿、知识库、本职工作等系统都需要先判断“信息从哪里来、可信度如何、能用于什么”，再判断“在本业务场景里能不能形成结论”。

## 二、统一逻辑

```text
URL或资料来源
-> 来源身份识别
-> 可信度分层
-> 原始性和可追溯性判断
-> 业务系统用途边界
-> 人工复核重点
-> 是否进入证据链
```

可信不等于可直接下结论。网易、新浪等大型门户不是“完全不可信”，但通常只能作为线索、传播材料、转载入口或舆情材料；如果要支撑正式结论，必须反向追溯到官方、公告、论文、财报、监管披露等原始权威来源。

## 三、可信度分层

| 等级 | 来源类型 | 典型例子 | 默认用途 |
| --- | --- | --- | --- |
| S1 | 国家官方与法定发布来源 | 政府官网、监管机构、交易所、法定披露平台 | 正式依据候选 |
| S2 | 国家级部门、事业单位与权威公共机构 | 国家级研究机构、公共服务平台 | 事实、统计、背景 |
| S3 | 学术权威与专业数据库 | 高校、期刊、论文库 | 学术证据、理论背景 |
| S4 | 中央级主流媒体与权威新闻机构 | 新华社、人民网、央视网 | 新闻事实、政策传播、舆情线索 |
| S5 | 大型商业门户与高公信力公共平台 | 网易、新浪、腾讯、搜狐、东方财富 | 线索、转载入口、公共信息提示 |
| S6 | 普通第三方、自媒体、论坛和未知来源 | 个人号、论坛、来源不明网页 | 检索线索或阻断 |

## 四、不同系统的差异

同一来源在不同系统里用途不同：

| 系统 | 更高权重来源 | 关键边界 |
| --- | --- | --- |
| 税收业务系统 | 税务、财政、政府、法律法规正式来源 | 媒体和学术不能替代政策原文 |
| 股票研究系统 | 交易所、证监会、上市公司公告、财报、法定披露 | 媒体和门户不能替代公告和财报 |
| 文稿系统 | 用户资料、权威公开来源、授权素材 | 要区分事实、观点、引用和版权 |
| 知识库系统 | 可追溯原始来源和高质量结构化资料 | 不能把来源等级等同于答案正确 |
| 企业微信助手 | 已复核内容和允许发送材料 | 不得把未复核内容真实发送 |

## 五、机器和人工分工

机器负责：

- 域名、根域、子域和最终链接识别。
- 来源等级初判。
- 标题、发布机关、时间、链接、哈希、路径等元数据登记。
- 判断是否需要反向追溯。
- 给出人工复核重点。

人工负责：

- 业务适用判断。
- 时效、修订、废止、附件、授权和版权判断。
- 是否可形成正式意见、申报建议、投资建议、合同意见或对外发送内容。

## 六、禁止误用

- 不得把 S5 大型门户直接当成正式依据。
- 不得把 S3 学术观点当成官方执行口径。
- 不得把 S4 新闻报道当成政策原文或财报公告。
- 不得把 S1 来源自动等同于“结论正确”，仍需核验适用边界。
- 不得让业务系统各自发明一套互相矛盾的来源等级。

## 七、公共组件

公共配置：

```text
00公共组件\01配置\信息来源可信度分层规则.json
```

公共脚本：

```text
00公共组件\02脚本\信息来源智能鉴别器.py
```

各业务系统应引用公共规则，再定义自己的业务用途边界，不应把通用来源判断机制写死在单一业务模块里。
